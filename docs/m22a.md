# M22a — Qualified structural reassembly and continuous composability

## What changed — and what did not

The approved [composability contract](composability_contract.md) makes reuse
an explicit, prospective architectural requirement. The
[acceptance charter](m22a_charter.md) was committed at
`a58bab5d5ddf4da9cbcb16b983a08562f09de81d` before implementation.

This milestone addresses a **structural-revision workflow gap**, not a missing
field law: fresh models containing many of these arrangements could already
be authored. Previously the M20b parameter-revision API deliberately could
not add/remove sources or introduce gravity. That contract is unchanged.

A single new production module,
`conductor_sim.structural_scenarios`, provides:
- `NamedSource(source_id, label, source)`.
- `SourceReplacement(old_id, new_named_source)`.
- `reassemble_scenario(parent, ..., add_sources=(), remove_sources=(),
  replace_sources=(), gravity=...)`.
- Immutable `ScenarioReassembly`, containing the original parent, the
  resulting ordinary `.scenario`, and computed structural lineage.

There are **no changes to existing production modules**: fields, force laws,
global/symmetry qualifications, numerical defaults, integrator, old scenario
revisions, validators, comparison rules and renderers remain as before M22a.
This is not a universal graph compiler, a new solver or a multi-domain merger.

## A complete public authoring example

```python
from pathlib import Path
from conductor_sim import (
    FixedPointField, PointCharge, PrescribedField, TestChargeMotionSpec,
    UniformGravity,
)
from conductor_sim.scenarios import PrescribedScenario, sample_scenario_viewer
from conductor_sim.structural_scenarios import NamedSource, reassemble_scenario
from conductor_sim.viewer import render_html
import json

original = PrescribedScenario(
    "one-held-charge",
    TestChargeMotionSpec(
        PrescribedField((FixedPointField(1e-9, (-.2, 0., 0.)),)),
        PointCharge(1e-9, (0., .1, 0.)), 1e-6, (.1, .2, 0.),
        .1, .005, plane_normal=(0., 0., 1.), length_scale_m=.5,
    ),
    (("point:A", "Held point A"),),
    "Teacher hypothetical: a charged-particle launch near one held charge.",
)
assembly = reassemble_scenario(
    original,
    scenario_id="two-held-charges-and-gravity",
    note="Add a second held source and uniform gravity.",
    add_sources=(NamedSource(
        "point:B", "Held point B", FixedPointField(-1e-9, (.2, 0., 0.))
    ),),
    gravity=UniformGravity((0., -1., 0.)),
)
# The whole final arrangement has passed the existing model constructors.
# A numerical run is still needed; model admissibility is not a solved result.
view = sample_scenario_viewer(assembly.scenario, extent_m=.6)
folder = Path("output")
folder.mkdir(exist_ok=True)
(folder/"reassembled.html").write_text(
    render_html(view, title="Two held charges and gravity"), encoding="utf-8"
)
(folder/"reassembled-lineage.json").write_text(
    json.dumps(assembly.as_dict(), indent=2), encoding="utf-8"
)
```

The existing source object and ID are retained. The old model is not changed.
The fixed sources do not react to the particle. No plate/cavity/induction
physics, guide, new motion plane, launch condition or numerical tolerance is
inferred from the requested assembly.

For an explicit replacement, use a **new** source identity:

```python
from conductor_sim import UniformSphereField
from conductor_sim.structural_scenarios import SourceReplacement

replacement = reassemble_scenario(
    assembly,
    scenario_id="replace-point-with-volume-source",
    note="Retire point A and introduce a prescribed volume-charge sphere.",
    replace_sources=(SourceReplacement(
        "point:A", NamedSource("sphere:new", "New volume source",
                              UniformSphereField(1e-9, .05, (-.2, 0., 0.)))
    ),),
)
```

A fixed volume-charge sphere is not a conducting sphere. Existing properties
of a retained component should instead be revised using the unchanged
`revise_scenario(assembly.scenario, ...)` API.

## Atomic qualification and identity

All additions/removals/replacements are assembled before the final
`TestChargeMotionSpec` constructor is called. Adding both members of a mirror
pair can therefore qualify jointly; no invalid half-edited intermediate is
solved. Existing physical axes, plane, guards, nonrelativistic speed limits,
time sampling and numerical controls remain intact.

Unchanged source order and objects are retained. Replacements occupy the
retired source's inventory slot; additions append in authored order.
Duplicate labels/IDs, conflicting or unknown targets, subclass/custom sources,
conductors in prescribed inventories and reused replacement IDs are rejected.
New structural source IDs reserve `test-particle`, `medium`, and `gravity`.
A legacy source named `gravity` is not silently reinterpreted by this new API;
legacy APIs remain unchanged.

Gravity semantics are explicit: omit the keyword to preserve membership;
pass `UniformGravity(...)` to add it when absent; pass `None` to remove it.
Changing an existing gravity component's parameters belongs to M20b/M21e,
not this structural operation. No-op requests are rejected.

`ScenarioReassembly.as_dict()` is detached JSON with the actual parent and
child inventories, exact model revision IDs, actual structural edits and,
when another assembly is supplied as parent, retained structural ancestry.
New descendants are teacher hypotheticals, never automatically source-given.
A digest identifies an authored record, not a trusted import or proof of a
numerical trajectory.

The legacy `.scenario` intentionally remains a freshly authored ordinary
model, not a v1 parameter record misused to describe component insertion.
**Retain the assembly record for structural provenance.** Passing a naked
`.scenario` starts retained structural history there; this is not a global
identity database. Retired IDs are protected within the supplied ancestry.
Subsequent ordinary parameter revisions reference the child model's digest,
which is also present in the structural record. Retained structural ancestry
is bounded to 16 steps.

## Separation of composition and observations

A successful reassembly is not a completed trajectory or a promise that
every observation can be supplied. The normal source-guard termination still
occurs. Each resulting model can use the existing standalone viewer.

M20a still refuses parameter-only paired comparisons when source membership,
gravity membership, exact clocks or physical slices differ. M22a does not
invent interpolation or silently accept a structural comparison. The
structural child can undergo normal parameter revisions and be compared
when the existing comparison contract permits it.

Physical model, numerical investigation, teacher hypothesis and presentation
are distinct. The new record does not move a source because its drawing is
inconvenient or convert an unsupported conductor into prescribed charge.

## Preselected continuous acceptance

The nine positive cards were frozen before implementation. They are curated
JEE-relevant **teacher hypotheticals**, not replicas of nine official papers,
and not a statistical claim about exam coverage.

| Card | New arrangement through the shared API | Independent evidence |
|---|---|---|
| P1 | Add second held point charge | Direct signed Coulomb sum, energy |
| P2 | Add uniform E and gravity atomically | Exact constant-acceleration motion |
| P3 | Add second coaxial ring | Independent axial E/V formulas |
| U1 | Three signed noncollinear planar point sources | Direct Coulomb sum plus separate velocity-Verlet reference in tests |
| U2 | Finite rod + point source + gravity | Independent 1600-panel rod quadrature, Coulomb and gravity |
| U3 | Three coaxial rings + axial E + gravity | Independent ring/field/gravity force and energy |
| R1 | Replace a point source with a volume sphere under a new ID | Interior/exterior sphere reference and replacement ledger |
| R2 | Remove point source and gravity, retain rod | Remaining field and ancestry |
| A1 | Add an off-slice mirror pair together | Existing M21c whole-inventory qualification and signed Coulomb reference |

Seven negative/boundary report cards cover incompatible axial force,
broken reflection, conductor/type rejection, stolen identity, initial source
guard, structurally incompatible comparison, and failure atomicity.
Additional unit cases cover source-count limits, custom subclasses, all
reserved identities, duplicate labels/edits, no-ops, ancestry, unchanged
legacy hashes, property-revision interoperability and admitted-but-censored
runs. Correct refusals are not counted as successful simulations.

The grading JSON separately records authoring, qualification, completion,
independent reference checks, observation-data eligibility and the existing
five teaching-evaluation dimensions. Browser usability is **not inferred**
from this data-only report. Four actual Chromium checks cover U1, U2, U3 and
A1, source identities and actual drawings, genuine off-slice omission,
force/energy labels, saved-time playback and 390px mobile layout. The existing
ring viewer draws meridian intersections, not a fictitious off-axis field.

A single focused CI workflow runs this suite whenever relevant source,
authoring or contract code changes. Existing complete Python and pinned real
FEMM jobs remain regression gates. FEMM is not a solver or independent
numerical reference for these prescribed-source motion cases.

```powershell
git pull --ff-only
python -m pip install -e ".[test]"
python examples/structural_scenarios.py --grade --output output/m22a-grade.json

Start-Process .\output\m22a-rod-point-gravity.html
python -m pytest tests/test_m22a_structural_scenarios.py -q
```

Other render IDs are P1, P2, P3, U1, U3, R1, R2 and A1. Each export has
standalone HTML and adjacent structural/numerical/physics-reference JSON.
Source-change notes are derived from the actual ledger, not authored claims.
Browser screenshots and assertions, grading, JUnit and exact commit/tree
bindings are retained as CI artifacts.

## Remaining limits

The API covers the existing prescribed-source test-charge family only.
Conductor-equilibrium restructuring, arbitrary boundary conditions, new
mechanical constraints, neutral particles, unrestricted 3D, off-axis
ring/disc physics, source response and new analyses remain separate work.
The inherited motion plane is not automatically replaced; some physically
valid arrangements require explicitly authoring a different qualified
analysis. Structural pairing in M20a is still out of scope.

No historical audit, signed/frozen artifact or acceptance denominator has
been revised. The permanent contract is prospective and the legacy
teaching-accompaniment rubric is preserved. The important result is reusable
structural authoring over existing physics—not an increase in independent
problem-specific solvers.
