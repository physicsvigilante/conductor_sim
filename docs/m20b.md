# M20b - Reusable physical scenario revisions

## Educational objective and boundary

Author a supported fixed-source model once, then explore teacher-created
variations without rebuilding its sources, integrator or visualization.
M20b adds `conductor_sim.scenarios`; the existing electrostatic laws, adaptive
RK4 controller, M19e viewer and M20a comparison are unchanged.

This is a Python authoring interface, not a natural-language parser, scenario
database, new scene graph, conductor-boundary-condition editor or general
structural-model compiler. It supports the existing seven prescribed-source
families. Source membership, kinds, IDs and displayed labels remain fixed.

## Authoring

```python
from conductor_sim.scenarios import (
    PrescribedScenario, revise_scenario, sample_scenario_viewer,
)

baseline = PrescribedScenario(
    "rings-original", spec,
    (("ring:A", "Ring A"), ("ring:B", "Ring B"),
     ("field:external", "External field")),
    "Teacher-authored axial model; explicit mass and launch state.",
)
variation = revise_scenario(
    baseline, scenario_id="rings-double-A", note="Double Ring A charge.",
    source_changes={"ring:A": {"charge_c": 20e-6}},
)
```

`spec` is an existing, admissible `TestChargeMotionSpec`, whose source order
matches the explicit identity bindings. Revisions address the bound source ID,
not its index or its display label. The caller supplies source lineage; the
engine does not infer it from geometry or PDF text.

Supported patch groups (SI units):

- `source_changes`: existing physical dataclass parameters keyed by stable ID;
  charges, dimensions, centres/endpoints, qualified axes, uniform E and its
  potential reference. All seven existing prescribed-source types are covered.
- `particle_changes`: `charge_c`, `position_m` (genuine initial position).
- `motion_changes`: `mass_kg`, `initial_velocity_m_s` (genuine launch velocity).
- `medium_changes`: `permittivity_f_m` (positive homogeneous permittivity).

Duration, sample spacing, numerical tolerances, length scales, guards, step
budgets and the selected analysis-plane normal are deliberately not physical
patches. Source identities `test-particle` and `medium` are reserved to avoid
collisions in the change ledger. Unknown IDs/properties and no-op revisions
fail explicitly; source addition/removal and type replacement are unsupported.

## Immutability, provenance and validation

`PrescribedScenario` retains an immutable spec and copies identity bindings to
tuples. `revise_scenario` returns a new object; it never mutates its parent.
All patches are assembled before the existing `TestChargeMotionSpec`
constructor rechecks the complete physical system. This allows coupled valid
changes, but does not project away invalid forces or silently repair geometry.
An admissible baseline does not authorize an off-axis ring launch, transverse
external field, invalid mass, or a newly overlapping source guard.

Every derived scenario is labelled `teacher-hypothetical`, even when its
parent is declared `source-given`. The latter is explicitly an author assertion,
not proof that the original problem has been parsed or reproduced. The note
is narrative; the immutable change ledger is computed from actual normalized
before/after model properties. A note cannot dictate the computed differences.

Each exact authored record has a SHA-256 `revision_id` and children retain the
`parent_revision_id`. This is lightweight, content-addressed lineage, not a
persistent registry, cryptographic authorship guarantee, software version or
numerical certification. `as_dict()` returns a detached JSON-native audit
record including all numerical settings; it is not a trusted import parser.

The declared action is conservative: source/medium changes require field
reassembly and reintegration; particle-only changes require reintegration.
Even a pure potential-reference change is independently reintegrated. There
is no unvalidated result reuse or inferred trajectory rescaling.

## Solving and comparing

A successful revision is an **admissible model, not a completed simulation**.
`sample_scenario_viewer(scenario, ...)` independently runs the existing M19a
integrator, then the existing M19e physical observation/energy checks. It has
no cached-result argument. A source-guard outcome remains explicitly censored.

Feed two resulting bundles to the unchanged M20a comparison with a common
authored extent, sample grid and presentation settings. M20a independently
computes the physical differences and requires complete duration histories,
identical world slices/scales and exact saved time grids. It does not resample,
interpolate a path, or run physics in the browser. A valid revision need not
be comparable: moving the first ring can change the slice origin; changing a
full-spatial launch or field can change its default slice. Such mismatches are
refused rather than hidden. They can still be examined as individual runs.

```powershell
python examples/revise_prescribed_scenarios.py --case double-ring-a-charge --output output/m20b-double-A.html
Start-Process .\output\m20b-double-A.html
```

Other cases: `ring-b-shift`, `double-mass`, `reverse-field`, `launch-speed`,
`gauge-shift`. Each writes a standalone comparison HTML and a sibling JSON
record of the parent/revision models, lineage and computed changes. The
examples preserve Ring A/B IDs and a horizontal common world x axis.

## Evaluation and evidence

Interpretation fidelity: all six examples are explicitly teacher hypotheticals,
not the original workbook's unsupported free motion under a transverse field.
Physical correctness: tests exercise independent constant-acceleration
references, charge reversal, launch conditions, potential-gauge invariance and
permittivity scaling, alongside the unchanged solver/viewer checks.
Simulation coverage: the existing seven fixed-source families and supported
axis/plane regimes only; no new conductor response or off-axis ring formula.
Educational usefulness: one model produces multiple meaningful independently
solved comparisons with a generated change ledger and retained source identity.
Textbook-answer completeness: not claimed or required by this milestone.

`tests/test_m20b_scenarios.py` also covers identity ordering, immutable parents,
input/audit copy isolation, chained revisions, malformed/no-op patches,
revalidation after geometry changes, invalid transverse launches, initial
source guards, censored runs, and admissible-but-incomparable views.

The existing paired-viewer GitHub workflow is extended rather than duplicated.
It retains all M20a checks and runs the six M20b exports through the same real
Chromium checker, including saved-time synchronization, source pixels, mobile
width, console errors and absence of external requests. Ordinary Python and
real FEMM regression jobs remain unchanged. Actual test counts and acceptance
status belong to the PR/check records, not assumptions in this document.
