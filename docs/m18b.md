# M18b — Held-source motion in the shared offline viewer

## Correctness review before expansion

The baseline is accepted M18a `9d1f39903d4569482511d54988e357ec69c48367`,
source tree `ecaf015e5fe8f1d44ef332531ed1ef181734f047`. Reconstructing its
retained GitHub source archive produced that identical tree locally.

Three input/output defects were reproduced with ten failing regression cases:

- Both scalar and vector motion duplicated the last output time for ordinary
  decimal durations such as `duration_s=.07, sample_interval_s=.01`.
  Floating-point division rounded the count just above seven. Shared bounded
  output-time generation now records the requested endpoint exactly once;
  it also checks excessive/overflowing sample counts before allocation.
- Internally consistent saved planar data could include a speed above the
  declared classical limit. All saved speeds now must remain below 0.1c.
- Nonpositive or boolean saved conductor-guard metadata was not rejected.
  The shared validator now requires a finite positive surface cutoff.

Short paths can be hidden under display-only source masks. Draw the path above those discs, below real source
markers and arrows, so excluded field pixels do not hide valid trajectory
data. The field mask itself remains unchanged. Browser acceptance uses a longer
actual trajectory where necessary: sub-marker motion is not exaggerated.

Only output scheduling, metadata checks and display layering changed. The RK4 stepping kernel,
force laws, acceptance tolerances and retained FEMM numerical tests are
unchanged. This is not a change of the physics integration method.

## One API, complete source inventory

`sample_motion_2d(spec, backend, result=...)` now accepts an M18a trajectory
with one moving charge and up to 31 externally held sites, within the existing
physically certified planar domain. No new solver, browser ODE, multi-moving
charge model or geometry-specific renderer is introduced.

Each selected actual numerical time is independently solved with the complete
`spec.problem_at(position)` model. A frame must provide exactly the original
moving and held source inventory. The moving force is selected by full source
identity, not the order of a backend's sorted/grouped charges. Its force and
the configuration interaction energy must agree with the saved trajectory.
Unsupported providers fail explicitly and owned solutions close on failure.

Every held site is included in the fixed display slice and extent. Custom
slices that omit a held site are refused; arbitrary tangential plane anchors
still do not determine the zoom. Saved graph rows that cross an authored
conductor or held-charge cutoff are rejected before acquiring field solutions.

## Metadata and display semantics

The existing `conductor_sim.motion_viewer_2d.v1` schema gains the optional
M18a `stationary_charges`, `moving_charge_index` and `charge_guard_m` fields.
Multi-source field records carry `charge_index` and `motion_role`. Validation
checks each full frame inventory, authored indices, signs, exact positions,
role, slice projection and all graph rows. Duplicate/missing identities,
changed held positions and mismatched fields fail before HTML is written.
The writer retains an existing file on validation failure. Older single-source
M17 payloads and scalar M16 playback remain supported without these fields.

Circles identify the moving charge; squares identify held charges. `qN`
labels use zero-based original authored indices, not solver order. Force and
velocity arrows belong only to the moving charge. The original Play/Pause,
Restart, display-speed, time slider, potential, field lines, surface-density,
component plots and energy graphs are reused. All numerical samples are kept
in the plots; only 2–24 saved times receive separately solved field snapshots.
There is no interpolation of electrostatic fields between moving sources.

K is the moving particle's kinetic energy. U is the full configuration's
mechanical interaction energy, including constant held-source terms and the
existing prescribed-potential convention. The plotted K+U is not the energy
of a freely moving isolated many-particle system: supports constrain the held
sites, whose displacement is zero. No force is discarded from the moving
particle merely because another site is held. Componentwise energy drift
remains the integrator's observation, not subtraction of rounded totals.

Sparse display chords crossing a held-charge guard are omitted just like
chords crossing conducting metal. A gap requests finer physical output
sampling; it does not invent a collision or an intermediate solution.
`charge-guard` and `surface-guard` remain approach cutoffs, not impact times,
physical particle radii or rebounds.

## Reproduce in PowerShell

```powershell
git pull --ff-only
python -m pip install -e ".[test]"
python examples/particle_motion_fixed_viewer.py --case plane --output output/m18b-plane.html
Start-Process .\output\m18b-plane.html
```

Other composed cases are `plates`, `sphere`, `cavity`, `nested` and `guard`.
For visible displacement in the nested/sphere cases, add `--duration-s .12`;
`--sample-interval-s` changes the physical output spacing, not the display
speed or integration force law.
The CLI reuses `examples/particle_motion_fixed_charges.py` for authored models
and writes standalone HTML plus matching JSON. Existing M18a numerical-only
commands still write only JSON.

## Acceptance scope

New Python checks cover all six cases; full electrostatic map consistency;
reordered and same-sign sites; actual authored index selection; distant held
sites; translated central starts; invalid metadata and file preservation;
resource closure; explicit capability refusals; held-source chord gaps; exact
HTML/JSON correspondence; and the output-grid and saved-data corrections.
Actual Chromium checks validate all stored frame inventories, source labels,
painted arrow origins and directions, Play/Pause/Restart, keyboard selection,
unchanged physics data, 390-pixel layout and zero network requests/JS errors.

Before merge require Python 3.10/3.12, all retained visualization/Chromium,
M15c and M17c reviews, the new M18b review, and all 97 pinned real-FEMM cases
with zero skips. Those FEMM cases establish earlier numerical-domain
non-regression, not numerical FEMM motion-force accuracy. Local tests excluding
FEMM do not satisfy that gate. Saved-data validation checks consistency, not
cryptographic authenticity or arbitrary edited trajectories against Newton's
laws. General 3D, multiple moving charges, finite electrode edges, changing
voltages, magnetic fields and relativistic motion remain outside scope.
