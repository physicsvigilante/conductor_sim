# M5 — procedural visualization and M4 review corrections

**M5 implementation and acceptance scope.** Merge is gated on ordinary Python,
pinned live FEMM and browser workflows on the exact PR head. See
[the acceptance record](m5-acceptance.md) and PR #6 for execution evidence.

## Review corrections

The M4 review reproduced invalid analytical sampler behavior: NaN coordinates
returned NaN, too-short tuples raised IndexError and extra coordinates were ignored.
All four analytical field/potential APIs now validate exactly three finite values.

The Kelvin-image implementation could overflow for an almost-centred charge,
although the physical field had a regular centred limit. A dimensionless image
term avoids constructing a huge image position or charge. Regression tests
exercise source offsets of 1e-150 through 1e-160 m and check the independent centred
limit, plus E = -grad(V). This is an algebraic rearrangement, not a new approximation.

Conductor names now reject quotes, backslashes, control characters, non-text and
blank names before they can enter FEMM command strings. Spaces and Unicode remain
supported. Generated HTML escapes labels and script-embedded JSON. Old README
statements denying M4's multi-source/multi-conductor support have been replaced.

The earlier M4 live tests mostly asserted summed source charge. A new real FEMM
regression checks **each signed source** in a zero-net dipole, preserving both
nonzero cavity sources rather than allowing a total-charge assertion to hide errors.

## Layers and authoring

`visualization.py` is a solver-independent sampling and geometry layer. A
`SamplingContext` supplies a physical problem, FieldSolution, spatial masks,
optional finite solver domain and optional density callback. `visual_adapters.py`
maps the existing solver interfaces into that contract. `viewer.py` renders the
result without solving any electrostatics. A new backend can supply its own context.

`SliceSpec` defines an orthonormal world-space plane, extent and grid resolution.
The meridian helper centres the plane on the conductors. Explicit planes support
translation/rotation and actual sphere-plane intersection geometry. Non-planar E
terminates field tracing; the potential map remains a valid scalar slice.

`sample_frame` exports SI potential and vector-field grids, masks, contour segments,
traced curves with termination reasons, surface profiles, conductor results and
solver identity. Unexpected solver failures propagate. Invalid-domain and source
samples are null, not fabricated zeros. Physical metal can retain sampled constant
potential; field tracing stops at its faces. Exact geometric segment intersections
prevent large steps tunnelling through very thin metal or source masks.

Contours use piecewise-linear triangulated cells and exclude invalid samples and
segments crossing barriers. They are interpolated approximations. Field traces
use midpoint integration of normalized E, with finite step budgets, zero-field
termination and checks for out-of-plane components. Vertices and arrows are ordered
along E even when seeded backwards from a negative charge. The line count is a
layout choice, **not flux or charge magnitude**.

Surface profiles are great-circle samples of each selected conductor face. The
analytical adapter uses exact density where available; the FEMM adapter uses its
one-sided local-E estimate. They are labelled separately. Profiles are not spherical
charge integrals, especially for non-axisymmetric analytical charge arrangements.

## Sweeps and exported viewer

`sample_sweep` accepts up to 24 `(label, ElectrostaticProblem)` states and any
compatible backend. Each numerical session is closed after sampling, including on
failure. Cleanup failure does not hide the original sampling failure. A supplied
plane is reused across frames. Otherwise the first case selects a fixed plane;
author an explicit plane when parameters change the relevant geometry or axis.

The self-contained HTML embeds only numeric samples and metadata, never a FEMM
session or remote resource. Controls select a stored frame, toggle potential,
equipotentials and lines, choose a surface profile, and inspect nearest-grid-point
values. The colour scale is shared across frames and clipped for display only;
raw JSON values are unchanged. Browser sliders **do not rerun the solver**.

The viewer is a reusable procedural renderer for the currently supported spherical
models, not a general scene graph or 3D CAD frontend. Analytical source-exclusion
discs are display safeguards, not physical source sizes; FEMM discs use actual
numerical core radii. Both are named in the export.

## Tests and usage

```bash
python -m pytest -m "not femm5"
python examples/visualize_conductors.py --output output/conductors.html
# With FEMM5_BINDING configured:
python -m pytest tests/test_visualization_live.py -vv
python examples/visualize_conductors.py --backend femm --resolution 31 --output output/femm.html
```

Optional browser check (Playwright 1.57.0, Chromium):

```bash
python -m pip install playwright==1.57.0
python -m playwright install chromium
python tools/check_viewer.py output/conductors.html --screenshot output/preview.png
```

The check loads the generated markup directly into Chromium, blocks external
requests and exercises state changes, pixel differences, controls, profile selector,
hover readout and mobile horizontal overflow. It is not a comprehensive accessibility,
touch or cross-browser certification. CI stores the exact source archive, analytical
preview, JSON, screenshot and browser results. Live FEMM CI separately exports an
actual numerical preview and its JSON.

Remaining: live interactive parameter recomputation, adaptive/error-controlled
streamline integration, improved FEMM near-surface precision, arbitrary geometry,
full scene graph and production-safe job supervision. No numerical accuracy claims
are increased by adding a viewer.

## Final review corrections

Changing a stored state now clears the hover probe rather than leaving values
from the previous frame visible. A state without density data clears the previous
profile method label. Conductor property provenance is an explicit sampling
metadata field, not guessed from a backend name; custom solvers are not labelled
as analytical references. The cross-section is labelled planar, since an authored
slice need not be meridional. Dedicated browser regressions exercise these cases.
