# M35b — Correct legacy M28a/M28b native sweep export evidence (issue #80)

**Draft candidate; NOT released and NOT independently reviewed.** The [frozen charter](m35b_charter.md) precedes implementation. Released M35a base `808d7ce9245aaeda3f8f58faff7181776d20183a` was independently reviewed and its 17/17 actual main-push workflows passed before this candidate was considered for release.

## Physical question and original failure

The M28a `TrajectorySweepRun` and M28b `EventSweepRun` run genuine physical-source revisions and native integrators. The known [issue #80](https://github.com/physicsvigilante/conductor_sim/issues/80) was in the **meaning of their subsequently exported evidence**: a public `dataclasses.replace` of an already-issued entry could set `status='complete'` while deleting the source model and native result, yet the old wrapper's `as_dict()` still exported that contradictory status. This does not show a force-law, electric-field, FEMM or integrator error.

## What now fails closed

- Every `TrajectorySweepRun`/`EventSweepRun` receives an exact **in-process runner-issued native SHA256 receipt** over its original complete old v1 detached evidence. The native result, true requested source plan, exact parent revision, source annotations, typed numerical event questions/policy and all comparison rows must agree. Re-validate on run construction and **every** `run.as_dict()`, including after untrusted dataclass replacement and nested mutation.
- An event result's native M24a `validate_event_run` is called on the baseline and each real child; exact typed study/physical model/question/policy and actual event outcome/termination are required. A genuine `complete` native event study must reach the duration end; terminal, source-guard and unresolved observations remain **censored**, not claimed complete. A previously admitted model with rejected event study retains `rejected-event-study` and no fake numerical event run.
- Genuine M28a trajectories must bind to the original actual physical spec, carry complete three-component finite native sample vectors, correctly typed *float* SI times, increasing timestamps, the real initial state, honest full duration or genuine source-guard censoring, and nonnegative finite energy drift summary. The issued digest detects all changed physical result values at export, including `False == 0.0` timestamp forgery and modified native force/energy fields.
- Physically refused, invalid event studies and numerical integration failures retain their distinct actual admitted/missing source/native statuses. Neither refused variants nor unrelated valid siblings are recomputed, silently dropped or fabricated. The status/model/native consistency checks also apply when calling standalone `SweepEntry.as_dict` or `EventSweepEntry.as_dict` with the genuine baseline and actual typed questions.
- Direct construction of a legacy run wrapper without a runner-issued token now fails closed rather than treating a caller-assembled object as authenticated native evidence. Continue to build results via the existing public `run_trajectory_sweep` and `run_event_sweep`. Ordinary `dataclasses.replace` of a valid issued run with altered content fails against the original issuance digest, not by implicitly refreshing it. An identical copy may retain the original bytes and be valid; there is no changed physics in that case.

**Trust boundary:** these are **in-process consistency receipts** and source-evidence checks, NOT externally signed cryptographic provenance. A privileged Python actor could deliberately access private issuer internals or construct malicious objects; detached exported JSON is never trusted input to reconstruct native physics. The M32a–M35a issued graph/fork/inquiry APIs **do not begin trusting** older M28a/M28b sweep wrappers as valid history sources.
