# M16b — Offline elapsed-time motion and energy explorer

## Goal and model reuse

M16a introduced actual classical one-dimensional particle motion from the
existing analytical `force_energy` observations. M16b adds **no new physical
integrator or force formula**: the one-line authoring interface
`sample_motion_1d(spec, backend)` runs M16a once (or consumes a prior matching
`Motion1DResult`) and uses the original `sample_sweep` + `render_html` to
precompute the potential, electric-field geometry, conductor charge profiles
and point-source position at the **actual integration output times**.

```python
from conductor_sim import Motion1DSpec, sample_motion_1d, GroundedPlaneBackend
from conductor_sim.visualization import write_visualization

spec = Motion1DSpec(problem, 0, 1e-6, (0, 0, 1), -.02, .06, .006)
bundle = sample_motion_1d(spec, GroundedPlaneBackend(), resolution=25)
write_visualization(bundle, 'output/motion.html')
```

The above `problem` is an authored `ElectrostaticProblem` with one point
charge and a supported conductor. `sample_motion_1d` is not itself a dynamics
backend and does **not** prescribe a charge's path: it uses the selected
position and velocity produced by `integrate_motion_1d`.

## Two independent resolutions (no simulated fields between frames)

M16a can retain up to **2,001** numerical time samples. The browser graphs
include **every sample** and all original event records. For bounded HTML
size and preparation cost, at most **24** actual time samples are chosen for
visual field snapshots; endpoints and nearby turning/surface events are kept.
The selection is spread over elapsed time, not distance travelled (which may
reverse). It is recorded explicitly as `frame_sample_indices`.

Each displayed field map is solved at **exactly the matching numerical
position**, on a fixed planar cross-section that contains the full trajectory
and conductor geometry. The same solution must provide a compatible
analytical force and mechanical interaction energy as the stored M16a sample.
If the sampled solution disagrees, or if a FEMM solution lacks a supported
force/energy provider, export **fails closed**. There is no browser-side ODE,
no interpolation of fields from a different position, no fabricated force,
and no FEMM-to-analytical substitution. The shared asinh potential colour
scale and field-line-density control are retained.

The standalone HTML contains the full saved dataset. Play/pause/restart and
playback-speed controls merely schedule the next saved field **snapshot**;
actual physical time is read from the stored records. Playback time is
compressed to about four seconds at 1× for human viewing—**1× is a display
speed, not one wall-clock second per physical second**. Keyboard manipulation
of the time slider stops playback and preserves a correct synchronized
particle position, signed velocity and graph marker.

## Graphs and scientific labels

The elapsed-time panel displays the particle's **signed displacement**, signed
1D velocity, and kinetic (`K`), mechanical interaction (`U`) and combined
(`K+U`) energies. Each plot has real physical elapsed time on its x-axis;
units are auto-scaled solely for readability. The readout also gives actual
force, acceleration and `energy_drift_j` from M16a; graph values never
replace the numerical data. Blue/teal scene arrows show force/velocity
vectors projected into the fixed display slice, with explicitly
**display-normalized lengths**.

Recorded turning points remain part of the timeline. A `surface-guard`
termination is an **approach cutoff** before an ideal singular metal contact,
not an exact impact, collision, bounce or wire current.

## Examples and reproducible browser checks

```powershell
python examples/particle_motion_viewer.py --case cavity --output output/m16b-cavity.html
python examples/particle_motion_viewer.py --case plane --output output/m16b-plane.html
python examples/particle_motion_viewer.py --case plates --charge-c=-1.602176634e-19 --mass-kg 9.1093837139e-31 --duration-s 5e-8 --sample-interval-s 5e-9 --output output/m16b-electron.html
Start-Process .\output\m16b-cavity.html
```

These produce self-contained HTML and adjacent JSON with identical embedded
physics. Chromium regression checks the saved state/field correspondence,
negative velocity/arrow direction, synchronized graphs, time units, play/pause,
restart, keyboard slider, mobile width and offline/no-JS-error behaviour.
Older v1 field-only bundles and M13–M15 **quasistatic position sweeps** remain
unchanged and never get a false elapsed-time control.

This does **not** add general 2D/3D particle trajectories, finite particle
impact models, relativistic dynamics, multiple moving charges, conductor
motion, numerical FEMM force, or time-dependent electrode voltages. M16b
uses the already validated **analytical** one-dimensional M16a domain.
Accepted old FEMM regression tests demonstrate numerical non-regression,
not physical FEMM dynamic-force validation.
