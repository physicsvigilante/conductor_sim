# M17a — Reusable planar electrostatic particle dynamics

M16a's exact elapsed-time one-dimensional dynamics is retained. M17a
adds an initial 3-vector velocity and integrates position and velocity in
a **physically invariant plane**, not on an artificial guide or a prescribed
trajectory. The plane follows from the authored conductor geometry and
initial velocity. It is reported in the result, never enforced by projecting
away genuine transverse forces.

## Public authoring example

```python
from conductor_sim import (
    ConductingPlane, ElectrostaticProblem, FixedPotential, Motion2DSpec,
    ParallelPlateBackend, PointCharge, integrate_motion_2d,
)

problem = ElectrostaticProblem(
    (PointCharge(1e-9, (0., 0., .1)),),
    (ConductingPlane(),
     ConductingPlane((0., 0., .2), (0., 0., -1.),
                     FixedPotential(20.), 'upper')),
)
spec = Motion2DSpec(problem, 0, 1e-6, (.2, 0., .03), .04, .005)
result = integrate_motion_2d(spec, ParallelPlateBackend())
print(result.termination, result.samples[-1].position_m)
```

Run the standalone numerical-data exporter:

```powershell
python examples/particle_motion_2d.py --case plates --output output/m17a-plates.json
python examples/particle_motion_2d.py --case plane --output output/m17a-plane.json
python examples/particle_motion_2d.py --case sphere --output output/m17a-sphere.json
python examples/particle_motion_2d.py --case cavity --output output/m17a-cavity.json
```

M17a uses the existing immutable `ElectrostaticProblem`, existing analytical
`force_energy(solution)`, and existing backends. Both M16a and M17a now
reuse a dimension-independent `rk4_step` routine; their integration controllers,
observations, input models and domain guards remain separately type-checked.
The new physics samples use schema `conductor_sim.motion_2d.v1` (3D SI
vectors for position/velocity/acceleration/force, elapsed time, kinetic,
mechanical interaction, and total energy, plus componentwise drift).
It is **not** a browser playback payload or a quasistatic position sweep.

## Domain and validation

- Exactly one nonzero moving point charge, no other point charges.
- One infinite grounded plane, or two facing infinite parallel planes with
  grounded/fixed-potential constraints, using force-capable analytical backend.
- One grounded/fixed-net-charge solid sphere with a charge outside it.
- One or more strictly nested concentric spherical conducting shells with
  charge strictly inside the innermost cavity.
- For planes, the invariant plane is spanned by the electrode normal and
  initial velocity. For spheres, it is spanned by the radius vector and
  initial velocity. Degenerate zero-angular-momentum starts are permitted.
- A transverse force at *any* evaluated state causes explicit refusal.
  There is no projection that manufactures 2D motion.
- An adaptive RK4 step-doubling controller evaluates true elapsed-time
  dynamics and records SI samples and mechanical-energy drift. Fixed applied
  voltages use the existing mechanical interaction potential with voltage
  source work accounted for, not naive capacitor field energy.
- A vacuum-side surface guard terminates before singular metal contact,
  labelled **approach cutoff, not exact collision or bounce**.
  Speeds at or above 0.1c are rejected. FEMM solutions without actual
  numerical force are refused; FEMM-to-analytical fallback is forbidden.
- Numerical/reference tests cover angled launch, independent constant-force
  kinematics, biased-plate parabolic limit, central-force angular momentum,
  curved cavity motion, numerical energy consistency, refusal, ownership,
  serializability and guard termination.

## Acceptance conditions

Full Python 3.10 and 3.12, original visualization and authoring/browser
regressions, and the pinned 97 real-FEMM numerical tests (zero skips)
must pass on the exact PR head before merge. Those FEMM tests prove
**old numerical non-regression**, not FEMM vector-force accuracy.

M17b will add curved-trajectory visualization by consuming this existing
trajectory and solving bounded matching electrostatic field snapshots.
M17a does **not** add a browser-side ODE, free unconstrained 3D arbitrary
geometry, multiple moving charges, magnetic fields, varying electrode
voltages, finite-particle impact, or relativistic dynamics.
