# M25a — Honest source geometry across retained motion investigations

M25a fills a **presentation** gap, not a new electrostatic physical model. The
post-M24b public authoring trial numerically solved two coaxial charged rings,
but the driven viewer listed those rings without drawing them; both new motion
viewers could also give off-plane points or rods misleading in-plane markers.

The same typed Python `source_geometry(spec, annotations)` builds a
bounded display-only ledger for **both** conservative-event and driven-motion
viewers. The existing static M19b viewer already has its separately qualified
physical-slice rules, including source omission metadata for mirrored rods and
points. Its historical outputs and serialized contracts remain unchanged here.
The new ledger is intentionally an observer, not a universal scene graph or
replacement of the older static-renderer schema.

## Actual geometry and invariant physical model

- True point charges are shown only when their positions lie in the physical
  motion plane. Off-plane points are omitted. Stable source identity, complete
  world position, charge and **signed normal offset** remain visible in the
  source ledger; the field is calculated from the original 3D source unchanged.
- True charged finite rods are shown as rods only if **both endpoints** lie in
  the physical slice. Off-plane rods (including rods crossing or aligned normal
  to that slice) are **not flattened** into a fictitious in-plane line segment.
  Both endpoints and signed offsets remain in the readout.
- Fixed uniformly charged **volume spheres** and fixed **thin shells** use
  physical plane intersections of their radial boundary. The drawn radius is
  `sqrt(R**2 - h**2)` **only if** `abs(h) < R`. Strictly outside bodies
  `abs(h) > R` are omitted regardless of the solver's *separate* numerical
  plane-proximity tolerance; `abs(h) == R` is a single marked tangent point
  with zero slice area, not a circular intersection. Here `R` is the radial
  source radius and `h` the signed normal offset.
  not the full 3D orthographic outline of a sphere displaced from the slice.
  These are not conducting equipotential objects; their original source laws
  and surface qualifications remain authoritative.
- Fixed **rings and discs** are displayed as genuine orthographic projections
  of their 3D circular boundary: two projected rim-basis vectors multiplied
  by the actual source radius, never point-charge substitutes or electric-field
  evaluations. Axis-in-plane source motion produces an **edge-on projection**;
  a ring has an outlined dashed diameter with endpoint circles at the true
  **major semiaxis**, derived from both rim-basis vectors rather than just one
  vector; a disc has a thicker surface projection. Both are distinct from a
  physical charged rod.
- Uniform fixed electric fields appear as **direction glyphs only**, not
  integrated field lines or spatial field maps. M24b scheduled applied E is
  separately identified in its physical input ledger and retains its actual
  force and work records.

Every displayed entry retains `source_id`, label, physical kind, charge when
applicable, status (`in-slice`, `slice-intersection`, `orthographic-projection`,
`background-field`, `slice-tangent` or `omitted-out-of-plane`) and the actual world quantities.
The source checkbox switches the source layer, **not the physics**; playback
still consumes the original computed states. Screen right/up and physical
plane normal are world vectors from the qualified model. Browser rendering
reads the Python-built geometry entries; it never computes electrostatic E/V.

## Public API and reproducible previews

The prior authored models are unchanged. For example:

```powershell
git pull --ff-only
python -m pip install -e ".[test]"
python examples/public_api_event_trial.py --case coaxial-rings --output output/m25a-rings.html
python examples/public_api_event_trial.py --case mirror-rod --output output/m25a-mirror.html
Start-Process .\output\m25a-rings.html
python -m pytest tests/test_m25a_source_geometry.py -q
python -m tools.check_m25a_source_geometry --case ring-disk --output output/m25a
```

The same geometry service is imported by `motion_event_viewer.py` and
`driven_viewer.py`. The source inventory, model revision, force components,
kinetic/interaction energy, scheduled work, dissipated energy and event
brackets are not changed by source display; only a new
`display/source_geometry` projection ledger in the standalone HTML is added.
The JSON numerical `run.as_dict()` stays its historical schema.

## Acceptance and acknowledged limits

Preimplementation frozen cards: [`m25a_charter.md`](m25a_charter.md).
Reserved transfer recipe: [`m25a_reserved_card.md`](m25a_reserved_card.md).
The authoring tests are public Python API cases, with no case-specific
production solver, but remain **same-developer/author-exposed**. The R2 recipe
is frozen before its first committed-CI execution; its exact numeric values
were not frozen before source implementation.

The legacy M19b viewer continues to show ring meridian intersections and its
existing certified off-plane omissions rather than adopting the M25a source
ledger by default. A separate opt-in migration could be evaluated if a future
real source-fidelity need justifies touching that historical visualization.
The new views are 2D slices/projections, not rotatable 3D apparatuses, material
contact solvers, off-axis ring/disc field maps or conductor-response simulations.
Correct qualification/refusal rules remain unchanged. An absent source marker
never means its true source field has been deleted.

## Post-review correction and source-identity trust boundary

An independent separate-chat review of PR #60 (Chat B, original report pinned
at commit `31ee492bd6070e8b74bf233c44a86de6301af827`) requested changes:
[F-01/F-02/F-03 review](https://github.com/physicsvigilante/review_sandbox/blob/main/projects/conductor_sim/pr-60/reviews/review-01-chat-b.md).
The original reviewer report remains unchanged. F-01 identified displaced
**open-end ring markers** in a qualified 45-degree rotated motion plane even
though the 81-point rim path was correct. The major projected semiaxis is the
largest singular direction of the actual 2-by-2 rim projection; both endpoint
circles are now positioned at its actual geometric extrema. Two fresh,
fully integrated, qualified native models exercise this rotation with real
Chromium canvas-arc assertions in the conservative-event and driven viewers.
Other true edge-on orientations and pure mathematical face-on/elliptical
projector controls are checked separately. No source law or qualification is
weakened to create an unqualified face-on axial trajectory.

F-02 was an actual *presentation* boundary: closeness to a plane for a motion
solver is not a licence to call a geometrically outside sphere/shell an
intersecting slice. Strict inside, tangent and outside cases with very small
radii now have separate status/shape and data-level regression controls.

F-03 documents the limits of IDs: a standalone
`source_geometry(spec, annotations)` receives an **author-supplied identity
assertion**, not a cryptographically authenticated mapping. Only the two
integrated viewers bind geometry to their already validated immutable
`PrescribedScenario` with `trusted_scenario=...`; mismatched annotations or
an unrelated spec object are rejected. The immutable scenario's revision ID
identifies the authored mapping; it does not establish the truth of source
provenance, and edited offline HTML is **not** an authenticated input format.
An author may deliberately create a *different* scenario with different IDs,
which requires an explicit new model, not undetectable swapping in the viewer.

Source PR CI must be re-run for the new reviewed head. The original failed
M25a CI launch (script import path) and original Chat B findings remain visible
as source-specific historical evidence. A focused Chat B re-review checks the
changed renderer, radial-boundary semantics, scenario-binding guard and two
new browser cases; a repeated whole-project review is not warranted if no
physical/numerical semantics changed. A reviewer report does not itself grant
production merge approval.
