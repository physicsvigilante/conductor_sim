# M28a — Frozen preimplementation contract: parameter sweeps of independently solved trajectories

Owner approved starting M28 after verified M27b and the F-01-only follow-up. This charter is authored **before implementation** and does not pre-authorize a release merge.

## Purpose and physical boundaries

A teacher should be able to keep one source-anchored physical apparatus and ask a family of physical hypothetical questions: change one identified fixed-source parameter or a genuine particle initial condition; requalify, integrate and compare real trajectories. This is an engine composition and time-observation milestone, **not** a case-specific ring formula, a second ODE engine, an LLM parser, a moving conductor, a source-contact model, or unconstrained 3D dynamics.

- The unchanged original `PrescribedScenario` is the baseline. For each **distinct** chosen parameter value, invoke the existing M20b `revise_scenario` with a stable physical component identity and create a separate immutable teacher-hypothetical child with an audit revision ID. Never mutate the baseline or chain siblings; each trial starts from the original. The actual numerical model remains a normal `TestChargeMotionSpec`.
- Only **one typed physical parameter per sweep**: an existing source's actual dataclass physical property (e.g. ring `charge_c` or full `center_m` vector), the moving `test-particle` charge/position/physical motion mass/velocity, or existing medium/gravity properties. Use M20b's existing supported revision paths. No ad hoc axis coordinate swapping, implicit plot-scale edits, unverified new source types or numerical-step/guard edits. Sweeps of separate parameters are separate runs, not Cartesian products.
- Bound total work: exactly one baseline and 1..6 distinct authored revisions. Reject duplicate values including an unchanged baseline, invalid identities, mixed value shapes, Boolean numerics and unsupported properties. Validate the **entire revised model** before integrating each revision; invalid physical revisions are visible typed refusals, not silently discarded and never silently clipped to admissible values.
- Use the unchanged public `integrate_test_charge` numerical controller, fixed fields, energy/guard rules and physical symmetry certification for every model. No browser-side RK, current, induction, conductor response, ring-wire impact, or invented trajectory extension. Numerical integration failures must be reported explicitly and separately from physically inadmissible cases.
- Preserve model-specific termination. A `source-guard` or other early termination is **censored**, not duration-complete. Compare baseline and variation only at **identical actual saved physical timestamps**, with no interpolation or extrapolation; absent times remain absent. Return explicit overlapping-time position and velocity component differences and Euclidean distances in SI. Cross-scenario energy values may have different physical gauges; do not infer work across scenarios from `delta U`.
- JSON export is detached, versioned, finite and records baseline/revision lineage, selected axis, all accepted solver sample series (or refusal), separate termination and observer limitations. SHA IDs identify authored records, not independently authenticated workbook facts or proofs of ODE correctness.
- A small standalone offline HTML comparison uses only the native saved trajectories: physical-plane projected position curves, source/parameter labels, a shared **discrete saved-time** slider and honest per-variant state/absence indicators. Explicitly label the figure a trajectory-space plot, **not** full apparatus source geometry. Do not quietly render an unqualified trajectory as a ring, a physical guide or a collision.
- Source workbook page 12 Q40–41: both ring charges/radii/separation, external field and **probe q=+10 µC are source-given**. Numeric probe mass, altered launch and motion duration are teacher hypotheses. Do not call original Q41's symbolic/rest/axial solution the free-plane simulation.

## Frozen positive acceptance cards

P1. An off-axis two-ring meridian baseline `examples.m27b_offaxis_motion.author("workbook-xy")`. One sweep changes `ring:B.charge_c` through -18 and -22 µC; a second changes `ring:B.center_m` to (0.35,0,0) and (0.45,0,0) m. The baseline remains bit-for-bit unchanged, source IDs/labels stay unchanged, revisions contain the actual differences, and all accepted runs use the existing ring E field and shared RK, never a new solver.
P2. Physical particle-parameter sweeps change `test-particle.mass_kg` and `test-particle.initial_velocity_m_s`; no change to fixed ring charges or numerical policy. Invalid off-plane launch or oblique ring geometry must fail the **whole-model** physical certificate.
P3. An independently understood uniform E reference with constant acceleration must match analytic kinematics for each mass choice at saved times. Rigid transform of an unfamiliar valid fixed-source system and corresponding launches must preserve coordinate-covariant results.
P4. A source-guard-censored revision is retained with its original terminal time and no fabricated later comparison states; a physically refused variation is separately recorded. Successful variations still run when another variation is rejected, with no source mutation.
P5. Full JSON retains all solved samples, rejection reasons and provenance, computed deltas at exact shared timestamps only; strict SI and no interpolated missing frames.
P6. Real offline Chromium HTML shows actual curved tracked trajectories and a slider with saved time, source identity and correct values; changing the slider causes only saved-state selection, works at 390px, does not fetch network resources or throw JS errors. Browser data comes from native output and correctly identifies censored outcomes.

## Frozen negative acceptance cards

N1. Duplicate axis values, baseline repeated, empty or overlong sweep, invalid stable ID, unsupported property or Boolean numeric, unauthored source index, unsupported numerical tolerance/guard edits: reject before computation.
N2. A revised ring axis oblique to the actual common motion plane, a ring center shifted out of that plane, invalid source-charge/positive-radius constraint, or a launch inside source wire guard must be explicitly refused. Large authored length_scale cannot override physical admission.
N3. A syntactically admissible model can still halt at source guard or fail numerical convergence. Censor; do not force a duration-complete sample or swallow unexpected implementation exceptions.
N4. No mismatched time index disguised as equality, unqualified browser interpolation, comparing full duration when one case is censored, or falsifying source identity. Malformed/tampered manifests must not be silently accepted by the renderer.
N5. Existing M20b revisions, M24 event/driven models, M27a static field, M27b motion, older prescribed/held-source viewers and 97 real FEMM tests remain unchanged.

## Evidence and release gate

Before release: new deterministic Python native/negative/analytic/guard tests, an unfamiliar or rigidly transformed transfer case, real Chromium offline browser check including 390px, full Python on 3.10/3.12, all existing independent physical references and 97 real FEMM nonregression tests. Preserve exact baseline and first failures; do not relax frozen physics assertions to meet a candidate. Reviewer should challenge source identity, typed revision application, guard/truncation, exact-time comparisons, numerical/reference evidence, browser saved-state semantics and what is/is not source-given.

The implementation may be split into M28a API and M28b fuller apparatus viewer. This M28a charter includes a **small trajectory-space comparison**, not a replacement for the existing source-geometry viewer. Keep the new source PR draft and unmerged until exact-head CI and independent scoped review as warranted; owner separately approves merging.
