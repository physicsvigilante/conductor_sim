# M21b — JEE Advanced static electric potential, field and endpoint work

## Why this milestone

M21a selected source-backed problems instead of prioritizing generic framework
features. M21b uses **existing electrostatic field formulas** to visualize
three concrete source-relevant questions, each requiring a different
observation mode. It is not a new solver and deliberately avoids fabricated
particle motion or conducting-source induction.

The acceptance charter, [m21b_charter.md](m21b_charter.md), was committed
before writing implementation code.

## Source-faithful examples

| Source | Physical quantities actually given | Viewer mode | Additional illustrative choices |
| --- | --- | --- | --- |
| Official JEE Advanced 2021 Paper 1, Q9–10 | Charges −Q at (0,0) and +Q/√3 at (2,0) m, V=0 circle | Full physical xy plane, M5 sampled potential/field, highlighted **zero-volt contour** | Absolute source magnitude Q=1 nC for display (the zero locus is Q-independent) |
| Workbook `02_conductors_half_size.pdf` p15 IIT-JEE 2012 archive, thin-shell graph | Thin spherical shell, uniform **positive surface** density and symbolic R; asks for E(r)/V(r) | True static radial E/V graphs with undefined E at ideal r=R | Q=+1 nC, R=0.10 m |
| Same workbook p12 Q40–41, two coaxial rings | Ring radii 0.30 m, separation 0.40 m, +10 µC and −20 µC, test charge +10 µC, uniform E=10⁵ N/C **up** | Physical horizontal axis and endpoint-work table, static axial E/V profiles, schematic orientation | None for Q40 (the mass for Q41 is symbolic and deliberately not assigned) |

The 2021 problem has an exact analytic Apollonius circle

[
(x-3)^2+y^2=3,quad R=sqrt{3},mathrm m, b=3,mathrm m.
]

The displayed highlighted contour is **derived from the actual sampled
potential grid** using the existing M5 triangulated contour routine. It is
not the exact circle drawn over an unrelated image. The original charge
signs and locations are maintained; near-charge singularities have visibly
excluded *presentation masks* that are not physical charge radii.

The 2012 shell is a fixed, uniformly charged **nonconducting surface**
model. For a positive total charge Q, the limiting radial behavior is

[
 V(r)=egin{cases}kQ/R&rle R\kQ/r&r>Rend{cases},qquad
 |E(r)|=egin{cases}0&r<R\kQ/r^2&r>R.end{cases}
]

At the ideal surface (r=R), the field has a one-sided jump: **no
single E(R)** is silently assigned. The saved sample at the surface is
`null` and the displayed line graph has an actual gap; V remains
continuous and defined.

For the two-ring question, the source-given endpoint work is

[
 W_{m field}=q(V_A-V_B)simeq +3.5950207,mathrm J.
]

The vertical external field is physically **transverse** to displacement
from ring A centre to B centre. It contributes **zero work** but exerts a
nonzero vertical force. The provided workbook statement “if the particle
moves along the centres” does not prescribe a physical guide force or
justifies inferring a free axial path. M21b **does not** simulate one. It
also does not substitute a numeric mass for symbolic Q41.

## Reuse / qualification

- `sample_fixed_potential_map` adapts built-in
  `FixedPointField`/`UniformElectricField` inventories to existing M5
  `SamplingContext`, `sample_frame` and `contour_segments`. It retains
  strict source identities and rejects point charges outside the physical
  plane, transverse external fields, or any axial-only ring/disc as a
  two-dimensional map.
- The static map's M5 renderer uses opt-in fixed-source metadata to hide
  conductor results and density panels, set accurate scope labels, and
  emphasize the requested V=0 contour. Default old M5/M19 viewer data and
  rendering remain unchanged. The saved grid is rechecked against source
  potentials and fields before HTML rendering.
- `sample_static_profile` observes source V and the **entire E vector**
  at actual world points. It stores parallel and transverse components
  separately. Singular or discontinuous E values remain null, and are
  never interpolated across a jump by the profile graph. Ring/disc sources
  can be evaluated only on their actual symmetry axes.
- `endpoint_field_work` calculates q(V_A−V_B) using each unchanged
  source's potential. The computed source-by-source ledger makes a
  vertical-field zero-work contribution explicit without discarding
  its physical transverse E. This is endpoint potential work, not
  elapsed-time integration.
- The two one-dimensional charts are lightweight server-authored SVG
  polylines over actual numerical observations. No browser physics,
  tracing or fabricated source-force magnitudes are used in those charts.

**Current bounded limitation:** M21b's certified physical 2D **map** supports
point charges and in-plane uniform electric fields, not 2D maps of rods,
volume spheres, thin spherical shells, off-axis rings or discs. The
existing fixed-source field backends can evaluate many of those in
different qualified observation regimes; M21b has not supplied the surface
and singularity masks/line-stop certificates needed to make every spatial
map reliable. Such cases are refused, not silently painted.

## Reproduce

```powershell
git pull --ff-only
python -m pip install -e ".[test]"
python examples/jee_potential_explorer.py --case 2021-equipotential --output output/jee2021-circle.html
python examples/jee_potential_explorer.py --case 2012-shell --output output/jee2012-shell.html
python examples/jee_potential_explorer.py --case ring-work --output output/jee-ring-work.html
Start-Process .\output\jee2021-circle.html
```

Every generated HTML is self-contained and accompanied by a JSON audit of
the source inventory and saved observations. For example,
`python -m pytest tests/test_m21b_jee_potential.py -q`
checks source-faithful geometry, independent Coulomb references,
sampled contours, masks, true shell surface discontinuity, field work,
transverse E, refusals, and invalid saved-state rejection. Three distinct
real Chromium runs must confirm actual painting and basic controls, all
offline without external network or JavaScript errors.

This is educational visualization for three authentic *problem families*.
It is not automatic PDF-to-simulation parsing, unrestricted LLM authoring
or proof of full JEE Advanced exam coverage.
