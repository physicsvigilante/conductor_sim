# M14a — Electrical connections between concentric conducting shells

## Goal and compositional interface

Create additional JEE conductor arrangements by changing **the authored
connection plan**, not the nested-shell field solver, FEMM mesh compiler or
viewer. The existing `NestedShellBackend` already provides exact independent
static equilibria for strictly nested concentric `SphericalShell` components
with grounded or fixed-net-charge constraints. M14a adds only a reusable
*constraint compiler* and comparison of the two static states.

```python
from conductor_sim import (
    ConnectionPlan, ConnectedShellBackend, ElectricalLink,
    ElectrostaticProblem, FixedNetCharge, SphericalShell,
)
from conductor_sim.visualization import write_visualization

initial = ElectrostaticProblem(conductors=(
    SphericalShell(.095, .10, FixedNetCharge(1e-9), name='inner'),
    SphericalShell(.195, .20, FixedNetCharge(2e-9), name='outer'),
))
plan = ConnectionPlan(initial, (ElectricalLink(('inner', 'outer')),))
result = ConnectedShellBackend().solve(plan)

print(result.after.conductor_by_name('outer').potential_v)
print(result.released_field_energy_j)
write_visualization(result.visualization(), 'output/connected_shells.html')
```

`ElectricalLink(members, mode='floating')` connects named shells via an ideal
thin wire and **conserves their combined initial net charge**, without
individually conserving each member's net charge. Floating connections
require each member to be initially isolated (`FixedNetCharge`). The
alternate `mode='grounded'` connects a named group to an ideal 0 V reservoir;
its total charge may change. Initially grounded and initially isolated
members can be included in a grounded group. Other shells retain their
original separate constraints. Multiple **disjoint** connected groups may
be authored in the same problem. All names, groups and source geometry are
checked before applying the new constraints.

The explicit `ConnectionPlan` wrapper prevents accidentally treating wiring
metadata as the old independent-conductor model. It holds the original
immutable `ElectrostaticProblem`; it is not a new `FieldSolution`. The result
provides `before` and `after` standard `NestedShellSolution` instances,
`resolved_problem` with independently determined shell net charges or
`Grounded` constraints, and per-shell charge transfers. This lets all
existing field, potential, surface density, profiles, masks, static HTML
states and FEMM backend boundaries remain unchanged.

## Physics and numerical method

For shells ordered from inside to outside, let shell i have inner/outer
radii a_i,b_i, shell net charge Q_i, and let q_0 be the total point-source
charge in the innermost cavity. The exact radial flux outside each shell is

    T_i = q_0 + sum_{j<=i} Q_j.

In the gap between shells i and i+1, the field is k*T_i/r^2. Thus the
potential of shell i is

    V_i/k = T_{last}/b_{last}
          + sum_{j=i}^{last-1} T_j*(1/b_j - 1/a_{j+1})

where k=1/(4*pi*epsilon). Equal potentials for each linked group plus one
**charge-conservation** equation for each floating group (or a zero-
potential equation for each grounded group) form a small dense **linear
system in shell charges**. Untied shells retain their original fixed-Q or
0 V constraints. The existing tested Gaussian elimination from the nested-
shell reference solves this constrained system; the resulting `Q_i` are
lowered into ordinary independent `FixedNetCharge` conditions. Grounded
linked members remain `Grounded` in that lowered model. The existing exact
nested-shell backend solves both states, and the resulting constraints are
checked again for equal potential and conserved linked-group charge.

The **field energy in radial gaps plus exterior** is exactly

    U_radial = k/2 * (
        sum_{i=0}^{last-1} T_i^2*(1/b_i - 1/a_{i+1})
        + T_last^2 / b_last
    ).

The reported `released_field_energy_j = U_before-U_after` is the loss of
stored electrostatic field energy from those regions when a passive ideal
connection reaches equilibrium. With static point charges in the innermost
cavity, its nonuniform cavity field is **unchanged** by connecting exterior
shells, and that cavity energy contribution is omitted from both numbers;
the *difference* is still valid for fixed positions and source charges.
For a no-source model, this is the entire field energy. A real resistive
wire can dissipate this energy as heat, but **no transient current,
resistance, power, electrical-contact arc, or duration** is simulated.

The ideal connecting wire is taken to have negligible thickness and
negligible disturbance of the spherical electrostatic geometry. The engine
does not solve a 3D wire piercing a conductor or arbitrary touching geometry.

## Reproduce one question from the new scanned PDF

`02_conductors_half_size.pdf`, **physical PDF page 14, Numerical Value
Type Q7**, asks: two concentric **thin spherical conducting shells** of
radii R and 2R carry q and 2q. They are connected by wire. Find the
change in the **outer shell** potential. No numerical R or q is required.

Initially, the outer shell sees all charge 3q, so

    V_outer, before = k*(3q)/(2R).

After linking the two shells, all excess net shell charge 3q resides on
the outermost surface, the gap becomes field-free, and

    V_outer, after = k*(3q)/(2R)
    delta V_outer = 0 V.

The example uses representative `R=0.10 m`, `q=1 nC` and narrow but finite
shell thickness solely to show a viewer. The outer shell potential and the
**zero** difference follow exactly, independent of these illustrative
values. This example therefore **supports a previously blocked PDF problem
without any additional case-specific solver logic**.

```bash
python examples/connected_shells.py --case pdf-p14-q7 --output output/connected_shells.html
python examples/connected_shells.py --case ground-link --output output/ground_connected.html
python examples/connected_shells.py --case cavity-charge --output output/cavity_connected.html
python examples/connected_shells.py --case three-shell --output output/three_shell_wire.html
```

The existing viewer's state slider selects the two stored equilibria. An
additional JSON `connection` object reports the group types, each shell's
net charge before and after, the charge transfer, energy and provenance.
The source scenario labels and notes explicitly state that this is **not
particle motion, field-line motion or a time-resolved electric current**.

## Verified scope, limitations and acceptance

M14a covers 2–8 strictly separated concentric `SphericalShell` objects,
with point charges only in the innermost cavity (arbitrary interior positions),
initial independent `FixedNetCharge`/`Grounded`, and nonoverlapping named
floating/grounded groups. It does **not** yet support concentric **solid
inner spheres**, eccentric shells, externally attached separated spheres,
charges in inter-shell gaps, finite wires, fully 3D conductor connectivity,
mechanical forces on cavity charges, or transient discharge.

The compiler is **analytical**. Although its lowered model has the same old
types understood by some FEMM 5 backends, M14a does **not** claim a real
FEMM solve of the physical connecting wire or establish its numerical
energy/force accuracy. Accepted ordinary/FEMM regressions must remain green;
no prior backend, mesh, image kernel or numerical acceptance tolerance was
changed. The only generic shared-viewer changes are a reusable optional
profile-sampling resolution argument and the browser acceptance correction
for physically identical surface-density profiles.

Acceptance requires the focused independent analytic tests (charge transfer,
Gauss-law surface totals, group potential equality, energy minimization,
source-cavity shielding, rotated source coordinates, group order, invalid
layouts), Python 3.10/3.12 full suites, the existing browser/source suite
plus a two-state real Chromium preview, and all pinned existing **97 real
FEMM tests** with zero numerical skips. The case remains a **candidate**
until those exact-head runs are green.
