# Post-M17 correctness review and M17c motion authorability

## Baseline and scope

The baseline is accepted M17b `09def02dd163154388252ec251139c97bb8d12b0`,
Git tree `699e6e50dcb7f9b5de8a4de7abf34ff7d53de26f`. The downloaded retained
GitHub visualization source archive was reconstructed locally and its entire
Git tree matched that baseline exactly. All **637 ordinary tests passed**
before changes; the 97 real-FEMM tests were deselected locally, not represented
as new numerical evidence.

No electrostatic force law, M16/M17 numerical integrator, numerical FEMM
compiler, existing physics tolerance, or retained acceptance gate is changed.
This milestone repairs the planar export/viewer boundary and adds an original
open problem-authoring trial, not a new solver or a new supported geometry.

## Reproduced errors and repairs

**Valid radial launches could fail to render after rotation.** Computing a
slice tangent by subtracting nearly parallel radius/velocity vectors could
leave only floating-point roundoff. Normalizing that residue invented a
nonorthogonal display axis. Four regression cases reproduce the error,
including a charge starting at `(0.1,0.2,0.3)` m with radial velocity
`(0.01,0.02,0.03)` m/s. Constructing the orthogonal axis by crossing the
already-proved plane normal with its radial/electrode direction fixes it
without altering the trajectory or imposing a physical constraint.

**Malformed saved motion could produce misleading graphs.** M17b checked
field-frame positions but not every graph-only row or all physical metadata.
An altered source-charge sign, kinetic energy, or an out-of-plane non-frame
position could pass HTML validation. Shared semantic validation now checks
all rows: finite and increasing times, finite vectors, initial state,
displacement, force/mass/acceleration, kinetic and total energy, planar
membership, reported maximum drift, termination/event consistency, frame
indices/counts, fixed slice and exact field-frame charge identity. Invalid
supplied trajectories are rejected before any field solve is acquired.

Drift is **not** reconstructed by subtracting large total energies: the
integrator's componentwise drift remains authoritative. Validation does
not re-integrate a trajectory, prove an arbitrary internally consistent
edited history is genuine, or cryptographically authenticate a JSON file.
Selected field snapshots still independently check force/energy against the
original electrostatic backend. This is not numerical FEMM force validation.

**A sparse curved path could be drawn through conducting metal.** A
half-orbit saved only at its endpoints has a connecting chord that intersects
the sphere even though both numerical endpoints are in vacuum. The viewer
now leaves such display chords unconnected, using the existing boundary
intersection primitives. Saved sample markers and an explicit gap note
remain visible. No fictitious intermediate trajectory or field is invented;
users can request finer physical output sampling to resolve the curve.
Older saved M17b bundles receive the same gap handling when rendered, without
mutation of their input data. Component plots now explicitly label m and m/s.

The initial focused set had **20 failures and 1 pass before correction**;
these are regression case counts, not 20 distinct physics defects. A further
sparse-orbit regression brings the correctness set to 22 tests.

## Original JEE-style authoring trial

There are **12 original prompts: 8 supported trajectories and 4 explicit
refusals**, with 21 independently checked output states per supported
trajectory (168 states total). This is **one open assistant-authored
engineering trial, not blind LLM accuracy**, an automatic natural-language
parser, or extra coverage of either checked-in textbook PDF.

The prompts, authored submissions and grading references are separate:

- `m17c/questions.py`: textual problems and units.
- `m17c/attempts.py`: existing public model components and `Motion2DSpec` only;
  no grading reference imports or problem-specific force/integration code.
- `m17c/reference.py`: independent mirror/Kelvin closed forms and a test-only
  velocity-Verlet reference with step-halving convergence. No production
  engine imports or production RK4 stepping kernel.
- `m17c/evaluate.py`: model/units/constraint checks **before** integration,
  full time-series comparison, vector angular momentum or tangential-velocity
  checks, force, acceleration, K/U/K+U and mechanical-energy drift grading.

Supported cases cover a translated tilted plane with a negative charge;
an obliquely launched electron between biased infinite plates; grounded and
fixed-net-charge exterior spheres; oblique grounded-cavity motion;
translated nested fixed-charge shells; a rotated radial special case; and
passage through the nonsingular cavity centre. Prompt masses of 1 milligram
are explicitly converted to `1e-6 kg`. Incorrect mass, charge sign, velocity,
geometry, constraints, time or observed output fail mutation tests.

The electron case uses **exact uniform-field kinematics as a limiting
reference**, not an assertion that induction is identically absent. A
conservative elementary-charge image-force bound is checked against the
background force. The production simulation retains the plate backend's
induced forces and interaction energy. The other seven references compare
against independently converged nonlinear trajectories; their test-only
integrator never supplies data to a production viewer.

Refusals cover two coupled moving charges, numerical FEMM force, finite-plate
edge/fringing geometry, and voltage varying during flight. A refusal cannot
be replaced by a convenient supported model and counted as a solved problem.

## Reproduce

From the repository checkout after installation with `.[test]`:

```powershell
python -m m17c.evaluate list
python -m m17c.evaluate grade --output output/m17c-grade.json
python -m m17c.evaluate render electron-plates --output output/m17c-electron.html
Start-Process .\output\m17c-electron.html
```

Other supported identifiers include `tilted-plane`, `grounded-sphere`,
`isolated-sphere`, `cavity-oblique`, `nested-cavity`, `rotated-radial` and
`centre-crossing`. Rendering calls the same production `sample_motion_2d`
and standalone HTML renderer; no benchmark reference is rendered as physics.

## Verification and merge gates

Local verification: **694 ordinary tests passed, 97 FEMM cases deselected**;
the original 637 tests plus 57 new correctness/authoring cases. The grader
reported 12/12 with the denominators above. Actual Chromium accepted tilted
plane, nanosecond electron and nested-cavity exports: matching physical
frames, full graphs, keyboard/playback, 390 px layout, no JavaScript errors
or network requests. A separate browser check measured 16 actual force and
velocity arrow directions and verified that the metal-crossing display
chord was not drawn. Representative screenshots were visually inspected.

Before merge require exact-head Python 3.10 and 3.12, all retained
visualization/Chromium and M15c authoring regressions, the new M17c review
workflow, and all **97 pinned real-FEMM numerical regressions with zero
skips**. Local deselection does not satisfy the FEMM gate. The FEMM run
establishes earlier numerical-domain non-regression, not FEMM trajectory
accuracy. No gate may be relaxed to accept this milestone.
