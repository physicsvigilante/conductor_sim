# M26a — Structurally reassemble an existing driven experiment

M26a closes the gap between [M22a atomic structural source revision](m22a.md)
and [M24b retained drag/scheduled electric-field motion](m24b.md).
It **does not** invent a force law, solver, scene graph, data importer or
analytical solution to new electromagnetic boundary conditions.

`reassemble_driven_model(parent, *, model_id, scenario_id, note,
add_sources=(), remove_sources=(), replace_sources=(), gravity=...)`
produces a frozen `DrivenReassembly` with `.model` (ordinary, fully
qualified `DrivenModel`), `.base_assembly` (the actual M22a source edit),
`.parent` (retained predecessor), `.changes` and detached `.as_dict()`.
The existing `DrivenStudy` and `investigate_driven_motion` operate on
`.model` directly.

## Authoring one apparatus and changing physical components

```python
from conductor_sim import PointCharge, PrescribedField, TestChargeMotionSpec
from conductor_sim.scenarios import PrescribedScenario
from conductor_sim.structural_scenarios import NamedSource
from conductor_sim.prescribed_fields import FixedPointField
from conductor_sim.driven_motion import (
    DrivenModel, LinearDrag, FieldPhase, UniformFieldSchedule,
    DrivenStudy, EventPolicy, investigate_driven_motion,
)
from conductor_sim.driven_reassembly import reassemble_driven_model

base = PrescribedScenario(
    "lesson:base",
    TestChargeMotionSpec(
        PrescribedField(()), PointCharge(1e-9, (0., 0., .1)), 1e-6,
        (.01, 0., 0.), .04, .01, plane_normal=(0., 1., 0.),
    ),
    (), "Teacher hypothetical; no fixed source initially.",
)
original = DrivenModel(
    base, LinearDrag(1e-8),
    UniformFieldSchedule((
        FieldPhase(0., (.1, 0., 0.)),
        FieldPhase(.02, (-.1, 0., .03)),
    )),
    "lesson:original", "Teacher hypothetical: scheduled-field launch.",
)
child = reassemble_driven_model(
    original, model_id="lesson:with-point", scenario_id="lesson:point-base",
    note="Teacher hypothetical: add an independent held point charge.",
    add_sources=(NamedSource(
        "point:A", "Held point A", FixedPointField(1e-10, (.2, 0., .1))
    ),),
)
study = DrivenStudy(child.model, (), EventPolicy(.005, 1e-9, 1e-9, 1e-8))
result = investigate_driven_motion(study)
assert child.model.applied is original.applied
assert child.model.drag is original.drag
assert child.base_assembly.parent is original.base
```

This edit is assembled **atomically** and validated first against the whole
qualified fixed-source model and then against every phase of the retained
scheduled field. Off-plane unpaired fixed sources, inconsistent ring axes,
invalid source identities, source-count overflow and invalid guard launches
remain refusals. No implicit source replacement uses an existing ID: a true
replacement explicitly retires the old identity. For an already existing
source's properties, use `revise_scenario`, then `revise_driven_model`.

The structural parent may be a previous `DrivenReassembly`. The new child
retains full M22a source ancestry and driven-parent IDs. Retired IDs cannot
be reused within that supplied chain. The immutable child has its own
teacher-hypothetical base scenario and driven model. Existing legacy parameter
revisions remain deliberately distinct. Changing the schedule or drag is
**not** permitted inside a structural operation. Source provenance is an
author assertion, not an authenticated PDF fact. SHA-256 identifies the
record; it cannot establish trusted imports or correct numerical dynamics.

The output model can be reused with different `DrivenStudy` event questions,
numerical policies and the existing offline viewer; those choices are not
physical structural changes. A valid model may still end at a numerical source
guard or unresolved event. Neither a valid constructor nor a successful
visual export demonstrates a complete physical trajectory.

## Evidence and limits

Preimplementation acceptance: [frozen M26a charter](m26a_charter.md).
Executable cases and refusal checks:
`python -m pytest tests/test_m26a_driven_reassembly.py -q`.
Regression gates include full Python 3.10/3.12, existing FEMM and browser
suites. CI results must be checked on the *exact final branch commit*
before requesting independent second-chat review. Existing FEMM tests are
nonregression, not validation of the new prescribed-driven physical law.

No conductor induction, moving held sources, free 3D dynamics,
velocity resets at schedule boundaries, true electromagnetic switching,
collision/absorption rule, off-axis ring fields or LLM PDF interpretation.
These represent separate physical qualifications, not missing adapter syntax.

Start-Process .\\output\\m26a-driven.html

The CI browser check renders the newly reassembled model offline and verifies
its true source identity, schedule switch, saved physical-time control and
mobile/wide Chromium pages; it is a presentation check, **not** a second
numerical force solver. The event and work records are original Python
outputs and cannot be created or changed in the browser.
