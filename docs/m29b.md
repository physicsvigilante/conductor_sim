# M29b — Typed physical event questions across genuinely different source arrangements

M29b addresses another *composability rather than physics-law* gap: a teacher builds one JEE-relevant physical apparatus, adds/removes/replaces supported fixed electric sources (or gravity), and asks the **same typed physical detector/reversal question** in each independently solved arrangement. The engine already had [M22a atomic source reassembly](m22a.md), [M29a independent structural trajectory families](m29a.md) and [M24a typed event investigation](m24a.md), plus [M28b event comparisons for **parameter-only** revisions](m28b.md). M29b composes their unchanged capabilities. [Frozen preimplementation acceptance charter](m29b_charter.md).

There is **no new electric field or gravity formula, no new source-domain qualification, RK, event bracket refinement, collision law, induction, or browser ODE**.

## Public reusable API

`StructuralEventFamilyPlan` accepts an existing `StructuralFamilyPlan` (one unchanged source-named `PrescribedScenario` and 1..5 immutable typed `StructuralCase` alternatives), a tuple of 1..16 supported `PlaneEvent`/`VelocityReversal` questions, and one finite M24a `EventPolicy`. `run_structural_event_family` assembles each physical alternative from the **same original model** using unchanged M22a `reassemble_scenario`, then invokes a **fresh M24a `EventStudy`/`investigate_motion`** for each admitted whole model.

```python
from conductor_sim import (
    StructuralEventFamilyPlan, run_structural_event_family,
    render_structural_event_family, write_structural_event_family_html,
)
from conductor_sim.motion_events import EventPolicy, PlaneEvent
from examples.m29a_structural_family import model

# One original two-uniform-field apparatus and four alternate structures.
family = model("uniform-edits")
question = (PlaneEvent(
    "x:detector", (.006,0.,0.), (1.,0.,0.),
    "Teacher passive detector x=.006 m", direction=1),)
study = StructuralEventFamilyPlan(
    family, question, EventPolicy(.003,1e-8,1e-8,1e-6))
run = run_structural_event_family(study)
print([e.status for e in run.entries])
write_structural_event_family_html(run, "output/structural-event.html")
native_json = run.as_dict()  # Detached, not a trusted model importer
```

Each original or revised `PrescribedScenario` is a complete physical model with stable source identities and author provenance. A model's source membership remains **fixed throughout its numerical trajectory**. Every structural sibling is a new possible teacher scenario, not a time-driven transformation of the original apparatus. `SourceReplacement` retires the old ID and introduces a genuinely new ID/type at the original inventory slot; source-property changes under the same ID belong to M20b/M28a and are not silently smuggled into structural authoring. Source types are prescribed *nonresponding* distributions, not a responding metal conductor.

## Numerical and scientific outcome semantics

- `rejected-structural-model`: the original M22a atomic, whole-model constructor refuses a requested membership/geometry/mirror/physical plane. There is **no invented accepted inventory** or trajectory.
- `rejected-event-study`: the **physical structure is valid**, but its *shared* event questions are incompatible with that particular model, for example a released charge on an authored ideal terminal stop plane whose initial acceleration points out of the permitted region after adding a fixed field. Retain the **real accepted structural ledger**; do not integrate this inadmissible event study.
- `integration-failed`: a physically and event-study-accepted model encounters an original bounded numerical or physical-domain error during actual M24a integration, reported separately from refusal/censor.
- `complete`: native M24a trajectory reaches requested duration, with unchanged source membership. Each question reports the original `located`, `unresolved`, `not-found-at-requested-resolution`, `located-with-unresolved-candidates` outcomes as appropriate.
- `censored`: the original native result terminates before the requested duration, e.g. `source-guard`, `terminal-event` or `event-unresolved`. Earlier true detector roots may remain retained, but **later roots are unknowable**; `search-truncated` is not `not-found-at-requested-resolution`. There is no continuation past a guarded source, no actual impact/contact response and no invented saved state.

Cross-scenario **event root-time comparisons** directly reuse the already independently reviewed M28b `_root_pair`, without reimplementing a root finder. A numerical event shift is only eligible when the **same event ID** has **exactly one resolved native located root**, the **same signed crossing direction**, and **BOTH physical trajectories reached the requested duration**. Guard-censored or terminal-event-censored runs are **unpaired** even when a single root was previously observed before the stop. Multiple crossings and opposite bidirectional crossings are also unpaired; no first root is arbitrarily chosen. For qualified pairs, report each genuine M24a numerical root bracket and the conservative **numerical bracket difference interval `[child.lo−baseline.hi, child.hi−baseline.lo]`**, plus a sample-time difference. This is **not** a rigorous uncertainty bound for the exact physical ODE root.

For full-world 3D trajectory differences, the original M28a `_shared_rows` matches **literally identical actual saved physical times** only. There is no silent interpolation or array-index matching. A non-grid terminal source-guard time can remain unmatched to a baseline sample. Different source inventories can have different potential reference conditions; `ΔU` between different scenarios is NOT work. These are distinct physical hypotheticals, not an evolving charged apparatus.

`StructuralEventFamilyRun.as_dict()` is detached, finite, versioned `conductor_sim.structural_event_family.v1` evidence containing the baseline source identity/charge/geometry and revision SHA, accepted child `ScenarioReassembly` parent/child record and actual source membership/changes (or refusal reason), full original `EventRun` native samples, questions, event IDs, original signed brackets/residuals/outcomes/unresolved observations, qualified event-time comparisons, and literal-time 3D differences. Record SHA is an **authored model identity**, not proof of source scanned-PDF authenticity, event exactness or a mathematically exact solver.

## Offline event-time visualization and source fidelity

`render_structural_event_family` produces a static, offline **event-time chart and complete numerical table**, plus a **source membership card for EACH experiment**. Cards display real bound source ID, *authored visible label*, built-in physical source type, gravity membership, case status and true M22a operation/parent ledger. HTML source/teacher text is escaped, not parsed as executable script. Arbitrary JSON dictionaries are refused as native input. The timeline only runs to each actual native observation end; an observed event occurs at its original numerical root time. If multiple numerical roots would overlap in screen pixels, one **count badge** is displayed to avoid misattributing markers across physical scenario lanes. Grouped badge offsets are explicitly **decorative, not event time evidence**. Any overlapping alternative terminal candidate retained slightly past the selected stop is grouped **at the true terminal boundary**, not interpreted as later particle motion. The **table and JSON retain every original individual event's ID, sample time, time bracket, signed direction, residual and source attribution**.

At a 390px viewport the document and chart fit without horizontal page overflow. The long event table is inside its own keyboard-focusable, labeled, horizontally scrollable region with a sticky scenario column and readable mobile minimum column widths. No internet, fonts, libraries, simulations or event root search execute in the browser. This visualization shows only **event-time outcomes**, NOT the original physical apparatus geometry (ring rims, rod/point positions) or charged-particle trajectory paths. For actual qualified fixed-source geometry or motion paths, use the historical M22a/M27b/M29a viewers.

The M29b examples below are **teacher-authored hypotheticals** unrelated to the scanned workbook's ring question; they must never falsely inherit Q40–41 ring values or q=+10µC just because the same source package can also author that textbook problem. The viewer displays original author-bound `PrescribedScenario.provenance`, explicitly not independent scan verification.

## Example studies

```powershell
python examples/m29b_structural_events.py --case uniform-detector --output output/m29b-uniform.html
Start-Process .\output\m29b-uniform.html
python examples/m29b_structural_events.py --case guard-detector --output output/m29b-guard.html
python examples/m29b_structural_events.py --case terminal-refusal --output output/m29b-study-refusal.html
python examples/m29b_structural_events.py --case double-crossing --output output/m29b-two-crossings.html
python examples/m29b_structural_events.py --case coincident-terminal --output output/m29b-terminal-cluster.html

python -m pytest tests/test_m29b_structural_event_family.py -q
python -m tools.check_m29b_browser --output output/m29b-browser
```

**Uniform detector:** original held E0=+100V/m x and Ey=+50V/m, probe q=+1nC, mass 1e-5kg, initial vx=.1m/s; teacher passive detector x=.006m. Independently adding another +100x field advances the real crossing; removing/replacing only y field or adding downward gravity preserves its genuine x time. The analytical independent reference is `t=2d/[v0+sqrt(v0²+2a_x d)]`.

**Guard detector:** original ballistic source configuration. Adding a negative held charge near x=.2m causes an actual `source-guard` before the far x=.22m detector, while retaining a genuine earlier x=.05m root. This earlier root remains **unpaired** due the truncated observation horizon. A distant positive source stays duration-complete; an inadmissible off-plane source refuses.

**Terminal-refusal:** original held negative-x E causes the charge released on the x=0 ideal stop surface to accelerate inward, so the original event study is valid. Adding a separate large positive-x E reverses the initial acceleration: the revised fixed-source physical model is admissible but its authored stop-side **event study** is not. A second negative-x source remains admissible.

**Double crossing:** a retarding field can make one particle pass the same passive plane forwards and backwards. Adding a new signed field changes both genuine roots, but no uniquely paired event shift is claimed.

**Coincident terminal:** 16 valid near-coincident ideal stop planes produce original native finite-resolution roots in each separately reassembled model. Chart count badges remain within each scenario lane and retain original stop boundaries; table and JSON preserve all actual native values.

**Mirror detector:** adding both off-plane mirror point sources atomically preserves the qualified motion plane; an unpaired off-plane single charge is physically refused. The event integration is genuine fixed-source Coulomb dynamics, not a projection. The native tests additionally verify rigid rotation covariance and direct Coulomb initial force in a novel authored pair.
