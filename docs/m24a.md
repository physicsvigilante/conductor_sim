# M24a — Reusable motion-event investigations

## The architectural improvement

One unchanged `PrescribedScenario` can now answer several typed event questions:
where a specified velocity component reverses, when a detector plane is crossed,
which terminal observation is reached first at the selected numerical resolution,
and the actual position, velocity, forces and energies at each located event.
These are investigations of the existing apparatus, not electron/plate-specific
solvers. Changing initial velocity still uses `revise_scenario`; changing the
numerical search policy or detector questions does not change the physical model.

The frozen [preimplementation charter](m24a_charter.md) names the source questions,
positive/negative cards and one author-exposed reserved transfer before implementation.
This capability does not unify conductor-induced motion, dipole angular events or
arbitrary rigid-body events. It covers the existing qualified prescribed-source
particle family, with optional uniform gravity.

## Public Python interface

```python
from conductor_sim import (
    PrescribedField, UniformElectricField, UniformGravity,
    PointCharge, TestChargeMotionSpec,
)
from conductor_sim.scenarios import PrescribedScenario
from conductor_sim.motion_events import (
    EventPolicy, EventStudy, PlaneEvent, VelocityReversal, investigate_motion,
)

model = PrescribedScenario(
    "lesson:oblique", TestChargeMotionSpec(
        PrescribedField((UniformElectricField((2000., 0., 0.)),)),
        PointCharge(1e-9, (.1, 0., .2)), 1e-6, (.2, 0., 1.2),
        duration_s=1., sample_interval_s=.04, plane_normal=(0., 1., 0.),
        gravity=UniformGravity((0., 0., -3.)),
    ), (("field:applied", "Applied electric field"),),
    "Teacher hypothetical: oblique launch in uniform E and gravity.",
)
policy = EventPolicy(max_step_s=.02, time_tolerance_s=1e-9,
                     position_tolerance_m=1e-9, velocity_tolerance_m_s=1e-8)
questions = (
    VelocityReversal("apex", (0., 0., 1.), "Vertical reversal", direction=-1),
    PlaneEvent("right", (.5, 0., 0.), (1., 0., 0.), "Right detector",
               direction=1, terminal=True),
    PlaneEvent("lower", (0., 0., 0.), (0., 0., 1.), "Lower detector",
               direction=-1, terminal=True),
)
run = investigate_motion(EventStudy(model, questions, policy))
# Ask a different question without reconstructing fields, charge or launch:
apex_only = investigate_motion(EventStudy(model, questions[:1], policy))
assert run.study.scenario is apex_only.study.scenario is model
```

A new investigation may need a new numerical run/refinement. Reuse of the model
is not a claim that coarse old saved samples suffice for every new question.
The pure, typed interface has no unrestricted user callback/plugin registry.
`EventStudy.as_dict()` binds the exact original model revision, query inventory
and a separately declared numerical policy. Original models and source IDs remain
immutable. Results include a new event-trajectory schema; old v1/v2 motion records
are not silently extended with unfamiliar termination meanings.

## Three meanings that must not be conflated

- **Directional reversal** means an isolated zero and sign change of `v.dot(axis)`.
  It is not necessarily total rest. The full three-component velocity is retained;
  `full_stop_within_tolerance` is explicitly numerical, not normalization to zero.
- **Plane crossing** is a root of `normal.dot(r-point)`. Direction -1/0/+1 selects
  decreasing/either/increasing signed crossings. A passive detector exerts no force.
  A terminal request ends the reported observation. An `ideal-stop-surface` is an
  explicit prescribed-field domain limit, requires a signed outgoing direction,
  and checks its initial side. It is not a responding conductor or collision law.
- **Source guard** retains its original numerical meaning. A field singularity or
  jump can end a search before a detector; no uncomputed event beyond it is claimed.

Initial rest and initial-on-plane are reported separately from later events.
Release from a launch plate into the authored side is allowed. A launch directly
out of a declared stop region is refused. A trajectory lying in a detector plane
has no isolated crossing. Grazing and unresolved near-tangencies are not called
exact impacts. Unavailable nonterminal questions do not erase independent resolved
questions; an unresolved terminal question conservatively stops at the last
accepted state before its candidate interval.

Nearly simultaneous events retain their IDs and are labelled order-unresolved
within the requested time resolution rather than arbitrarily picking an ordering.
A terminal event truncates the reported physical history; it supplies no bounce,
absorption, emission, heating, charge-transfer or post-contact continuation.

## Numerical service, not interpolation of saved animation frames

The existing full-vector adaptive RK4 controller has one **opt-in** accepted-step
monitor and optional maximum investigation step. Its normal execution path,
step-size policy, forces, guards and old schemas are preserved. The public old
`integrate_test_charge(spec)` signature remains unchanged.

For an accepted interval the monitor builds scalar cubic Hermite proposals from
its endpoints and physical derivatives. Three additional fractional states check
the proposal; critical-point partitions can reveal two crossings even if both
saved output endpoints have the same sign. If the proposal does not agree at the
requested resolution, the existing controller subdivides rather than inventing
an event. Root localization uses fresh shared RK4 step-doubling states and bisection.
Every returned event re-evaluates the original force and potential providers;
energy is never interpolated. Source-clearance and nonrelativistic checks also
apply to those fractional states. Independent event evaluation/count budgets
fail explicitly instead of reporting no event.

The continuous field can be evaluated mathematically just beyond a regular
terminal detector to bracket a root. Those trial states are not reported as
post-boundary physical motion. Singular fields remain excluded by their guards.

**Limits:** this is a finite-step numerical event search, not a formal enclosure
of the exact ODE or a proof of all roots. Bracket widths bound root localization
within the numerical solution; they do not include the trajectory's global error.
Very short multiple crossings, near-grazing or ill-conditioned events can be
unresolved. Output sampling, ODE tolerance, event tolerances and maximum event
step have different purposes. Convergence and independent physics checks are
required when interpreting precision. `not-found-at-requested-resolution` is
not a proof that no event exists; `search-truncated` does not answer later queries.

For background on this general numerical distinction, the SciPy solve_ivp
reference also cautions that endpoint sign-change event searches can miss
multiple crossings within one step. M24a adds checked interior proposals but
makes no unrestricted root-count guarantee and adds no SciPy runtime dependency.

## Source fidelity and acceptance cards

Actual original scanned workbook `02_conductors_half_size.pdf`, SHA-256
`9dff3c02a9f1848d2c3d99cb1a6e7a44dc7f5a51f7a3a2b8cc92d10ce1fbca5d`,
physical PDF pages 2 and 3, was rendered and visually rechecked.

**p2 Q19** gives a 100 eV electron projected normally at a large metal plate with
surface density -2.0e-6 C/m2, asking the limiting launch distance. The stated
one-sided ideal surface-field interpretation is `E=sigma/epsilon0`, not an
insulating sheet's `sigma/(2 epsilon0)`. The example's 1 mm and 0.2 mm starting
clearances are disclosed teacher choices. The numerical stopping displacement is
computed from the located reversal and initial position; it is not supplied as a
known answer. Only under this uniform-field assumption does that displacement give
the limiting launch distance. Equality is not silently treated as collision.
Image-force response, microscopic emission and fringe fields are not modelled.

**p3 Q30** asks electron transit time between plates at symbolic separation d and
potential difference V. Initial release from rest is the interpretation tested.
The display chooses d=.01 m and V=100 V explicitly as illustrative values. The
field and motion are the ideal prescribed uniform-capacitor approximation, not an
exact responding-conductor solve. Initial lower-surface release is not counted
as a later collision. Independent reference: `sqrt(2*m*d*d/(e*V))` and final K=eV.

| Case | Use of the one unchanged event service |
|---|---|
| `sheet-stop` | Stopping distance, time, velocity and energy; plate not reached before terminal stopping observation |
| `sheet-encounter` | Same source givens, a disclosed shorter launch distance; plane before the stopping event |
| `plate-transit` | Release on the lower surface, upper-plane encounter and energy |
| `oblique-gravity` | A directional apex with nonzero total speed, competing detectors and energy, over one retained model |
| `source-guard` | Search ends at the existing guard before the requested plane; no false contact |
| `reserved-transfer` | Frozen volume sphere + uniform E + gravity; independent displaced harmonic-oscillator reference. Execute only after candidate freeze. |

Development also uses independent nonuniform point-charge turning-energy and
volume-sphere trajectory references, normal reversal and rotation/translation
covariance, two crossings hidden inside one output interval, grazing, initial
zeros, query failure independence, direction filtering, ordering, data tampering,
source guards, policy limits and immutable initial-condition revisions.
The cases are JEE-relevant teacher/source-anchored investigations, not a blind
LLM-authoring benchmark or a statistical estimate of examination coverage.

## Preview and actual browser acceptance

```powershell
git pull --ff-only
python -m pip install -e ".[test]"
python examples/motion_event_studies.py --case sheet-stop --output output/m24a-stop.html
python examples/motion_event_studies.py --case plate-transit --output output/m24a-transit.html
python examples/motion_event_studies.py --case oblique-gravity --output output/m24a-oblique.html
Start-Process .\output\m24a-stop.html
python -m pytest tests/test_m24a_motion_events.py -q
```

The offline player uses saved computed states and event states on physical time.
It shows declared detector/surface geometry, full vector and energy readouts,
actual brackets/residuals, initial-state notes, outcomes and source identities.
It does not depict field lines or infer induced conductor charge. A full 3D
source inventory is only orthographically projected, explicitly labelled. The
browser performs no field/trajectory solve or uncomputed state interpolation.

Existing observation CI is extended, not multiplied into another permanent
workflow. Ordinary suites, relevant prior motion/observer checks and actual
FEMM conductor nonregressions are gates. FEMM is not an event-motion reference.
Legacy numerical data/HTML are regenerated for byte-preservation checks; new
solver hooks are inactive for all unmodified old requests. Initial developmental
failures and post-freeze transfer exposure must be retained in acceptance evidence.
