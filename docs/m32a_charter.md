## Missing engine-level composability

M31b can ask M24a questions over an M31a coupled physical family, M30b over a structural→one-axis sweep, and M29b over source structures. These are valuable, but the engine still needs **one reusable finite composition plan** instead of writing a new adapter for each next combination. A teacher/LLM must be able to say: from this immutable original physical world, make source-inventory branches; revise one or several physical SI properties atomically on selected admitted worlds; branch again from a selected revised world; and ask either genuine trajectory or supported detector/reversal observations of each selected node. These are **separate physical hypotheses**, NOT sequential time evolution or motion of a source during playback.

The model's actual parents, source identities and authored assumptions remain explicit. Real qualification and numerical integration happen on EACH newly authored world; a previously admissible parent does not mean a child is admissible. Numerical initial guesses are never physical initial conditions.

## Bounded native public model

Introduce a simple, strictly typed original-world-rooted directed acyclic **physical-world graph**:

- `StructuralWorldNode(node_id, parent_id, case: existing StructuralCase, observation='trajectory'|'events')`. A structural node uses the **unchanged M22a `reassemble_scenario`** once to apply its complete atomic source add/remove/replace or gravity-membership changes. A structural parent is `baseline` or a prior **structural** node whose full M22a ancestry is retained as a native `ScenarioReassembly`. A structural node may NOT directly descend from a physical-property-revised node in M32a: M22a's public ancestral retired-source bookkeeping is not carried by an M20b `PrescribedScenario`; silently recreating a retired ID would weaken provenance. A later milestone may qualify this mixed-order capability explicitly. Require case.case_id == node_id; all source identities are genuine stable M22a identifiers.
- `PhysicalWorldNode(node_id, parent_id, note, edits: tuple of 1..4 existing `CoupledPropertyEdit`, observation='trajectory'|'events')`. The parent may be baseline, any accepted structural world or any accepted physical-revision world. Resolve every exact stable-ID/physical-property target and SI scalar/vector shape against **that parent**, through the existing M28a/M31a physical allowlist. Reject duplicate target, no-op, gauge-only input, absent/retired source, Boolean/nonfinite value and incompatible shape. Use **one M20b `revise_scenario` call** per node to apply all edits atomically; whole-system qualification is essential (for example a jointly shifted held point and probe initial position may pass when either unilateral intermediate state would fail).
- `UnifiedObservationPlan(plan_id, original: PrescribedScenario, nodes: typed tuple, baseline_observation, questions=(), policy=None)`. Root label is reserved `baseline`; enforce unique bounded ASCII node IDs, native typed inputs, **topological parent order**, no cycles, 1..8 child nodes, maximum depth 4, total <=20 physical edits, and no invented source kind/geometry. Plan ID plus node ID must form a valid new scenario ID. A reused root/source revision ID must refuse.
- Observation is **one of two genuine native modes per node**: `trajectory` uses unchanged `integrate_test_charge`, or `events` constructs the existing `EventStudy`, independently runs unchanged `investigate_motion`, validates `validate_event_run`, and preserves original M24a root samples/brackets/directions/outcomes. At most 16 original typed `PlaneEvent | VelocityReversal` questions and ONE built-in `EventPolicy` may be supplied when an event observation is requested. Unlike older global event-family plans, a passive or stop detector need only qualify for the individual node on which it is requested: an event study that refuses on an otherwise valid parent does **not** prevent a separately physically accepted child from being observed.
- Compute baseline observation once; each accepted child observed **once** by the selected existing native solver. Never use ordinary M31a saved samples as substitute for event-root integration. No browser ODE, novel physics backend, event interpolation, duplicate source law, or fake source motion.
- Never disguise failures: `skipped-parent-model` when parent has no admitted physical world, `rejected-structural-model`, `rejected-physical-edit`, `rejected-physical-model`, `rejected-event-study`, `integration-failed`, genuine `complete`, `censored-source-guard`, `terminal-event`, `event-unresolved`. The scenario/source inventory remains present when a physical model was accepted but observation failed. A parent with accepted physical scenario but event-study refusal may still have independently qualified physical children; a parent with failed numerical observation cannot justify a comparison without a real parent native run. Other siblings continue.
- Only compare immediate **parent → child** when the parent/child both have a genuine native result in the SAME mode: unchanged M28a `_shared_rows` on literal equal original saved physical timestamps for 3D Δr/Δv; and ONLY for event→event edges use unchanged M28b `_root_pair`, which pairs one located same-signed event in TWO duration-complete native event histories. Mixed trajectory→events or missing/censored/terminal/unresolved/multiple-root histories have explicit unpaired or empty comparison categories. No interpolation, extrapolation, post-guard path, numerical exact-root theorem or cross-source-inventory energy difference interpreted as work.
- Return one typed native `UnifiedObservationRun` and detached finite `conductor_sim.unified_observation_graph.v1` JSON: complete original graph plan with every teacher-authored source operation and real physical property edit, explicit source-world inventory and immediate model revision IDs, actual M22a parent/child structural ledger, M20b physical change ledger, real M24a or ordinary native result, separate status stages, original/child observation clocks and valid immediate-parent comparisons. A **runner-issued, pre-export-rechecked in-process receipt** must bind full plan, actual source worlds, native evidence, all statuses, observations, and comparisons; reuse the exact-literal built-in value and scenario-identity precautions from M31a/M31b. Forgeries that rebind model values, source IDs, detector question, event clock, status or parent to authentic results must be rejected by ordinary public dataclass construction/copy and postconstruction export. This is a typed-value/provenance integrity boundary, NOT cryptographic proof against privileged private-Python mutation or authentication of PDF text.

## Frozen acceptance

P1. **Two independent structural branches and nested joint physical revision:** M29a original uniform E=(100,+50,0) V/m; structurally add a new named x-field and separately remove original y-field. On the added-field world, atomically change new field amplitude and probe mass. On that qualified child, separately change real launch speed. Observe typed x-detector in event mode at each selected node; independent constant-acceleration roots, real source IDs, preserved parent revisions, true event-specific saved-state clocks and correct parent→child comparisons.
P2. **True joint admissibility:** on supported fixed-point world shift held point and probe physical initial z together; each unilateral world would refuse. The graph's atomic physical child succeeds with genuine translated motion. No hidden projection or browser-side force correction.
P3. **Repeated structural membership safely constrained:** add a named fixed source, then under a **structural** child replace it with a NEW stable ID or remove it. Retired old ID cannot return in the ancestry. Attempt structural-after-physical must refuse pre-execution, rather than silently losing M22a history.
P4. **Different observation types:** one branch ordinary genuine trajectory, another same event question; a mixed-mode edge has no invented root/position comparison. Two event-mode true parent/child nodes use original M24a and M28b policies.
P5. **Real refusal with successful child:** an admitted parent can reject an M24a ideal stop surface but an independently qualified later revised child can admit it and be genuinely observed. The parent has real accepted source inventory but no event trajectory; child event-time shift is unpaired without parent observation.
P6. **Guards, multiple roots and sibling independence:** genuine source guard retains any previously observed root, later detectors are search-truncated; two bidirectional real crossings do not silently pair. Structural source/physical qualification failure does not hide a valid sibling. A physically admitted but numerically unobserved node has no invented event.
P7. **Unfamiliar independent transfer:** a previously unused signed fixed-source + gravity + newly introduced field arrangement and genuine two-property revision; independently express numerical SI force/position or event time from direct Coulomb/analytic formulas, not production field callbacks; validate exact native source lineage and nontrivial 3D behavior. Retain existing reviewed rod+DOP853 transfer as historic regression only.
P8. **Adversarial evidence and resource bounds:** duplicate/forward/cyclic node or reserved ID, non-native plan/operation/source, duplicate/unchanged/disallowed physical target, forged source parent or revision, forged event result/termination/timestamp, rewritten original M32a plan, coherent false physical edit/label, Boolean 0.0 SI time, mutated evidence after construction; all fail closed. No arbitrary user-defined callback or trusted JSON importer. Initial refused worlds never become solver-backed fake evidence. Bounded node count and total edits enforced.
N1. Do not claim scene graph, universal JEE question parser, responding conductors, induction, moving external source, physical collision/charge exchange, free uncertified 3D, numerical sensitivity derivative, field solver redesign, remote browser/LLM runtime orchestration, or new graphics.
N2. Existing 1,912 Python tests and 97 real FEMM, all accepted original event/model/physics references and Chromium playback remain unchanged.
