# M38b — Original-safe off-axis teacher Kelvin viewer (development)

M38b adds **presentation**, not a new charge law or new JEE problem. The independently released M38a physical authoring API integrates *no* Newtonian orbit: it samples constant-velocity Cartesian world positions and invokes a freshly solved M37a Kelvin electrostatic observation at each real externally prescribed physical timestamp.

## The real educational distinction

The original workbook question in 02_conductors_half_size.pdf, physical page 8 Multiple Correct Q21, has a positive charge **radially** approaching a grounded metallic sphere at externally maintained small speed. Its source-given answer indices (1),(3) and genuine radial current graph are already covered by the verified M37b viewer. M38b instead displays **one teacher-hypothetical 3D straight-line pass-by**, not that printed scenario. It adds **zero** newly solved original JEE items, and it must not change any provisional 30-case original-source coverage statistic.

A teacher can now actually watch the same *qualified Kelvin apparatus* through a different **authored physical trajectory**, while reading signed conventional grounding-wire current. For positive source charge the initial approach produces **positive** sphere-to-ground conventional current, an exactly tangential closest instant produces **zero net grounding current**, and recession produces **negative** current. The source continues at constant world Cartesian velocity; the induced Kelvin force is **observed**, not integrated. Local charge-density redistribution may continue even when net wire current is zero.

## Physical scene geometry, not a fake 2D picture

Every 3D straight line and sphere centre lie in at least one actual Euclidean plane. M38b chooses an explicitly displayed local u-w plane: u is the **real world velocity unit direction**; w is the resolved perpendicular offset from sphere centre to the original line, with deterministic orthogonal fallback for truly radial paths. The normal vector is shown numerically. All 3-vector source positions, force and Cartesian velocity remain visibly available in world x/y/z coordinates.

The stationary grounded solid sphere is an *actual circular cross-section of radius a* in that plane. The complete straight *externally prescribed* path appears using the same fixed metres-per-pixel scale on both local axes. The user interface explicitly states **NOT world x-y and not perspective 3D**. The graph is **signed current I(t) in amperes**, computed at exactly the saved physical times. Connecting the precomputed current vertices is **display interpolation** only. No new force field, transient conductor, charge evolution, formula or ODE runs in JavaScript.

## Public authoring and reproducibility

- Core: src/conductor_sim/prescribed_line_viewer.py provides line_view_manifest(trace) and render_prescribed_line_viewer(trace). Both require a genuine M38a PrescribedSphereLineTrace and re-execute the unchanged native M38a data check before emitting a physical claim.
- Example: tools/m38b_line_viewer_example.py exports m38b-line-physics.json (genuine M38a 41 SI states), m38b-line-viewer.json (Python-precomputed geometry and labels) and m38b-line.html (self-contained offline HTML).
- Independent reference: tools/m38b_line_view_reference.py imports **no production engine**. It checks the 41 physically genuine Kelvin observations through already independent M38a source SI and **independently derives** local axes, pixel scaling, all scene positions, signed-current graph points and SI labels. A saved JSON record is still not an external signature of historic execution.
- Browser: tools/check_m38b_line_browser.py uses genuine Playwright Chromium on a local file:// page, checks actual visible teacher/source and world-basis labels, all signed-current points, sphere/path, genuine selected SI numbers and markers, mobile layout, JavaScript-enabled saved-frame selection and disabled-JavaScript **untouched** first frame. It checks no external HTTP/JS errors and saves screenshots.
- HTML hostility: tools/check_m38b_line_hostility.py runs **18 real HTML-only forgeries** against the actual production browser checker, after confirming each false claim is visible in JS-disabled Chromium. Genuine saved physical JSON and embedded payload remain unchanged. A fraudulent first-frame scene, chart point, text label, source attribution or enabled control must be **refused for its intended scientific reason**, not just visually overwritten at JavaScript startup.
