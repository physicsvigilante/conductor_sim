# M29a — Compare true trajectories after structural source reassembly

**Why this capability exists:** the [prospective composability contract](composability_contract.md) requires independently authored arrangements of reusable physical sources, not a new problem-specific code path for every JEE question. The existing [M22a source reassembly API](m22a.md) atomically adds/removes/replaces named sources, but it is an **authored model**, not by itself a solved trajectory family. The accepted [M28a property-sweep API](m28a.md) compares real native trajectories when a single existing physical property changes, but intentionally forbids source membership changes. M29a fills the **bounded structural-comparison gap** while retaining both older contracts.

[Read the frozen preimplementation charter](m29a_charter.md). It was committed before M29a production code.

## Public reusable authoring

The small `StructuralCase`, `StructuralFamilyPlan`, `run_structural_family` API binds one immutable source-named `PrescribedScenario` to **1..5 independent teacher-authored structural alternatives**. Each case describes actual M22a membership operations, not a textual prompt, and runs independently from the same baseline:

```python
from conductor_sim import (
    FixedPointField, UniformGravity, NamedSource,
    StructuralCase, StructuralFamilyPlan, run_structural_family,
    write_structural_family_html,
)
from examples.m29a_structural_family import model

baseline = model("mirror-pair").baseline
family = StructuralFamilyPlan("lesson:mirrors", baseline, (
    StructuralCase(
        "both-mirrors", "Teacher adds two held charges symmetrically.",
        add_sources=(
            NamedSource("point:above", "Upper fixed point",
                        FixedPointField(2e-9, (.12, 0., .08))),
            NamedSource("point:below", "Lower fixed point",
                        FixedPointField(2e-9, (.12, 0., -.08))),
        ),
    ),
    StructuralCase(
        "single-off-plane", "Unqualified source-plane experiment.",
        add_sources=(NamedSource("point:single", "Unpaired fixed point",
                                 FixedPointField(2e-9, (.12, 0., .08))),),
    ),
))
result = run_structural_family(family)
assert result.plan.baseline is baseline
print([case.status for case in result.entries])
# ['complete', 'rejected-structural-model']
write_structural_family_html(result, "output/m29a-mirror-study.html")
audit = result.as_dict()  # detached, typed and versioned JSON
```

The `StructuralCase` fields are `case_id`, `note`, `add_sources`, `remove_sources`, `replace_sources`, `gravity_action` (keep/add/remove) and optional new `UniformGravity` for add. A replacement requires the existing `SourceReplacement(old_id, NamedSource(new_id, ...))` with a **fresh** source identity. To change **properties** of an existing source, use unchanged M20b/M28a property revisions instead; M29a does not silently change the meaning of a retained identity. Case IDs and operations are bounded before numerical work.

## Reassembly, numerical model and refusals

Each alternative calls the existing public `reassemble_scenario` directly from the unchanged parent. The **entire final source inventory and gravity membership** is qualified at once with the existing 3D field, certified invariant motion plane, source geometry, guard and numerical contracts. Adding a mirror pair atomically is allowed where adding only one destroys the actual physical reflection symmetry; there is no silent dropping of the transverse force.

A refused alternative is **`rejected-structural-model`** and retains its requested operation and reason, but no invented source inventory or solved trajectory. Another sibling can still be physically valid and independently integrate. A structurally qualified model can encounter a known numerical/domain failure (**`integration-failed`**) or terminate at the original source singularity guard (**`censored`**). Only a native result reaching the full authored duration is **`complete`**. The actual original `TestChargeMotionResult`, force and energy ledgers, available time samples and source IDs are not reinterpreted.

Structural families are fundamentally **different physical experiments**, not temporal evolution of a single apparatus. Source membership stays fixed during every individual numerical integration. The viewer does not tween a moving source or approximate conductor induction; a source is not a reacting conductor or movable charge unless a different qualified physical law explicitly supports it.

## Honest numerical comparisons across different source inventories

`StructuralFamilyRun.as_dict()` provides a detached finite `conductor_sim.structural_motion_family.v1` record with baseline source identity/revision, all true source-assembly parent/child records, add/remove/replace/gravity ledgers, all native accepted particle states, termination/refusal and **3D vector** position and velocity differences in SI.

For each accepted child, comparisons use **only literally identical original saved physical timestamps**, not matching list indices. A source-guard run can stop at a non-grid time; missing baseline or child states remain missing. No interpolation, continuation after guard or causal effect of sequentially changing sources during one run is inferred. The renderer's shared clock is the **union** of all actual saved model times, so longer valid histories remain visible after a shorter model is censored. Native potential energies may use different reference settings and source inventories: differences between absolute potentials in different scenarios must not be called work or induced energy.

For the analytic uniform-field example below, the engine retains full-world force. If a teacher adds `E_x=+100 V/m` to an already held `E_x=+100 V/m` field with q=1 nC and mass 10⁻⁵kg, the true x acceleration changes from .01 to .02m/s². At time t, the independently derived displacement difference is `Δx=(q/(2m))*100*t²`; no saved-time interpolation or new Newton-law implementation is required.

## Standalone offline visualization: what it is and is not

`render_structural_family` uses the original M28a qualified world-plane projection basis and the genuine solved Python samples. Lines depict **particle trajectories only**, while the table shows each actual case-specific complete source inventory, source type, gravity membership, structural operation and true native state/refusal. A shared discrete saved-time slider and play control select only real sample states. If a variant is guard-censored, its final observed path remains drawn but its current-position marker disappears when that time is unavailable. The chart explicitly says it is **not actual source apparatus geometry or ring rims**. Use retained M22a/M27b source viewers for the apparatus. Each HTML is standalone with escaped author text, no network, no browser ODE and no external untrusted JSON restore.

Author-provided baseline `origin` and `provenance` are displayed as **author assertions**, not independent scanned-PDF proof. New cases are always described as teacher hypotheses. The source workbook Q40–41's ring values and probe q=+10µC are source givens in original ring lessons, but the new M29a physical examples are independently authored uniform field, fixed point, finite transparent sphere, reflection pair and gravity variants **unrelated to that workbook**; their outputs must never claim the workbook's provenance.

## Four ready-to-run source membership lessons

```powershell
python examples/m29a_structural_family.py --case uniform-edits --output output/m29a-uniform.html
Start-Process .\output\m29a-uniform.html
python examples/m29a_structural_family.py --case point-replace --output output/m29a-replacement.html
python examples/m29a_structural_family.py --case mirror-pair --output output/m29a-mirror.html
python examples/m29a_structural_family.py --case guard-and-refusal --output output/m29a-guard.html
python -m pytest tests/test_m29a_structural_family.py -q
python -m tools.check_m29a_browser --output output/m29a-browser
```

`uniform-edits` adds a third fixed uniform field, removes one field, adds gravity, or replaces a field under a newly bound physical ID. All are genuine separately integrated models, and the x/y state histories are compared against independent constant-acceleration kinematics.

`point-replace` replaces a signed point charge with a named **uniformly charged *volume* sphere**, which has a different physical field for a probe inside its radius. This is an ideal transparent fixed distribution, **not** a metallic conducting sphere. A different case removes the original held point entirely.

`mirror-pair` adds two off-plane charges symmetrically as **one atomic qualified reassembly** and verifies the actual transverse force cancellation from direct Coulomb, while a single nonparallel added source is explicitly refused rather than projecting a false planar path.

`guard-and-refusal` compares a baseline ballistic experiment with a newly added attracting point that censors at a real source guard, a valid distant point that reaches full duration, and an inadmissible off-plane point that refuses whole-model qualification. Differences only exist where both actual numerical histories supply the same time.

## Physical and evidentiary limitations

M29a supports only the existing prescribed fixed-source test-charge model family with its certified planar motion and optional constant gravity. It does not combine FEMM conductor-equilibrium surfaces with prescribed E by naive superposition, change source positions *during* a run, infer arbitrary 3D particle motion, model collision/contact/absorption, or change numerical tolerance/plane on a structural operation. It does not import arbitrary JSON as trusted physics or claim a renderer projection proves a 3D apparatus geometry.

Release requires actual native source/trajectory/independent analytic references, unknown-ID/incompatible symmetry/guard/refusal negatives, 390px real Chromium plus complete Python 3.10/3.12, 97 actual FEMM5 and all historical visualization nonregressions. Because the cross-inventory comparison/evidence is new, require one exact-head independent **R2** adversarial review with unfamiliar physical assembly and source-bound geometry/provenance checks before an authorized production merge. Prior M28a/M28b physical/time/event evidence remains unchanged.
