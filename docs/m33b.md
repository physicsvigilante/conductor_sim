# M33b — Genuine new event inquiries on existing physical-world graphs

> **Historical milestone note:** this capability was released via PR #76.
> See [current capabilities and release evidence](current_capabilities.md); the original
> development-gate wording below is retained as implementation history, not current status.


**Development candidate, not independently reviewed/released.** Consult the
[frozen charter](m33b_charter.md) and the exact-source CI validation before
interpreting this capability as a reviewed release.

M33a lets a teacher compare already-observed physical alternative worlds, but
a different detector question still requires creating a new graph plan and
independently building and integrating those source worlds again. M33b
introduces a **native post-graph inquiry**: keep one trustworthy
`UnifiedObservationRun` containing physically qualified worlds, select
existing worlds by stable ID, and ask a completely new M24a
`PlaneEvent`/`VelocityReversal` question set. It is **not** a text-to-physics
interpreter, JSON importer, or saved-animation root detector.

```python
from conductor_sim import (
    GraphEventInquiryPlan, WorldComparison, run_graph_event_inquiry,
)
from conductor_sim.motion_events import PlaneEvent, EventPolicy

# graph is an existing, authentic run_unified_observation_graph result.
# It must have been authored with retain_source_ancestry=True.
inquiry = GraphEventInquiryPlan(
    graph, "teacher:new-detector",
    ("baseline", "alpha", "beta"),
    (PlaneEvent("plane:x-new", (.006, 0., 0.), (1., 0., 0.),
                "A NEW teacher-authored signed physical detector", direction=1),),
    EventPolicy(.003, 1e-8, 1e-8, 1e-6),
    comparisons=(WorldComparison("compare", "alpha", "beta"),),
)
result = run_graph_event_inquiry(inquiry)
record = result.as_dict()
assert record["schema"] == "conductor_sim.graph_event_inquiry.v1"
```

**Every admitted selected physical model receives a genuinely new M24a
`EventStudy` and `investigate_motion` numerical integration** with this
new event question tuple and policy. This does not reassemble sources,
revise physical initial conditions, reuse a previous event history with the
wrong detector, invent a root from ordinary trajectory samples or imply
that alternative held fields physically evolve into one another.

The immutable native result records the originating graph hash and plan ID,
actual model revision IDs, source identities/labels/kinds, M32b
branch-local source ancestry, previous graph-observation status (separate
from the new inquiry status), full new M24a event evidence and typed
refusals. A physical world that was admitted but had its *old* numerical
event study refused remains eligible for an independently qualified *new*
question. A physically refused world always has no new native event result.

Optional native `WorldComparison` pairs compare **right-minus-left**
independent new event runs. M28a shared-time trajectory differences use
*only literally equal saved SI timestamps*; M28b event shifts require
one located, same-direction root in **each complete-duration study**,
with numerical root bracket shifts rather than exact ODE error theorems.
Guard/terminal/unresolved/multiple and opposite-direction roots never
manufacture a valid whole-duration event shift. Per-event refusal can
coexist with legitimate shared-time comparison of observed trajectory
prefixes. A unique valid event pair can be meaningful even if saved time
grids do not otherwise align.

The detached, finite `conductor_sim.graph_event_inquiry.v1` and
`conductor_sim.graph_event_inquiry_plan.v1` schemas are new and opt-in;
**existing M32a v1, M32b v2 and M33a v3 public graph exports remain
byte-shape unchanged**. Ordinary dataclass/result mutations are rejected
by a runner-issued in-process SHA256 receipt plus native M24a validation
at construction and every export. This is not an independent
cryptographic signer or authentication of textbook source assertions.

## Run the real teacher example

```powershell
python -m examples.m33b_event_inquiry --output output/m33b-inquiry.json --source-graph-output output/m33b-source-graph.json
python -m pytest tests/test_m33b_graph_event_inquiry.py -q
```

The standard-library-only [separate-expression SI oracle](../tools/m33b_independent_inquiry.py)
**does not import `conductor_sim`**. It verifies four new actual M24a
native studies of the unchanged baseline, two structurally independent
sibling fields, and a physically revised cousin at all actual saved
x/y/z SI timestamps against Newtonian `qE/m` positions, velocities
and forces. It independently calculates the new signed detector roots
and all three right-minus-left cross-world vector/event differences,
checks the *full source graph JSON SHA256 against the inquiry's bound
source graph digest*, and runs six deliberate tampered-evidence controls.

```powershell
python tools/m33b_independent_inquiry.py --source-graph output/m33b-source-graph.json --inquiry output/m33b-inquiry.json --output output/m33b-independent.json
```

The retained [M33b source-head CI workflow](../.github/workflows/m33b-independent-inquiry.yml)
records the true commit/tree and SHA256-sealed native graph, new inquiry
and separately calculated reference, in addition to the regular Python
3.10/3.12, historical real-FEMM and real Chromium regressions. A
separate-context R2 reviewer must independently challenge unfamiliar
physics and hostile evidence/refusal before any owner-authorized merge.

**Out of scope:** new FEMM solvers, static conductor response,
nonqualified 3D, source motion, collisions, source interchange as a
time-evolving real system, new Coulomb/rod/ring laws, scene graph,
browser-side ODEs, new data import or arbitrary Python callbacks.
