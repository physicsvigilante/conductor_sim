## Goal and measurement

Does the existing `ElectrostaticProblem` + M13a `force_energy` + M13b
`PositionSweepSpec` + offline viewer let an assistant author **new** JEE
problems without modifying solver or renderer code? Can the assistant refuse
physically unsupported requests rather than draw a misleading substitute?

This is **one open, non-blind assistant-authored trial**, not an estimate of
LLM accuracy on arbitrary problems. The assistant had access to public API
documentation and to the prompt bank and authored the attempts in the same
workspace. The independent grading key is stored separately from the attempt
module. Publishing prompts, keys and attempts in one repository makes this a
*reproducible engineering evaluation*, not a hidden leaderboard or valid
statistical held-out score. Future blinded trials should use unseen material
and external, independently written grading keys.

## Explicitly separated evidence

* `m13c/questions.py`: 18 frozen natural-language prompts; **no** models,
  expected force values or grading keys.
* `m13c/attempts.py`: assistant's first completed submissions using **only**
  existing public model types and the M13b position-sweep interface.
  No import from `m13c.reference` and no editing `src/conductor_sim`.
* `m13c/reference.py`: independent physical-model fingerprints and SI
  image-charge force/energy oracle, not invoking any engine solution or
  the engine's force observation code. Single-plane formulas and grounded
  symmetric-plate midpoint energy are cross-checked against closed forms.
  Plate observations use an independently accumulated image series at order
  768 against the actual analytical backend at order 96, with explicit finite
  cutoff qualification. The acceptance tolerances are local to this trial.
* `m13c/evaluate.py`: validates complete authored geometry, charge inventory,
  constraint, selected component, path, number of states and backend; independently
  checks **each stored frame** for total force vector, path force, direct,
  induced, background and total mechanical interaction energies, and work
  from a fixed-voltage/gauge reference. Refusals must be case-specific and
  **must not contain a fabricated model or solver**.
* `tests/test_m13c_open_trial.py`: individual pass/refusal tests, strict
  wrong-model/wrong-backend rejection, closed-form oracle anchors, metadata,
  provenance, command-line grade, and offline supported/blocked rendering.

The 18 tasks cover ten candidate analytical sweeps (grounded-plane normal and
multi-source, translated/rotated plane, grounded and isolated sphere, external
multi-source sphere, grounded/biased parallel plates, oblique multi-source
slab) and eight genuine capability blockers (rotating dipole, charged ring,
insulating volume, time-changing electrode voltage with source work, wired
separated spheres, particle trajectory, non-axisymmetric FEMM force, cavity
force/energy). These are **not** eight solver defects: they are intentionally
out-of-scope requests for this engine's current domain.

## Repeat the independent trial

```bash
python -m m13c.evaluate list
python -m m13c.evaluate sources
python -m m13c.evaluate grade --output output/m13c-first-pass.json
python -m m13c.evaluate render plates-grounded --resolution 21 --output output/m13c-grounded.html
python -m m13c.evaluate render plates-oblique-mixed --resolution 19 --output output/m13c-oblique.html
python -m pytest tests/test_m13c_open_trial.py -q
```

The exported HTML shares the existing **position slider, force arrow,
force-versus-position and mechanical-energy-versus-position plots, work
summary and density controls**. It stores static equilibria, not motion or
elapsed time. In a geometrically oblique 3D case the 2D field-line tracing
may have **no valid in-plane traces** (and the density slider is disabled),
while force/energy samples and a projected force arrow remain available;
this is intentional rather than drawing inaccurate projected 3D field lines.
The script also produces adjacent raw JSON, including question metadata.

The optional `--submission other.trusted_module` loader **executes imported
Python** and is safe only for trusted local modules, not an online sandbox.
No arbitrary file, PDF or web text is executed.

## Provisional acceptance and limits

The first local run graded **18/18** (ten runnable models, eight correct
refusals). This score is **conditional and open-trial-specific**; it is not
from the requested new PDF and is not proof that any future LLM can generate
new problems. Source PDF integration is still pending.

Required CI gates for this scoped contribution are Python 3.10/3.12 ordinary
regressions, independent M13c CLI grading, source and Chromium explorer review,
and the unchanged pinned real-FEMM tests. Real-FEMM regressions demonstrate
that earlier numerical functionality continues to work; **M13c does not add
FEMM force accuracy or new FEMM-capable geometries**.

No force on charges in cavities, no arbitrary charge trajectories, no changing
voltage-source work model, no rigid-dipole torque, no charged ring solver and
no connected separated-sphere solver are claimed. A separate PDF-anchored
extension should follow after the missing document is actually available.
