### Exact PDF question checks

**p9, Multiple Q27.** The printed diagram specifies a +1 μC charge at A,
tangent segment AB=4 m, sphere radius BC=3 m, hence AC=5 m. Using the
neutral isolated-sphere Kelvin images, conductor potential is
`kq/AC = 1797.51 V` (≈1.8 kV); at tangent point B, the induced-charge-only
potential is `kq/5−kq/4 = −449.378 V` (≈−0.45 kV). Both match the
question's offered values. The exact static conductor geometry is modelled
using `SolidSphere(3,FixedNetCharge(0))` and `ExternalSphereBackend`.
A **separately labelled five-position radial sweep** is a pedagogical
extension and does not claim the PDF asks about charge movement. The
existing M13b force/energy viewer and independent external Kelvin references
check every stored state.

**p8, Multiple Q21.** A positive charge approaches a grounded conducting
sphere. The PDF's symbolic setup is instantiated with illustrative
`q=1 nC`, `R=0.1 m`, and seven radial states `r=0.32→0.18 m`;
these numerical values are **not from the page**. Independent ideal formulas
are `Q_ind=−qR/r`,
`F_r=−kq²Rr/(r²−R²)²` and
`U=−kq²R/[2(r²−R²)]`. Negative induced charge accumulates as
the positive charge approaches, implying electrons flow from ground into
the sphere and **conventional current from the sphere to ground**. No
time-dependent current magnitude or trajectory is simulated.

Each additional radial position is a **static equilibrium**, not elapsed
time. Force arrows show direction; the force graph, mechanical interaction
energy and work are real SI observations. The source, page, SHA and added
path caveat are embedded in the HTML and adjacent JSON. No new physics
solver, FEMM force fallback, or renderer was authored.

### Reuse and open (non-blind) authoring trial

The separate original `m13c/questions.py` bank freezes **18 new
JEE-style prompts** not transcribed from either PDF. `m13c/attempts.py`
is one assistant-authored attempt using the existing immutable problem
components and M13b `PositionSweepSpec`. The independent
`m13c/reference.py` and evaluator check geometry, constraints, authored
source identity, force components, direct/induced/background and total
interaction energies, and quasistatic displacement work. In the open first
trial, **10 analytical sweeps passed and 8 unsupported requests were
correctly refused (18/18)**. This is an **open engineering test**, not
measured generalization to hidden tasks.

The PDF SHA is validated before grading or exporting. Only trusted local
Python modules may be imported through the original open-trial module loader.
M13c preserves all existing electrostatics solvers and numerical acceptance
criteria. GitHub CI must pass Python 3.10/3.12, the Chromium interactive
viewer, and all pinned *real FEMM regressions with no skips*. FEMM validation
is a stability check, **not proof of numerical FEMM force accuracy**.

The next physics priorities suggested by the source are properly constrained
