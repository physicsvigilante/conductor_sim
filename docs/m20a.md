# M20a — Side-by-side comparison of verified prescribed-field scenarios

## Motivation

M19c/M19d demonstrated that an LLM can reuse one typed fixed-source model
for many teacher-generated hypothetical investigations. M19e preserved
**author-supplied physical source identities** and a correctly labelled
world-horizontal ring-axis schematic, but each HTML export still displayed
only one scenario. M20a adds a **small, offline comparison adapter** around
two ordinary M19e exports. There is **no scenario database, model-graph
compiler, new physical law, numerical integrator or duplicated viewer**.

The focus is physical exploration, **not textbook-answer completion**.

## API and example

```python
from conductor_sim import (integrate_test_charge, sample_test_charge_viewer,
    render_scenario_comparison, write_scenario_comparison)

# Model author builds two separately valid TestChargeMotionSpec objects;
# each retains the same declared physical source IDs and common frame times.
# An identical `extent_m` is needed for truthful side-by-side scale.
left_bundle = sample_test_charge_viewer(left_spec,
    result=integrate_test_charge(left_spec), axis_orientation='horizontal',
    source_annotations=(('ring:A', 'Ring A'), ('ring:B', 'Ring B'),
                        ('field:external', 'External field')),
    visual_frames=12, extent_m=2.25)
right_bundle = sample_test_charge_viewer(right_spec,
    result=integrate_test_charge(right_spec), axis_orientation='horizontal',
    source_annotations=(('ring:A', 'Ring A'), ('ring:B', 'Ring B'),
                        ('field:external', 'External field')),
    visual_frames=12, extent_m=2.25)
write_scenario_comparison(
    left_bundle, right_bundle, 'output/compare.html',
    baseline_id='ring-AB-baseline',variation_id='ring-AB-teacher-change',
    baseline_title='Reference scenario',
    variation_title='Teacher hypothetical',
    baseline_provenance='Teacher model: page 12 ring source, separately stipulated mass',
    variation_provenance='Teacher hypothetical: external field aligned with ring axis')
```

Other built-in comparisons are `ring-b-shift` (move only ring B) and
`gauge-shift` (add +17 V to the uniform field reference without changing E
or motion). Both scenarios are **explicit teacher hypotheticals**, not the
workbook's original unconstrained motion under a vertical electric field.
The source has a symbolic mass, while the demos stipulate `0.10 kg`. The
real workbook's original vertical field would force an off-axis movement,
which the axis-only ring law **cannot simulate freely**; the engine keeps
refusing it. This comparison never silently substitutes or drops that force.

## Reuse and truthful synchronization

`prepare_scenario_comparison` invokes the **same M19b/M19e strict saved
bundle validator separately for each scenario** (including every numerical
sample, source charge, E/V, `F=qE`, full `U=qV`, guard rules and the valid
source-axis domain). The comparison then checks:

1. Same physical SI/energy conventions, same signed ring/disc axis and
   **identical physical display slice** (world origin, axes, limits and
   grid resolution). Otherwise a trajectory change could be an artifact of
   different screen scales or incompatible coordinate projections.
2. Original saved numerical time arrays exactly equal, selected **real**
   frame indices exactly equal and **both complete their requested duration**.
   No time resampling, interpolated field frame, browser-side particle solve
   or silent comparison after a guarded endpoint is permitted. Mismatched
   grids, truncated histories and different frame counts are refused.
3. Every physical source has a **declared stable author ID and same kind** in
   both scenarios. Adding/removing sources or changing kind is outside this
   narrow property-revision interface. Author identity assertions are not
   cryptographically proven by these IDs. The adapter compares actual
   source values by stable ID, not array index, and explicitly identifies
   changed charge, dimensions, centre, field, potential reference, mass,
   initial position or velocity. Unchanged source values stay unchanged.
4. A real physical property or reference-potential change exists. Inputs
   and original single-viewer serialization remain unmodified.

The shared elapsed-time slider **only selects identical saved field frames**
in the two original embedded standalone viewers. Play/Pause/Restart and
0.5–4× speed use a parent-only presentation clock; the same saved time
controls both. The panels retain the original offline source geometry,
energy graphs, particle arrows, axial profiles, annotations and physically
certified projection. Under the shared clock, each shows actual world-space
position and velocity, kinetic energy and potential energy with correct
units. A comparison readout gives `|r_variation − r_baseline|` and
`|v_variation − v_baseline|` between **two separate states at the same t**;
this is not work or the trajectory of one particle moving between scenarios.
`qV` gauges can differ: absolute potential-energy differences across gauge
changes are **not automatically physical work**.

No addition to the existing `conductor_sim.visualization.v1` renderer or
M19a's numerical integrator was needed: both embedded viewers are the
identical accepted M19e renderer loaded with their own validated bundles.
Output HTML is standalone without a network, dependencies or additional
physics computation. The parent document contains only display-time
selection, simple arithmetic on saved values and a validated change table.

## Deliberately bounded comparison domain

- **Not** a general versioned scenario graph, persistent stable-ID registry,
  human-language parser, automatic sensitivity/inverse solution or cross-
  solver engine comparison.
- **Not** interpolation between physical frames or real-time recomputation.
  A matching frame index is never assumed to represent matching time without
  checking the original complete time and frame arrays.
- Only **two fully completed** prescribed-field histories with common
  time/display grids and matching declared source kinds/identities.
  A real source-guard stop is legitimate M19a partial coverage, but this
  particular synchronized comparison refuses mismatched/truncated histories
  instead of pretending both completed the same experiment.
- No claim of generated off-axis ring/disc fields, conductor induction,
  multi-particle motion, collisions or general 3D field maps.
- **No new independent solver verification** is implied by displaying two
  previously validated bundles side by side; the original M19a physics
  references and distinct independent reference checks remain necessary for
  any claim of motion accuracy. The validator checks source/row consistency,
  not the authenticity of an arbitrarily edited self-consistent trajectory.
