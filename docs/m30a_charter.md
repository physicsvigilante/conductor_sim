# M30a — Frozen preimplementation charter: parameter exploration inside newly assembled physical arrangements

**Commit this charter before M30a production code.** Scope is a prospective educational/composability extension; existing M22a/M28a/M29a/M29b physics and published evidence remain untouched. Standing owner policy: routine development without approval requests; merge only after a fresh independent PASS on the exact PR head plus green exact-head CI and postmerge verification.

## Motivation

M22a adds/removes/replaces real named fixed sources with full physical requalification, M29a freshly integrates these structural alternatives, and M28a independently sweeps a real property of **one fixed source inventory**. What is still missing is a bounded, reusable way to ask *follow-up parameter questions about a source that was only introduced or replaced in the altered arrangement*, while preserving the whole two-step physical lineage. This is a meaningful, generalizable form of LLM-directed model exploration; no problem-specific Coulomb solver or scene graph is required.

## Public scope

- A typed `StructuralParameterPlan` contains one unchanged `StructuralFamilyPlan` plus 1..3 explicit `BranchSweep` entries. A branch selects the literal `baseline` or the ID of one declared structural case and one existing M28a `SweepAxis`. No duplicate branch IDs, arbitrary lambda parameter transforms, JSON import or inferred Cartesian product. Total requested values across branches is at most 12; each remains within M28a's 1..6 bounds.
- The branch's `SweepAxis` applies to the **actually accepted** parent at that branch, not automatically to the untouched original. Newly added and newly substituted source identities are valid targets when they exist in the branch; retired IDs and absent gravity are not silently remapped. The M28a physical-property whitelist remains unchanged; gauges/reference-only edits and numerical conditions are excluded.
- Orchestrate *existing* `run_structural_family` once to get the immutable original and M22a-assembled whole physical alternatives and their genuine native trajectories. On each selected admitted branch, create the original M28a `TrajectorySweepPlan` based on that branch's accepted `PrescribedScenario`, and run **original `run_trajectory_sweep`** to revise each requested property by existing M20b `revise_scenario` and fully integrate it. Re-running the selected branch's baseline in M28a is bounded and deliberate; no cached frame substitutes for integration. Verify stable identities and original baseline nonmutation.
- Separation of statuses is mandatory: a structurally unqualified branch is **skipped-structural-model** (no fabricated model); an admitted branch with an inapplicable sweep axis (missing/retired source, same-value, wrong shape) is **rejected-sweep-axis** and retains its real structural source inventory; an admitted physical branch whose unmodified baseline trajectory failed is **unavailable-branch-trajectory**, not a physical refusal; an otherwise accepted sweep is **evaluated** with M28a's original per-value `complete`, `censored`, `rejected-physical-model` or `integration-failed` unchanged. Unexpected program errors propagate. No sibling is quietly dropped.
- The original/structural child/source property grandchild digests form a **two-edge provenance chain**: original M22a parent → independently qualified changed-inventory branch → M20b changed-property variation (no fake direct original-to-grandchild revision). Each original named source identity and authored label/type must agree with real model objects. Every grandchild preserves the exact branch source inventory, particle, numerical controls, gravity membership and declaration of physical plane, except the single explicitly targeted permitted property.
- Retain unchanged M28a and M29a exact saved-time 3D position/velocity differences **within the correct immediate parent comparison**, not cross-lattice work, fabricated sensitivity derivatives, interpolation or postguard continuation. Serializing detached `conductor_sim.structural_parameter_family.v1` data must include full real source lineage, requested axes/values, source inventory, each original M28a sweep result, separate branch-level refusals and honest authored provenance. Read-only data export, not a trusted model importer or proof of workbook authentication.
- M30a is **engine/JSON first**. No new scene graph, apparatus renderer, event locator, browser ODE, conductor induction, arbitrary free 3D, simultaneously moving sources, time-varying source membership, new force law, RK controller, numerical precision claim or automatic 2D parameter derivatives. M29b typed event observations remain separately available; nested structural→parameter→event queries may follow after this compositional layer is independently qualified.

## Frozen acceptance cards

- **P1 — Analytic new-source sweep:** From existing M29a `uniform-edits`, select added `field:Enew` (not in original), vary its complete `field_v_m` vector at two non-baseline values. Native x/y position and velocity in the newly assembled model and grandchildren must agree with independent quadratic constant-acceleration kinematics at every saved time. The baseline and assembled source IDs/names must remain unmodified; grandchild revision parents equal the accepted structural child SHA; M22a parent SHA equals original SHA.
- **P2 — Replacement and identity retirement:** Select original `replace-Ey` branch, sweep **new** `field:Ey-new` field vector. All accepted parameter grandchildren retain only the new identity in that inventory; no mutation or revival of the retired `field:Ey`; exact per-property M20b ledger.
- **P3 — Gravity membership then variation:** Select M29a `add-gravity` structural branch and sweep newly present `gravity.acceleration_m_s2`; compare to analytic (r(t)=r_0+v_0 t+\tfrac12(a_E+g)t^2) with separately correct electric and gravitational force terms.
- **P4 — Honest cross-stage refusals:** One M29a off-plane unpaired source branch is refused at structural stage (no invented accepted inventory); a separate physically accepted branch attempting to sweep an absent/retired ID is **rejected-sweep-axis**, preserving its real branch and source ledger. A valid sibling continues to execute.
- **P5 — Guard and invalid physical values:** An accepted branch's numerical source guard censors at its actual end; an inadmissible parameter grandchild (e.g. off-plane field) retains M28a original `rejected-physical-model` with no trajectory while an independent valid sibling completes. No cross-censored-time projection.
- **P6 — Unknown composition transfer:** Independently authored tilted rod/held point/gravity configuration with a newly added charge source, then sweep only that added source charge. Challenge a genuine new trajectory/force against independent quadrature+DOP853 or closed-form/analytic direct Coulomb reference; source identity and parent/child/grandchild SHA must match the actual physical models.
- **N1 — Plan boundaries:** Reject unknown branch ID, duplicate selected branches, non-tuple typed plan, empty/overlarge branch count or >12 values and malformed/nonphysical M28a axis; do not silently coerce booleans/nonfinite values, source indices, or a gauge into physical parameters.
- **N2 — Provenance and unsupported claims:** Null structural inventory on structural refusal; real inventory on sweep-axis refusal; versioned identity chain on accepted cases. No event-time conclusion, conductor response, source dynamics, property changes during a numerical run, or unqualified 3D projection.
- **N3 — Regression:** Unchanged original M22a/M29a/M28a/M29b trajectory/structural/event contracts and all historical Python, offline browser, and 97 real FEMM5 nonregression checks.
