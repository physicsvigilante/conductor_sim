# M31a — Atomic coupled physical hypotheses on separately qualified source arrangements

[Preimplementation charter](m31a_charter.md) was committed **before new M31a production code**. M31a extends the physically composable JEE teaching engine without introducing another electrostatic field law, RK controller or scene graph.

M20b could already atomically revise multiple physical component properties, but the recent reusable M28a/M30a authoring plans explored only **one physical property at a time**. M31a now exposes a bounded way to describe a small set of **named, jointly edited hypotheses** on the original physical source model or any genuinely reassembled M22a source-inventory child. This matters when two physical changes must occur together to preserve physical symmetry, rather than refusing a valid whole system because a sequential intermediate arrangement would be inadmissible.

## Native public API and physical sequence

Use CoupledPropertyEdit to name one real stable source/particle/gravity/medium identity, existing M28a physical-property name and one complete SI scalar or 3-vector. A CoupledHypothesis binds 2..4 distinct targets to one named source world: literal baseline or a declared original M29a StructuralCase. A CoupledPhysicalPlan contains 1..5 such hypotheses, at most 16 requested edits total, and one original immutable StructuralFamilyPlan.

~~~python
from conductor_sim import (
    CoupledPropertyEdit, CoupledHypothesis, CoupledPhysicalPlan,
    run_coupled_physical_family,
)
from examples.m29a_structural_family import model

family = model("uniform-edits")
plan = CoupledPhysicalPlan("teacher:coupled", family, (
    CoupledHypothesis("new-source-plus-mass", "add-E",
        "Change the newly introduced source and actual probe mass together.",
        (
            CoupledPropertyEdit("field:Enew", "field_v_m", (150.,0.,0.)),
            CoupledPropertyEdit("test-particle", "mass_kg", 2e-5),
        )),
))
result = run_coupled_physical_family(plan)
native_json = result.as_dict()  # Detached evidence, not a trusted model importer
~~~

The runner reuses M29a run_structural_family to assemble and integrate each accepted source world from the unchanged original. For each requested coupled hypothesis, it resolves physical target identity and numeric dimensional shape against **the actual selected structural parent** using M28a's existing allowlist. A source added/replaced under a new ID or gravity added only on that branch may be modified; retired or absent source IDs are rejected.

All requested property edits are then applied in **one** call to the unchanged M20b revise_scenario and full-world qualification logic. Only after that whole model is admitted does the unchanged native integrate_test_charge solve genuine particle motion. No sequential intermediate models are physically inferred or silently solved; the new model's immediate parent_revision_id is the actual source-assembly revision, not the source-original model's SHA.

## Key physical example — joint admissibility

Start with the M29a point-replace original: a stationary held point at (0.2,0,0) m, a +q probe at (0,0.1,0) m and velocity lying in the certified xy plane.

A teacher asks to shift the **held point and the genuine probe initial position together** by +0.05m in world z, leaving all relative positions, initial velocity and physical plane normal unchanged.

Neither *individual* shift would qualify under the retained symmetry-plane contract: with the other charge not shifted, the held point would be off the moving probe's physical plane. But the **atomic double shift is an admissible new physical model**, and its independently integrated motion and SI forces match the original after translating every position by +0.05m. This is a reusable whole-system constraint, not a manually authored fake corrective force or numerical projection.

Other examples couple a newly added uniform electric source and probe mass/launch, a true replacing source and probe velocity, or newly added uniform gravity and an existing held electric field.

## Native status/evidence distinctions

- skipped-structural-model: the original M22a reassembly refused; no invented accepted inventory or property revision.
- unavailable-branch-trajectory: the structural model exists but did not supply its normal M29a parent trajectory. Preserve the real parent inventory and do not pretend an original physical calculation completed.
- rejected-coupled-edit: the selected source world exists, but a target is absent/retired, has a gauge-only or disallowed physical property, wrong scalar/vector type, or an edit repeats its parent's unchanged value.
- rejected-physical-model: all requested edits are individually valid physical target/value shapes, but **the fully jointly revised physical model** is not admitted by the original full-system M20b constructor, e.g. an uncompensated out-of-plane source field.
- integration-failed: the complete revision exists, but an original numerical or physical-domain integration error prevents a trustworthy trajectory.
- complete or censored: the unchanged native integrator reached the requested physical duration or stopped at an existing source singularity/field guard. Censoring never proves what happens later or authorizes extrapolation/contact behavior.

The detached finite conductor_sim.coupled_physical_family.v1 JSON records the original full M29a structural-native family, source ID/authored label/built-in kind for every accepted model, original M22a parent→structural SHA/ledger, immediate M20b structural→coupled grandchild revision SHA, original full numerical samples and genuine 3D position/velocity differences matched at **literally identical saved physical SI timestamps** to each hypothesis's immediate parent. There is no sample-index comparison, work derived from energy differences between different source inventories, numerical derivative/sensitivity theorem or source motion during a trajectory. Source-given labels are author assertions, not independently authenticated PDF contents.

## Numerical result and comparison integrity

The public coupled result accepts only exact native TestChargeMotionResult objects.
Only the supported duration and source-guard terminations are admitted;
an unknown termination cannot be misreported as a censored physical event.
Result comparison rows must reproduce the existing M28a native
literal-time comparison of the actual immediate parent and revised child,
with exact built-in value types and floating-point representations (including
signed zero). Python's cross-type equality, such as `False == 0.0`, or a
custom equality-overriding numeric or dictionary subclass must not authenticate
typed physical timestamps. Mutable comparison dictionaries are rechecked
at detached JSON export. This does not change M28a's physical clock or
numerical interpolation policy.
This protects the declared typed-result evidence contract, not arbitrary
malicious mutation of every Python object or exact-ODE error bounds.
