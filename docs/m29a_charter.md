## Architectural gap and exact scope

The original [composability contract](composability_contract.md) asks for more than changing a source charge: teachers should be able to **add/remove/replace** genuine physical components and compare newly solved models. M22a already exposes atomic immutable `reassemble_scenario` and typed `NamedSource`, `SourceReplacement` with identity/whole-model qualification. M28a and M28b compare same-membership **parameter** revisions. No currently accepted public interface runs an independently versioned family of **different source memberships** and reports censored/complete numerical trajectory differences together with the structural change ledger. M29a fills that orchestration and evidence gap, **not** a missing physical law.

## Public functionality

- One unchanged baseline `PrescribedScenario` and **1..5 explicit, independently named structural alternatives**. Each describes a bounded M22a atomic structural operation with `add_sources`, `remove_sources`, `replace_sources`, and optionally adding/removing **uniform gravity membership**. Each child is built **directly from the original parent**, never from a previous sibling. A case cannot edit source dataclass physical properties in place under a retained identity; that's M20b/M28a. New/replacement sources have explicit qualified built-in types, source IDs and labels. Replaced sources need a new physical identity. Case scenario IDs are stable; child provenance is a teacher hypothesis, never silently a source-given assertion.
- Exactly the existing `reassemble_scenario` constructs and fully validates each final `TestChargeMotionSpec`. No source-by-source intermediate solve, projection away of transverse force, relaxed geometry plane, invented conductor response or hidden changed duration/sample interval/numerical tolerance/source guard. A malformed/physically inadmissible case is a recorded **refused structural variant**, not a deleted variation; correctly authored siblings still integrate.
- Independently integrate the baseline and each admissible structural child through unchanged public `integrate_test_charge` (fixed-source electric fields, uniform gravity, conservative work/energy, adaptive physical time, original source guard). The baseline model and source ID binding are never mutated. A qualified child can still terminate at the source guard; keep actual time/state and **censored** status rather than fabricate an impact, postguard path or requested duration completion.
- A detached finite/versioned JSON audit stores baseline revision ID/source inventory, each structural `ScenarioReassembly.as_dict()` (parent+child exact record hashes and changes), original native solver samples/status, physical source inventories for each variant, typed refusal reason, and comparisons `delta_position_m`/`delta_velocity_m_s` **only at literally matching actual saved physical timestamps** using M28a's existing difference helper. Do **not** compute cross-scenario potential-energy difference as source work, because source inventories/physical potential reference differ.
- The tiny offline HTML comparison shows **true particle trajectories projected onto the same certified physical world plane**, a shared slider selecting the **union of original native saved timestamps** and an explicit per-scenario source inventory/change description. This is trajectory space, NOT a visualization of actual ring rims, apparatus geometry, conductor or source-contact physics. For each case the available entire native solved particle path stops at actual termination; its marker/readout vanish if it lacks that exact saved time. No browser-time field/ODE calculation, guessed interpolation or implicit animation of structural source changes during one run.
- All displayed provenance originates in actual authored `PrescribedScenario`/structural ledger and is labeled **author assertion**. An unrelated point/rod/gravity case cannot be labeled as the workbook's ring problem. Browser HTML must escape hostile source labels. A common 2D overlay must refuse separate physically distinct planes (as M28a already does); M22a retains the unchanged original particle/plane, so this should be structural invariant. It must never imply native 3D source geometry from projected trajectories.

## Frozen positive acceptance cases

P1. **Uniform E addition with analytic reference:** baseline a genuinely moving q=+1nC, m=1e-5kg test particle at origin with a named `field:E0` of E=(100,0,0) V/m, v=(.1,0,0), duration=.1s; add a distinct `field:E1` of E=(100,0,0). Compare actual x/vx at each native time against independent `x=.1t+(q*(100 or 200)/m)t²/2`, `vx=.1+(q*(100 or 200)/m)t`, and `Δx=0.5*q*100*t²/m` without changing original source.
P2. **Source deletion, identity and gravity presence:** From the same or separate original valid model with two independent named E sources, remove one; separately add `UniformGravity((0,-2,0))` in the certified plane; verify intact retained source IDs, field inventory, teacher-only provenance, actual changed forces/trajectories, and new gravity as a separate component, not an equivalent fictional electric source.
P3. **Replacement under fresh identity:** Replace a held fixed point source with an explicitly named *volume-charge sphere* in its original inventory slot; verify old identity is retired (not redefined), new identity binds exact new source type, historical source ledger includes before/after objects, and resulting genuine trajectory/energy differs in the supported regular regime. The volume sphere is **not** a conducting metal sphere.
P4. **Atomically added mirror pair transfer:** A baseline with one in-plane point plus teacher-chosen launch can add **two off-plane mirror point sources in one reassembly** and run an actual qualified trajectory. Adding only one mirror source should be refused under existing whole-source reflection/plane qualification. Independent direct Coulomb acceleration (and optional SciPy DOP853/Verlet) checks physical net force, world motion-plane and energy. A separate rotated point+rod with gravity may serve as unfamiliar valid transfer.
P5. **Source guard and partial success:** An added attracted held point results in an early source guard for one alternative, while another valid alternative integrates to duration, and one inadmissible off-plane arrangement is explicitly refused. Retain actual guard terminal time, original full 3D evidence and exact shared-time comparisons only; no phantom states after guard and no comparison across unsupported times.
P6. **Browser truthful source membership:** Wide and 390px real Chromium compare baseline, source-added, source-deleted or replacement cases with actual differing source IDs/labels and model-change ledgers, saved-time controls and original native positions. No model membership changes over one run; all comparisons depict separate possible experiments.

## Frozen negative acceptance cases

N1. Duplicate case IDs or >5 variants, malformed case/no actual operation, unsupported arbitrary source/callback, oversized/missing stable IDs, duplicate new ID, unknown removal/replacement ID, replacement with same ID, source retirement/reuse within a single retained structural ancestry: refuse the relevant plan or individual case **before** doing impossible numerical work, without touching parent or working siblings.
N2. Off-plane uncompensated field or tilted full-ring axis violates complete-model motion-plane qualification: recorded refusal, not projected 2D force. A two-source mirror pair must be added simultaneously (not temporary unqualified half-assembly).
N3. A parameter-only change to an existing retained source under a structural operation is forbidden by M22a (use M20b). Changing launch mass/velocity, duration, sampling, solver guard/threshold or plane under M29a is forbidden. A source `gravity` ID cannot impersonate uniform gravity.
N4. A valid baseline doesn't guarantee revised model qualification, numerical convergence, absence of source guard, or a completed trajectory. Refusal and censoring are distinct, explicit outcomes. No comparison values at unshared floating times or after either run's last genuine native time.
N5. Invalid/trusted JSON input must not silently become a native `StructuralFamilyRun`; out-of-range/nonfinite exported time or source fields fail closed. HTML source labels cannot inject script or claim PDF transcription.
N6. Existing M22a reassembly, M20b physical-property revision, M28a numeric property sweeps, M28b event roots/time brackets, M27b real ring trajectories, other historical browser reports, and **97 actual FEMM conductor tests** retain their accepted behavior.
