## Original JEE workbook p8 Q21: the missing distinction

The original-labelled viewer includes **one fixed, separately attributed teacher numerical illustration**; changing q, R, d0, v, or duration requires an explicitly labelled **TEACHER HYPOTHETICAL** view, so no stale default numerical caption can be attached to a changed physical model. This does not limit the composable prescribed-speed engine itself.

The original `02_conductors_half_size.pdf` physical p8 **Multiple Correct Q21** shows an **external positive charge** q approaching a **grounded solid metallic sphere** radius R at **small externally prescribed constant speed v**. Its physical p17 answer key says **options (1),(3)**. The workbook is **not asserted to be an official historical JEE paper**. All illustrative numbers used here are teacher chosen: q = +1 nC, R = 0.10 m, initial separation d0 = .30 m, v = .04 m/s inward, elapsed duration 3.0 s. None are source-given numbers.

An M16a freely moving particle would *accelerate* under the sphere's induced force, unlike the question's **constant speed maintained by an external agent**. No phantom Newtonian motion, no user-supplied wire R/L or transient FEMM/Maxwell time solve is created.

With the physically printed **q>0**, **v>0 inward**, and d(t) = d0 - vt:
\[
Q_{\mathrm{sphere}}(t)=-\frac{qR}{d_0-vt},\quad
I_{\mathrm{sphere\to ground}}(t)=\frac{qRv}{(d_0-vt)^2}>0,\quad
\frac{dI}{dt}=\frac{2qRv^2}{(d_0-vt)^3}>0.
\]
This is the conventional current direction **sphere→ground**; electrons move oppositely. The magnitude grows as the charge approaches. Current is NOT the time derivative of induced mechanical energy, nor wire Joule heat.

## Reusable authoring

For untrusted **raw** LLM/teacher dimensions, first use the new public `author_prescribed_grounded_sphere(source_charge_c, source_position_m, sphere_radius_m, sphere_center_m=..., permittivity_f_per_m=...)`. It rejects Boolean/nonfinite coordinate and SI scalar values **before** the historical model constructors can coerce them. Existing `PointCharge`/`SolidSphere` constructors convert raw coordinate Booleans to floating-point numbers for backward compatibility; once an `ElectrostaticProblem` is already built the original raw type cannot be recovered. This legacy normalization is **not** a provenance attestation. The authentic source example uses the strict factory.

Use public `PrescribedSphereRadialSpec(problem, radial_speed_m_s, duration_s, sample_count, surface_guard_m)`, where `radial_speed_m_s<0` means inward and `>0` outward, independent of world axes. Accept one external nonzero signed `PointCharge` and one real `Grounded SolidSphere` with a positive homogeneous permittivity; exact original source inventory remains immutable. Refuse unsupported shell/isolated/multiple conductors or sources, touching metal or guard, zero speed, speeds at/above 0.1c, false Boolean SI parameters or overlarge sample counts.

`sample_prescribed_sphere_radial(spec)` builds immutable world states at the specified physical *prescribed* elapsed times and invokes the M37a native `observe_grounded_sphere_wire` at each genuine new source position. M37a, in turn, obtains its induced net Q, force and physical energy from the already qualified Kelvin backend. No new Coulomb law or integrator is coded in this production module. A changed charge sign, radius, initial position, centre, permittivity or signed velocity generates a genuine new physical series, not data interpolation.

Example:

```python
from conductor_sim import (
    ElectrostaticProblem, Grounded, PointCharge, SolidSphere,
    PrescribedSphereRadialSpec, sample_prescribed_sphere_radial,
)

problem = ElectrostaticProblem(
    (PointCharge(1e-9, (0,0,.30)),),
    (SolidSphere(.10, Grounded(), name="Sphere A"),),
)
trace = sample_prescribed_sphere_radial(
    PrescribedSphereRadialSpec(
        problem, radial_speed_m_s=-.04,
        duration_s=3., sample_count=31, surface_guard_m=1e-4
    )
)
for row in trace.samples:
    print(row.time_s,row.radial_distance_m,
          row.wire_current_sphere_to_ground_a)
```

The output `trace.as_dict()` explicitly declares `conductor_sim.prescribed_ground_wire.v1`, original physical inputs, complete SI units, a signed constant-speed protocol, actual prescribed timestamps, native sphere net Q, both terminal current directions, genuine static induced force and interaction energy. An internally consistent JSON trace does not by itself cryptographically authenticate its origin; qualified execution is through the Python model.

## An offline, deliberately limited visual explorer

`render_prescribed_ground_wire(trace, source=...)` outputs one self-contained HTML/SVG page with a source-given-versus-teacher attribution banner; an honestly scaled, *fixed radial schematic* of the grounded solid sphere and the point charge; a signed conventional-current-versus-*prescribed physical time* graph; and synchronized stored numeric readouts. Only real computed snapshots are consumed by JavaScript, which never calculates current, force, induced charge or a trajectory. Frame switching and play-speed compression are presentation only. The scene is a fixed *radial schematic*, not an arbitrary-world 3D projection or electric-field-line map.

Without JavaScript, the true initial-state sphere, charge, source identity, entire static graph and initial SI values remain visible; interactive controls are disabled. The browser shows no misleading new state. All frame reads and chart/scene markers are checked against the actual independently validated embedded JSON in real offline Chromium. Mobile and no-JS screenshots are saved. No external request is required.
