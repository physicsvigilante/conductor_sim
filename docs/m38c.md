## Root cause and correction

The M38b student page plays **already computed and verified** Kelvin physical-time frames, switching snapshots at a presentation interval of 100 ms. Its old acceptance checker waited for a real index greater than 0, read that moving index in one Playwright RPC and then checked the clock, signed current, scene and marker in many further RPCs while the browser's timer continued advancing. The marker could truthfully correspond to a later saved physical time than the prior index. The old check was therefore a *time-of-check/time-of-use browser test race*, not evidence of inaccurate charge or current calculations.

The corrected `tools/check_m38b_line_browser.py` leaves the actual production viewer **unchanged**. It first witnesses a genuine Play transition from `t=0` to a saved index >0. It then runs one atomic in-page callback that reads the current index, **captures every displayed live Play-frame SI label and scene/current marker BEFORE any redraw**, and dispatches the already existing physical-time slider's normal `input` action **without changing its index**. That original handler stops the presentation timer and draws the same complete saved state. The captured *unmodified running frame* is independently checked against the genuine previously validated Kelvin record, so a broken Play-only renderer cannot be concealed by the pause redraw. Only after confirming the actual frame is frozen does the checker inspect the SI readouts, coordinates, chart markers and labels again via Playwright; it checks the same frame after **more than one old 100 ms timer tick**. Three genuine Play / freeze / verify / Restart cycles run before the unchanged mobile/no-JavaScript/browser integrity gates. The independent native Kelvin physical observations and strict tolerance are untouched.

The focused Python regression also injects deliberately stale **live pre-pause** current markers/labels and a changed paused index into the checker boundary; each must be rejected for the intended physics/timing reason. Real Playwright Chromium remains the execution gate for genuine browser timing.

The acceptance report now includes `real_playback_witness_indices` (three observed, nonzero actual saved-state indices) and `playback_freeze_verified_after_100ms_tick`. This verifies actual elapsed-state playback then stable cross-element inspection, rather than bypassing Play entirely or asserting a fabricated snapshot.
