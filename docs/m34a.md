# M34a — Stable oblique physical motion planes across source revisions

**Development candidate; not a released feature until independent R2 review, current-source full CI, owner approval and postmerge main checks.** Frozen preimplementation [charter](m34a_charter.md), inherited independently reproduced [issue #77](https://github.com/physicsvigilante/conductor_sim/issues/77).

## Why this is physical composability work, not a new solver

A genuinely qualified oblique source model may use an authored physical motion plane normal such as (1,2,-1). The native M19/M27 scenario constructor normalizes this once to approximately (0.4082482904638631,0.8164965809277261,-0.4082482904638631). In binary64, math.hypot of these values is 1.0000000000000002. A later M22a structural revision or M20b physical revision calls the original full-model constructor. Repeating unit-length division changes the original normal's final bits despite no teacher-authorized analysis-plane change. M22a then rejects a valid real source change because its exact invariant checker sees a changed analysis field.

M34a changes only the motion-plane-normal normalization decision in TestChargeMotionSpec. A finite nonzero vector whose actual math.hypot length differs from 1 by **at most math.ulp(1.0)** is retained verbatim as a sufficiently unit-length already-qualified representation; other vectors are normalized by the original existing _unit function. The full original physical initial-condition, plane/axis, field-symmetry, gravity, source singularity and force qualification is still applied to every new system.

This is a machine-precision representation allowance, **not** approximate teacher permission to change a physical plane or a new generalized 3D solver. Existing event detector normals, source axis normals, Coulomb laws and FEMM equilibrium are not modified. No blanket tolerance was added to M22a unchanged-analysis or source-identity checks. True out-of-plane fields, velocities and gravity remain refusals.

### Explicit limitations

A physical plane is still a qualified plane, not arbitrary unrestricted 3D; numerical event brackets locate roots of actual integrated trajectories, not rigorous exact ODE error intervals. No moving held sources, conductor induction/response, collision/contact, new FEMM solver, viewer, PDF source authentication, arbitrary code callbacks or browser-time ODE are introduced. The native in-process evidence receipt is not an external cryptographic signature.
