# M28b — Frozen preimplementation contract: typed event observations across physical sweeps

**Owner direction:** continue building autonomously through bounded and fully verified milestones; seek independent review where required, not routine approval after review gates. This charter is committed **before any M28b production code**, on a separate branch. It does not replace independent physics/evidence review.

## Educational objective

A teacher varies one genuine physical parameter of an immutable qualified M28a `PrescribedScenario` apparatus and asks the **same** typed M24a physical question in every independently reassembled and integrated variant: When does the test charge cross a detector plane? When does a signed velocity reverse? Does an earlier guard or terminal observation censor that question? The engine should provide finite-resolution numerical answers and refusals with honest identity/time/source provenance. No source reauthoring, ad-hoc equation or new RK/event root finder should be required for each variation.

## Architecture and semantic boundaries

- The M28b public `EventSweepPlan` wraps **one existing M28a `TrajectorySweepPlan`**, an unchanged tuple of 1..16 typed M24a `PlaneEvent`/`VelocityReversal` questions, and one ordinary `EventPolicy` numeric study policy. No callbacks, strings-as-events, arbitrary event types, numerical-policy sweep axes or browser event detection.
- Execute the baseline and each 1..6 **independent** physical revision via unchanged M20b `revise_scenario`/M28a `_revision`, M24a `EventStudy` and `investigate_motion` (which reuses the existing physical full 3D force, fixed ring fields, 2D plane certificate, adaptive vector RK, guards, interpolation-free event refinements). M28a's ordinary `run_trajectory_sweep` stays unchanged.
- Preserve baseline model identity, source IDs and ancestral `revision_id`. A variant can be *physically inadmissible*, individually *event-study inadmissible*, *numerically integration-failed*, *completed* or *censored* by a source guard/terminal event/unresolved event. Keep each distinct and retain exact engine status, not falsely name every terminal event a collision. Unexpected implementation exceptions propagate.
- Compute trajectory comparisons **only at identical saved actual floating-point physical timestamps** via existing M28a native comparison helper. When M24a injects an event-specific non-grid sample/terminal time, no unsolved baseline or variation point is fabricated for alignment.
- Preserve **every event root**, signed direction, original physical event ID, residual/unit, time-bracket, original force/energy sample and unresolved candidates. The event-study's `outcomes` remain the authoritative classification: `located`, `located-with-unresolved-candidates`, `unresolved`, `not-found-at-requested-resolution`, `search-truncated`. No unlocated event may be called absent.
- A cross-scenario **event time shift** is admitted **only** when the same event ID has exactly one resolved (no unresolved candidates) numerical root in the baseline and exactly one in the variant. Rather than claiming exact physical event times, provide the two original brackets and their conservative numerical **difference interval** [variant.lo−base.hi, variant.hi−base.lo]. Distinguish root-localization bracket uncertainty from ODE global integration error. Multiple roots or censored/unresolved questions never use a fake first-event pairing.
- Return a bounded, typed, finite, detached, versioned JSON audit with baseline scenario revision, child lineage, actual sampled event histories, every case's complete or censored termination, per-event outcome and the eligible shift interval. Never claim SHA digest authenticates a scanned PDF.
- A compact standalone **offline event-summary HTML** may display source-bound baseline/teacher provenance, per-case outcome/termination, every numeric root bracket, and an SVG source-agnostic event timeline. It does **not** draw the charged-ring apparatus or solve events in the browser. No hard-coded workbook assertions in generic renderer; use the existing M27b viewer for authentic ring source geometry. HTML must escape hostile source labels and require native `EventSweepRun` (not arbitrary external JSON). Real Chromium 390px width, no page/network/console errors.
- Workbook p12 Q40–41's source-given Ring A/B parameters, field and probe q=+10 µC remain authored context; altered numeric mass/launch/duration, event detector, parameter variations and event policy are **teacher hypotheticals**. M28b is not the original symbolic-mass/rest/axial Q41 solution.

## Frozen negative cases

N1. Unsupported source/gauge-axis (from M28a), numerical-policy parameter revisions, duplicate values, wrong shape, invalid model, one-axis size limits: reject at ordinary M28a plan boundary unchanged.
N2. Duplicate event IDs, arbitrary callbacks, event-axis normal to motion plane for velocity reversal, excessively small time resolution, or invalid baseline ideal-stop conditions: reject **before** integrating baseline; avoid mixed/partially initialized plans.
N3. For a single revised variant, invalid *event-study* stop-side or physical plane/geometry refusal must be distinct, leave other children and baseline unchanged.
N4. Multiple crossings of one detector or unresolved candidate => explicitly *unpaired* event shift, even when the first root looks intuitive. An event root bracket is not a rigorous enclosure of the exact ODE's true root.
N5. Censored guard or terminal event does not imply a detector was never encountered later. Query outcome `search-truncated` stays distinct from `not-found-at-requested-resolution`.
N6. No post-guard/frame interpolation, comparing samples by index, false source provenance, dropping author IDs, forged HTML script injection, hidden 390px overflow or copied browser numerical integration.
N7. Original M28a trajectory sweep, M24a event studies, M27b real ring motion, M20b gauge revision and 97 real FEMM conductor regressions remain unchanged.
