## Three independent layers of evidence

**1. Native execution:** `python -m tools.m36b_jee_replay --output-dir output/m36b` uses public physics/observer APIs to produce seven genuine source results, native event times/samples, source-work and electrostatic-equilibrium observations, actual sampled contours and seven offline rendered viewers. It also emits an explicit unsupported local-3D refusal. No result counts as verified because the runner says so.

**2. Physically separate reference:** `python -m tools.m36b_jee_reference --input output/m36b/native-replays.json --output output/m36b/independent-reference.json` imports **no production physics**. Its independently coded constant-acceleration, Coulomb potential, dipole energy, Gauss/local-field-qualification, static self-capacitance and conserved charge formulas are evaluated against the actual saved native observations and field vectors. Test cases tamper with native outputs, mislabel static scenes as motion or turn the 3D refusal into a fake simulation.

**3. Genuine browser inspection:** `python -m tools.check_m36b_jee_browser --output-dir output/m36b` opens all seven generated HTML documents in real Playwright Chromium offline, checks visible source-appropriate physical labels and graphics, prevents HTTP requests, saves screenshot evidence. This is a presentation check only, not a physics engine validation.

Dedicated [CI workflow](../.github/workflows/m36b-jee-source-replays.yml) executes all three independently on the exact development source and uploads source/manifest/reference/browser/screenshots/test outputs even on failure. Ordinary Python, real FEMM and inherited Chromium jobs remain required; no coverage is dropped.
