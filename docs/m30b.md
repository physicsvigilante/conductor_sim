# M30b — Genuine typed physical events on two-stage source/property models

The [frozen preimplementation charter](m30b_charter.md) was committed before production. M30b is a bounded scientific **engine/JSON** capability that completes an important teacher exploration sequence:

Original immutable fixed-source model → genuine independently qualified source-membership change → independent physical parameter changes targeting a newly added/replaced source → exactly the SAME typed passive detector or reversal question across these models.

No physical source changes during a trajectory. Each model is a separate teacher-authored hypothesis. There is no new Coulomb, rod, gravity, RK, source guard, event bracket refiner, browser ODE, conductor response, collision law or arbitrary 3D simulation. Only physically qualified existing M22a/M29a/M30a models are considered.

## Reusable native API

NestedEventPlan contains one native M30a StructuralParameterPlan plus immutable native M24a questions and EventPolicy. run_nested_event_family first runs the unchanged M30a whole-source/parameter model validation and independently solved native physical trajectories; then it runs a **separate original M24a EventStudy and investigate_motion** for the actual original physical model, each qualified selected structural parent, and every admitted physical parameter grandchild.

The ordinary M30a no-event trajectory cannot substitute for an event-specific integration. A true numerical event root comes from M24a, never from linear interpolation between plotted or saved frames. Every accepted event runner is checked against the *exact* PrescribedScenario object from the real source hierarchy. The literal baseline branch reuses the one original event run and does not pretend that a model was structurally changed into itself.

~~~python
from conductor_sim import (
    BranchSweep, NestedEventPlan, StructuralParameterPlan, SweepAxis,
    run_nested_event_family,
)
from conductor_sim.motion_events import PlaneEvent, EventPolicy
from examples.m29a_structural_family import model

physical = StructuralParameterPlan(
    "teacher:changed-fields", model("uniform-edits"), (
        BranchSweep("add-E", SweepAxis(
            "field:Enew", "field_v_m",
            ((50.,0.,0.),(160.,0.,0.)))),
    ),
)
question = (PlaneEvent(
    "x:detector",(.006,0.,0.),(1.,0.,0.),
    "Real positive-x passive detector",direction=1),)
run = run_nested_event_family(NestedEventPlan(
    physical,question,EventPolicy(.003,1e-8,1e-8,1e-6)))
evidence = run.as_dict()  # Detached JSON; never a trusted physics importer
~~~

The named field:Enew source is **not in the original physical inventory**; it exists only after the independently qualified structural add-E operation. Each grandchild's charge, field or gravity property changes under an M20b revision whose immediate parent SHA is the newly assembled structural scenario, not the original. Real source IDs, authored labels, type, original/structural/parameter SHA, structural and parameter refusal reasons, and native samples stay bound in the complete M30a record embedded in M30b output.

## Scientific statuses and no false event claims

- **skipped-structural-model**: the M22a structural arrangement is inadmissible; there is no accepted source inventory or fabricated observation.
- **unavailable-branch-trajectory**: an admitted physical structural world lacks its native M29a trajectory. It retains its accepted source inventory but does not invent event observations. A new test closes the previous M30a R2 review's nonblocking coverage gap here.
- **rejected-sweep-axis**: the structural world is valid, but its requested physical parameter target/value is not an admissible M28a sweep on that world. M30b may still ask a genuine typed event about the *valid structural parent*, but there are no property grandchildren to observe.
- **rejected-physical-model**: an attempted M28a grandchild is physically refused; it contributes no fabricated physical/event history.
- **rejected-event-study**: the complete physical source model exists, but the shared authored event question is incompatible with that model, such as invalid initial departure from an ideal stop plane. The refusal is event-specific; it does not make the whole physical arrangement invalid. In particular, an admitted parameter grandchild may restore event admissibility even when the *structural parent* rejected that event; M30b still investigates that grandchild afresh, keeping its root comparison **unpaired** against its missing parent observation.
- **integration-failed**, **complete**, or **censored**: original M24a classification and genuine last observation time. Source guards and terminal events are observational stops, not simulated impacts/contact. Earlier real detector roots are retained, but later physical behavior is unknowable after a guard.

M30b uses the *unchanged* M28b _root_pair on two graph-edge types only: original → separately accepted structural parent, and that parent → its actual M20b parameter grandchild. Numerical event shifts are reported only if both native runs reach requested duration and each has exactly one **resolved numerical root**, same event ID and same signed direction. Two crossings, unresolved or unlocated events, opposite signs, censored source-guard/terminal studies, or a missing parent event are **unpaired**. A numerical root's native bracket is not an exact mathematical uncertainty/error bound for the physical ODE root.

Event-run 3D displacement/velocity comparisons reuse M28a _shared_rows on **literally identical saved M24a physical SI times**, not sample index, HTML interpolation or M30a's separate no-event output grids. Cross-inventory electrostatic potential energies are not interpreted as work. No event outcomes are inferred from charts.

## Evidence, refusal staging and limitations

Detached conduit: conductor_sim.nested_event_family.v1. Original native M30a physical source/parameter family remains intact; original EventRun and each branch/grandchild event result or refusal are separately attached with correct exact source and event-model bindings. Every numeric event retains its actual original root time, signed direction, time bracket, position, residual, event ID, outcomes, unresolved candidates and true termination. Source-given labels and author assertions are not independent authentication of textbook PDF facts.

Reproducible teacher examples:

~~~powershell
python examples/m30b_nested_events.py --case added-field --output output/m30b-fields.json
python examples/m30b_nested_events.py --case gravity --output output/m30b-gravity.json

~~~

The frozen acceptance cards cover analytical uniform-force detector root timings, gravity-added negative detector with no baseline crossing, true event-incompatible structural parent followed by event-admissible property grandchild, source guard with real earlier root but no whole-duration pairing, two actual opposite-direction crossing roots, a noncanned titled finite rod plus held point charges with real source-charge variations and signed event, typed refusal and model identity binding, and a targeted test of the preceding M30a reviewer F-01 coverage gap. An independent reviewer must separately challenge an unfamiliar source/property/event arrangement against a separate Coulomb/rod reference and DOP853 or another genuinely independent numerical/analytical calculation.

This release adds **NO M30b apparatus or event-time viewer**: M29b and M28b have their own restricted offline event charts, while M30b provides engine/JSON evidence for later qualified visualization. It is not a conductor, wire-impact, dynamic-source, arbitrary 3D, or exact-ODE-proof facility. The complete historical Python 3.10/3.12, real Chromium and 97 real FEMM5 conductor regressions remain mandatory release gates.
