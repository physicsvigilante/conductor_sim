# M32a — Native unified physical-world observation graph (development candidate)

**Preimplementation scope:** [frozen charter](m32a_charter.md) was published
as a charter-only commit before production work. This is an UNREVIEWED
M32a development candidate until the source PR and independent R2 release gate
pass. M31b and all earlier models remain unchanged.

## The composition problem M32a addresses

M29–M31 already support a number of fixed compositions (structural alternatives,
single-property variations, jointly admissible property edits, then typed
events), but each authored combination previously required a different
family-specific plan and result adapter. M32a's `UnifiedObservationPlan` is
a **single, bounded physical-world graph** rooted at an unchanged native
`PrescribedScenario`. Each world declares its actual immediate parent, a
real structural M22a source operation or 1..4 M20b supported physical property
edits, and the desired native observation mode. Independent siblings and
multi-generation physical-property branches are supported without writing
another physics solver.

```python
from conductor_sim import (
    CoupledPropertyEdit, StructuralWorldNode, PhysicalWorldNode,
    UnifiedObservationPlan, run_unified_observation_graph,
)
from conductor_sim.motion_events import PlaneEvent, EventPolicy
from examples.m29a_structural_family import model

family = model("uniform-edits")
add = next(c for c in family.cases if c.case_id == "add-E")
study = UnifiedObservationPlan("teacher:graph", family.baseline, (
    StructuralWorldNode("add-E","baseline",add,"events"),
    PhysicalWorldNode("atomic","add-E","Change two real SI properties together.",(
        CoupledPropertyEdit("field:Enew","field_v_m",(150.,0.,0.)),
        CoupledPropertyEdit("test-particle","mass_kg",2e-5),
    ),"events"),
), "events", (
    PlaneEvent("x:detector",(.006,0.,0.),(1.,0.,0.),
               "Physical crossing detector",direction=1),
), EventPolicy(.003,1e-8,1e-8,1e-6))
run=run_unified_observation_graph(study)
print(run.as_dict()["nodes"][1]["parent_event_time_comparisons"])
```

Native source worlds are qualified **as complete physical arrangements**.
A structural world uses existing `reassemble_scenario` and retains its
true M22a ancestry, so a retired source identity cannot be silently revived
inside supported structural chains. A physical world resolves supported SI
properties against its ACTUAL immediate source world, and calls original
`revise_scenario` ONCE with all edits together; the entire final model
must satisfy its original physical plane/guard/field/force contracts. Each
admitted world then gets one original `integrate_test_charge` trajectory OR
a freshly investigated original M24a `EventStudy`.

A structural-after-physical edge is deliberately **not** enabled in this
first graph: M22a's ancestry record is not automatically carried through a
raw M20b physical revision. The engine must not pretend otherwise merely
to maximize graph connectivity. Real future support needs a separate
ancestry-preservation contract.

The finite versioned `conductor_sim.unified_observation_graph.v1` JSON
exports the true original model and plan, all node IDs/parents/notes/edits,
M22a source membership ledgers, M20b physical revision ancestry, native
trajectory/event observations, distinct refusals, actual root time/brackets,
and immediate-parent comparison evidence. Numerical comparisons use only
identical saved physical SI times and two duration-complete single
same-direction M24a roots. A parent that rejected a particular event study
may have a child independently qualified for that study; it cannot offer
a fabricated parent event shift. Genuine source-guard/terminal/unresolved
histories never imply unobserved later motion.

M32a's result is protected by a **runner-issued in-process provenance receipt**
over the complete plan, actual models, all native observations, statuses and
comparison data. It is checked at construction and before detached export;
this is NOT cryptographic authentication of arbitrary private Python
access, source PDFs, or exact ODE correctness.

## Run examples and tests

```powershell
python examples/m32a_unified_observations.py --case uniform-events --output output/m32a-uniform.json
python examples/m32a_unified_observations.py --case joint-translation --output output/m32a-shift.json
python -m pytest tests/test_m32a_unified_observation_graph.py -q
```

Limitations: at most 8 nodes, depth 4, up to 20 physical edits, 1–16
existing native M24a questions (when events requested), physically certified
planes and existing source kinds. No new Coulomb/rod/ring/gravity law, FEMM,
numerical integrator, scene graph, LLM runtime, automatic PDF interpretation,
browser solver, conductor induction or contact physics. All teacher hypotheses
are separate physical worlds, never a continuous time-changing source.
