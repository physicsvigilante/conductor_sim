## Educational gap and physical model principle

M20b already supports **atomic multi-property physical revisions** of one qualified fixed-source world through revise_scenario. But reusable M28a/M30a exploration plans only sweep ONE physical property at a time. Teachers should be able to author a *bounded set of named, distinct coupled physical hypotheses*—such as a held ring's charge together with a probe's mass and launch; or a source's position together with the probe's physical initial position—on an original or independently reassembled source inventory, without new per-problem production code.

The essential difference from sequential one-axis sweeps: **every coupled hypothesis is one atomic full-model revision of its actual immediate physical parent**. Do not reject a joint admissible translation merely because each single intermediate change would individually violate a physical invariant plane. Do not treat numerical solver initial guesses as physical initial conditions, and never move a source continuously during playback.

## Native scope

- Public immutable CoupledPropertyEdit(component_id, property_name, whole SI value), CoupledHypothesis(case_id, structural_branch, note, tuple of 2..4 distinct physical edit targets) and CoupledPhysicalPlan(plan_id, existing StructuralFamilyPlan, tuple of 1..5 named CoupledHypothesis). Total edits no more than 16. A structural_branch is literal baseline (the original model) or one of the existing M29a case IDs. The reserved baseline selector is not an allowable structural case ID; duplicate hypothesis IDs or component/property targets refuse.
- Edits use M28a's **existing physical property allowlist, target identity and shape rules**: signed numeric scalar or complete 3-vector, no booleans, nonfinite values or source-list indices. M20b's broader reference/gauge fields cannot masquerade as a physical hypothesis. A target must exist in the ACTUAL structural parent: newly added/replaced source IDs, newly added gravity and existing probe fields are valid; retired or absent sources refuse at a distinct edit-qualification stage. Every edit must differ from that parent's current physical value. A partial no-op inside a claimed coupled hypothesis is refused rather than silently omitted.
- Run unchanged M29a run_structural_family ONCE to obtain native original trajectory plus each atomic M22a accepted/refused source arrangement and source lineage. Select the literal original baseline or a separately accepted M22a structural child per hypothesis. A structural rejection is **skipped-structural-model** (no invented accepted inventory); admitted structural world with absent ordinary native parent integration is **unavailable-branch-trajectory** (retain real accepted inventory, no invented parent). These siblings do not block unrelated hypotheses.
- Group all edits by their M20b typed target (source ID, test-particle, medium, gravity) and invoke unchanged revise_scenario **exactly once per hypothesis** on the ACTUAL selected parent, never on the original if a structural child was selected. This creates one immutable grandchild with actual immediate M20b parent_revision_id, exact edits/ledger and full requalification; a rejected unknown/shape/gauge/unchanged edit is **rejected-coupled-edit** (physically admitted parent retained). A final combined world that fails whole-model physical constraints after applying all otherwise admissible edits is **rejected-physical-model** (no fake numerical history). A valid complete model gets a fresh unchanged integrate_test_charge; recognized MotionIntegrationError / UnsupportedProblem becomes **integration-failed** while duration completion or a real source-guard stop becomes **complete** or **censored**. Unexpected coding errors propagate. Do not evaluate intermediate single-edit worlds or apply changes sequentially.
- All actual 3D Δposition/Δvelocity comparisons are **relative to that hypothesis's real immediate physical parent**, at literally identical M28a saved SI physical times via unchanged _shared_rows. No time interpolation, array-index alignment, cross-world work from absolute potential energies, arbitrary sensitivity/derivative, event interpolation, responding conductor, contact law, new field/RK, free unqualified 3D, unbounded Cartesian grids or scene graph.
- Versioned detached finite JSON conductor_sim.coupled_physical_family.v1 must include original physical source model and native M29a structural family, original→structural M22a assembly SHA/ledger, actual source identities/names/types, selected branch, requested coupled edits and all stages/statuses, ordinary M20b immediate physical parent SHA and grandchild revision/changes, native trajectories and honest exact-timestamp comparisons. SHA certifies authored records, not scanned-workbook provenance or proof of numerical correctness. Do not accept arbitrary imported JSON as trusted engine input.
- **Engine/JSON only**. Existing M24a/M30b typed event APIs remain independent; adapting typed events to coupled hypotheses is a *later bounded milestone* when justified. Do not add HTML viewer, browser-time model editing, mutable graph compiler, cross-model energy work, 3D camera or arbitrary scripting callbacks in this charter.

## Frozen acceptance examples

P1 **Coupled new source and particle mass/launch:** From existing M29a uniform-edits, select structurally introduced field:Enew and atomically change its entire vector E from +100x to +150x V/m AND probe mass from 1e-5 to 2e-5 kg, optionally a third physical launch velocity change. Verify original→structural→grandchild identities, all real unchanged named source IDs, complete trajectories and every saved position/velocity against separate constant-acceleration SI kinematics. Compare against M28a single-axis results only as distinct hypotheses, not equivalent.
P2 **Jointly valid plane-preserving translation that separately refuses:** Original M29a point-replace world: a held point at (.2,0,0) and probe at (0,.1,0) in a physical xy plane, both shift +z by .05m *atomically*. The combined model remains genuinely physically admissible with equivalent original relative dynamics translated z=.05; each one-sided z shift without the other should be independently refused by the existing full-model qualifier. This is a key compositional benefit, not a numerical projection.
P3 **Replacement/retirement:** On replace-Ey source branch, atomically change the new field:Ey-new vector and probe mass or initial velocity. The old field:Ey identity is retired, never resurrected; parent/child SHA and M20b changes reflect only real new source IDs.
P4 **Added gravity and cross-component field coupling:** On add-gravity branch, atomically modify the NEW gravity acceleration and existing held E field, preserving separate F=qE and mg ledgers, gauge/reference-only exclusions and whole-world plane qualification. Independent analytic 2D acceleration.
P5 **Separate honest rejection stages:** Unpaired off-plane source is refused structurally with no qualified child inventory; physically admitted branch with missing retired ID, absent gravity or no-op edit is rejected-coupled-edit while preserving its REAL admitted parent inventory; an admitted per-target edit combination whose whole model leaves the invariant physical plane is rejected-physical-model; valid sibling remains independently solved.
P6 **Genuine source singularity guard and exact-time comparisons:** On a structurally admitted attracting point source branch, coupled charge and probe mass edits may change actual source-guard termination. If guard occurs, keep only actual solved samples and literal same-time rows; never infer postguard travel or contact.
P7 **Unfamiliar transfer:** A newly assembled tilted finite rod/held signed point/gravity arrangement with an added point source, jointly revise that NEW source charge and probe mass/launch. Independently check initial force and full numerical trajectories against standalone direct Coulomb/rod Gauss–Legendre quadrature plus SciPy DOP853; check two-edge identities, physical refusal stages and no old-source mutation. No per-card production changes after reusable adapter written.
P8 **Robust result authenticity:** Wrong type/branch ID, empty/overbound/duplicate edits, invalid shape/Boolean/nonfinite values, wrong source ID, forged mismatched parent or trajectory, bad numerical status and untrusted arbitrary JSON must refuse, not produce plausible-looking output.

N1 No multi-property patch may quietly adjust duration, sample clock, numerical tolerance, source guard, motion plane or source MEMBERSHIP; use separate accepted APIs. A source parameter revision is a distinct physical hypothetical, not source motion in one run.
N2 No new solver/field/ODE, conductor equilibrium response, arbitrary free 3D, collision, browser animation, partial intermediate-model physics or cross-inventory U-as-work. Combined physical admission never implies numerical completion.
