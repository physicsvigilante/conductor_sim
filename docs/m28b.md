# M28b — Reusable typed event questions across physical parameter sweeps

M28b completes a core JEE exploration workflow: **author one physical apparatus, revise one parameter, and ask the same physical event question of every independently integrated model**. It combines the retained [M28a physical sweep](m28a.md), unchanged [M20b identity-addressed revision](m20b.md) and unchanged [M24a true numerical event investigation](m24a.md). The [preimplementation M28b charter](m28b_charter.md) was committed before production code.

## Native public API

`EventSweepPlan` combines an existing `TrajectorySweepPlan` with one immutable tuple of supported M24a `PlaneEvent`/`VelocityReversal` instances and one `EventPolicy`. `run_event_sweep` validates the baseline study **before executing**, then produces a fresh M24a `investigate_motion` for the baseline and *each* independently revised child. It does **not** reuse M28a's precomputed motion samples to guess where a detector was crossed; event localization uses M24a's real force evaluations and bounded step monitoring.

```python
from conductor_sim import (
    EventSweepPlan, run_event_sweep, render_event_sweep,
    SweepAxis, TrajectorySweepPlan,
)
from conductor_sim.motion_events import EventPolicy, PlaneEvent
from examples.m27b_offaxis_motion import author

original, _ = author("workbook-xy")
sweep = TrajectorySweepPlan(
    "lesson:ring-charge", original,
    SweepAxis("ring:B", "charge_c", (-18e-6, -22e-6)))
questions = (PlaneEvent(
    "x:detector", (.275, 0., 0.), (1., 0., 0.),
    "Teacher's passive detector at x=.275 m", direction=1),)
policy = EventPolicy(.001, 1e-8, 1e-7, 1e-5)
model = EventSweepPlan(sweep, questions, policy)
run = run_event_sweep(model)
assert run.plan.sweep.baseline is original
html = render_event_sweep(run)
audit = run.as_dict()   # detached JSON-native audit, never trusted physics import
```

The source workbook p12 Q40–41 supplies ring A/B charges +10/−20 μC, radius .30m, separation .40m, applied upward 100kV/m and probe charge +10 μC. The free-plane mass .01kg, launch x=.2m/vx=.1m/s, duration .015s, detector, and revised ring charges are **teacher hypotheticals**, not the original symbolic/rest/axially-constrained Q41.

## What gets compared, and what does not

- **Physical revision:** 1..6 independent siblings from the unchanged original source-bound model. M28a's physical/gauge allowlist and M27b whole-model plane/singularity guards are respected. A source change may refuse as `rejected-physical-model`; a model may be physically valid but fail an **event-specific** ideal-stop initial-side condition as `rejected-event-study`.
- **Actual native events:** Every supported question retains its ID, direction, unit, finite numerical event bracket, sampled position/velocity/force/energy and any unresolved candidates. A passive detector is not a physical wall, an observed terminal condition is not a contact/absorption law, and source guards truncate the investigation.
- **Run status:** `complete` only when M24a reaches full duration; `censored` on terminal-event, source-guard, or event-unresolved; `integration-failed` for recognized numerical/domain failures. Underlying engine termination strings remain intact. Question outcomes such as `search-truncated` and `not-found-at-requested-resolution` are never conflated.
- **Cross-scenario time shift:** For the *same* event ID, exactly **one** independently located numerical root and zero unresolved candidates must exist in **two duration-complete** runs, with the **same signed crossing/reversal direction**. Then report each original bracket [tmin,tmax], an estimate from reported event samples and conservative **numerical bracket difference interval** [child.min−base.max, child.max−base.min]. This interval bounds differences between the localized numerical roots, **not** the exact physical ODE root error. Two crossings, opposite signed directions under a bidirectional event, unresolved tangencies, and any censored/nonlocated observations (including a root observed **before** a later source guard or terminal stop) remain explicitly **unpaired** instead of selecting arbitrary first roots. Both genuine preguard roots remain retained in the original M24a data, but no unsupported unique whole-duration shift is asserted.
- **Trajectory comparisons:** Directly reuse M28a's match-on-identical-actual-time helper for all saved native event trajectory observations; do not align samples by array index or interpolate a trial's non-grid terminal state. Each source/velocity revision is a different physical experiment, not a physical transition of a particle between scenarios.
- **Evidence:** `EventSweepRun.as_dict()` is detached, versioned `conductor_sim.event_sweep.v1`, recording the original model record and revision SHA, changed model/lineage, actual `EventRun` native histories and event-question classifications. A model digest is record identity, **not** a verified scanned-PDF source or mathematical/numerical proof.

## Visual presentation

`render_event_sweep` and `write_event_sweep_html` produce an entirely offline **event-observation timeline** and table. Each horizontal line runs only to the last **actual saved physical time** for that case. Event markers show individually located numerical M24a roots and the table labels every signed direction. Where M24a retains a **near-coincident terminal alternative** with a representative event sample just past the chosen stop time, the chart shows a small **bounded, scenario-lane-contained cluster anchored immediately to the LEFT of the true stop boundary**, not as post-stop motion. The packed markers use decorative x/y offsets for legibility; those offsets **do not represent numerical event times**. Each original candidate's exact saved sample time, numerical bracket, source ID, residual and signed direction remain in the table. In the declared 16-question limit the cluster is arranged in four small vertical rows across bounded columns, never extending above or below its experiment lane. Separately styled terminal marks reveal censored runs. The table lists all original event brackets and eligible shift intervals. No browser-side force law, event locator, interpolation or network service exists.

This is an **event-time chart**, neither an SVG of the actual rings/point sources nor a new particle trajectory scene. Use the existing fully qualified M27b viewer to see the ring physical apparatus. Source IDs and text come from the actual authored `PrescribedScenario` and are displayed as author assertions; no generic renderer assumes an unrelated model is the ring workbook.

The uniform-mass case has constant field E=1000 V/m, q=1 µC, baseline m=.001kg, v=0, detector x=.05m, and gives the independent analytic test `t=sqrt(2*d*m/(qE))`. The multiple-crossing case tests why one event ID with two actual crossings cannot be paired as if it had a single root. The gravity-guard case compares **source-guard truncation** against a duration-complete hypothetical, without inventing events after either horizon.

## Limits and release requirements

This is intentionally a new composition of existing numerical capabilities, **not** a new event solver or free 3D dynamics. Physical source coordinates, model membership and constant source E are fixed during each independent run; the browser never integrates or changes them. It does not model impact, charged-wire contact, conductor induction, finite conductor kinetics, real-time teacher steering, graph-based general geometry or error bounds for the exact continuous ODE.

Acceptance requires focused analytical/censor/identity/type/refusal tests, real Chromium 390px offline acceptance, all Python 3.10/3.12 regressions and 97 real FEMM conductor nonregressions. Because event-time and cross-scenario evidence semantics change, require one independent **R2 review** of the exact green candidate. Routine merges afterward may proceed under the user's standing authorization, but review failures must be corrected and re-reviewed rather than waived.
