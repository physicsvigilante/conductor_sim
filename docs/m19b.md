# M19b — Offline fixed-field/test-charge viewer

## Purpose

M19a separates **fixed, nonresponding electrostatic sources** from a test
particle. The field provider supplies `potential_at(r)` and
`electric_field_at(r)`, while M19a's shared adaptive RK4 controller integrates
`F=qE` and uses the **full** test-particle potential energy `U=qV`.

M19b connects that existing numerical data to the **same** offline HTML
renderer and elapsed-time Play/Pause/Restart, 0.5×–4× display-speed slider,
source markers, vector force/velocity arrows, full-trajectory displacement,
velocity, kinetic/potential/total-energy graphs and JSON-sidecar provenance.
There is **no second ODE**, no browser computation of electrostatic force and
no charge-distribution response to the moving test particle.

## Example

From PowerShell in a local checkout:

```powershell
python -m pip install -e ".[test]"
python examples/test_charge_viewer.py --case ring-turning --output output/m19b-ring.html
Start-Process .\output\m19b-ring.html

python examples/test_charge_viewer.py --case disc-approach --output output/m19b-disc.html
python examples/test_charge_viewer.py --case uniform-deflection --output output/m19b-uniform.html
Start-Process .\output\m19b-uniform.html
```

The same CLI accepts `ring-crossing`, `two-rings`, `sphere-transit`,
`shell-interior` and `rod-deflection`. The Python API is:

```python
from conductor_sim import sample_test_charge_viewer
from conductor_sim.visualization import write_visualization
from examples.test_charge_motion import make_case

spec = make_case('ring-turning')
bundle = sample_test_charge_viewer(spec, visual_frames=12,
                                   profile_samples=201)
write_visualization(bundle, 'output/m19b-ring.html')
```

The exporter accepts a previously integrated matching M19a
`TestChargeMotionResult` through `result=...` to avoid any second integration.

## What the viewer displays (and refuses)

The particle is a **probe**: it is drawn at each actual saved numerical
position, but its own charge is **never added to the source inventory**.
Displayed arrows are the true stored vector `F=qE` and velocity, normalized
in length for legibility. Each is projected into the *already certified*
physical plane, not forced to follow an invented constraint.

The scene depicts fixed source **geometry** (uniform-field arrows, point
sites, ring meridian intersections, disc diameter, finite rod or uniform
spherical distribution) and the saved trajectory. It is explicitly labelled
**schematic slice**, **not a 2D electric field/potential map**. There are
no spurious conductor results, induced charge densities, equipotential
contours or 2D field lines. This is deliberate: the M19a ring/disc formulas
are valid **on their common symmetry axes only**. Drawing off-axis values
from them would be scientifically incorrect.

- With a ring or disc source: calculate a bounded **21–501 odd-point** signed
  axial profile `V(s)` and `E_parallel(s)` along that *real* common axis,
  including the particle's current axial-coordinate cursor. At the ideal disc
  surface, `V` remains continuous but the field value is **undefined**; the
  saved E graph has a `null` gap and never invents zero or interpolates across
  the discontinuity. The ring centre is finite and can be crossed.
- With spatially supported sources (fixed point, rod, uniform field, uniform
  volume sphere and uniform thin shell): `V(t)`, and the two physically
  projected E components versus **actual elapsed time** are taken directly
  from every M19a numerical sample. This is not a field map along a
  fictitious line through the motion. In particular a curved trajectory is
  not misrepresented as a one-dimensional spatial axis.
- Energy graphs retain full `K`, `U=qV`, and `K+qV`; a small compatibility
  alias named `interaction_energy_j` exists only for the old HTML plotting
  code and is validated to equal the full `potential_energy_j` exactly.
  **No induced-field half factor** enters the fixed-source physics.
- Source singularities and ideal surface-field jumps remain M19a guarded
  *approaches*, never physical collisions or impacts. Connecting a sparse
  pair of saved positions with a straight display chord can cross an
  excluded source; such visual chords are omitted, not recomputed.
  A uniform *volume* sphere has a continuous field at its radius and is
  mechanically transparent in the model; the test particle may cross it.

Playback uses the **whole stored M19a trajectory** for graphs and path
(up to 2,001 samples), but selects only 2–24 real saved sample indices
for the field/particle arrows, controls and time cursor. Because the field
is fixed and does not respond, **no new static field solves are needed**.
Playback compression is a display rate, not a claim that a physical second
is one wall-clock second. All HTML and JSON content are embedded offline.

The bundle uses the original `conductor_sim.visualization.v1` renderer with
a distinct `prescribed_motion` payload
(`conductor_sim.test_charge_viewer.v1`). Existing static, position-sweep,
conductor 1D/2D and held-charge modes remain unchanged.

## Acceptance and scientific evidence

The exporter verifies every saved numerical row against the immutable
fixed-source E/V, charge/mass, `F=qE`, `K+qV`, exact initial conditions,
energy drift, source/surface guards, planar domain and speed limit.
The shared HTML validates the same source inventory and values again,
including **unsampled** graph rows, source-profile `null` gaps and exact
frame-to-particle identities. These checks reject malformed/corrupted data,
but cannot prove that an arbitrarily edited self-consistent history is an
independently integrated solution.

The M19b acceptance suite includes all eight M19a example configurations,
independent ring and disc analytic formulas, stationary field invariance,
mutated-field and mutated-energy negative controls, sparse-guard termination,
fully offline real-Chromium playback/arrow paints, source/particle separation,
axis restrictions, 390px layouts and preservation of prior viewer modes.

**Merge gates:** exact-head Python 3.10/3.12, full legacy
visualization/Chromium and M15c/M17c/M18b/M18c acceptance, M19a physics,
new M19b Chromium and Python tests, and the separately pinned **97 actual
FEMM tests with zero skips**. FEMM results establish earlier conductor
non-regression, not FEMM verification of these prescribed sources.

Still not implemented: arbitrary off-axis ring/disc observations, arbitrary
3D time motion, real conductor induction in prescribed fields, multiple
moving charges, finite-plate fringing, physical collisions, or natural-language
problem parsing. These require separate explicit milestones and tests, not
unlabelled model substitutions.
