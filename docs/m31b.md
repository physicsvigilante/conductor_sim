# M31b development candidate — event questions over atomic coupled physical models

[**Frozen preimplementation charter**](m31b_charter.md). This document describes
the unmerged development candidate, not a released or independently reviewed
feature. M31a remains the accepted physical-model authority.

A `CoupledEventPlan` wraps one existing `CoupledPhysicalPlan`, a tuple of
native M24a `PlaneEvent` / `VelocityReversal` questions, and one M24a
`EventPolicy`. A teacher may now ask the *same* event question after a genuine
two-property physical revision of an independently reassembled named source
world. Source, mass, gravity, medium and physical initial-condition edits are
still fully qualified by M31a/M20b, not changed during the trajectory.

```python
from conductor_sim import (
    CoupledEventPlan, EventPolicy, PlaneEvent, run_coupled_event_family,
)
# physical_plan is an already authored, native M31a CoupledPhysicalPlan.
plan = CoupledEventPlan(
    physical_plan,
    (PlaneEvent("detector", (.006, 0., 0.), (1., 0., 0.),
                "Passive detector", direction=1),),
    EventPolicy(.005, 2e-7, 1e-7, 1e-7),
)
result = run_coupled_event_family(plan)
evidence = result.as_dict()  # Detached evidence, NEVER trusted import
```

The original M24a event study is run once, referenced accepted structural
parents are observed once each, and each admitted coupled physical child gets
a new genuine M24a event integration. Numerical root comparisons use the
existing M28b unique same-direction duration-complete policy and compare the
child only with its *actual immediate physical parent*. Its saved physical
positions and velocities are aligned only at literally identical M24a times.

JSON `conductor_sim.coupled_event_family.v1` retains original M31a physical
family evidence, per-source event runs, physical refusals, true event-study
refusals, unresolved/guard/terminal histories, real source IDs and the
two-edge revision lineage. All returned M24a native typed result objects are
validated against the actual source scenarios before detached export.
Deliberate mutation of arbitrary trusted Python internal objects is not
cryptographically authenticated.

There are **no** moving sources, conductor response, new force solver, browser
ODE, inferred postguard trajectory, arbitrary free 3D, collision laws,
numerical derivative or cross-source-inventory energy-as-work. Numerical
event-time brackets localize the solver's observed root; they do not certify
exact physical ODE root error.
