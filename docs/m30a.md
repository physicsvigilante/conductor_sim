# M30a — Parameter sweeps inside structurally reassembled source worlds

The [frozen charter](m30a_charter.md) was committed before production at `8e129679eb88317f46c8ebd6eb04485b1215ec8b`. M30a implements **engine composability**, not a scene graph or another field/force law.

## Physical authoring workflow

1. Author an ordinary, immutable M29a `StructuralFamilyPlan`: one source-bound original `PrescribedScenario` and 1..5 atomic physical source alternatives. M22a performs the real structural assembly, full-world physical qualification and stable source ID changes.
2. Select **1..3** branch IDs (literal `baseline` or one of the case IDs), each with an existing M28a `SweepAxis` of 1..6 SI values, at most **12 total** requested alternatives.
3. A branch's sweep is anchored to its **newly assembled physical model**. Its axis may name a source introduced in that branch, a source identity genuinely replacing another, or gravity explicitly added in that branch. This is the key capability missing from standalone M28a: a source not present in the original inventory is now a fully typed, reusable physical parameter target.
4. The M30a runner calls the **unchanged** M29a `run_structural_family`, then M28a `TrajectorySweepPlan` and `run_trajectory_sweep` for each admitted requested branch. M28a calls ordinary M20b `revise_scenario` for each value and freshly integrates with the existing M19/M27b physical RK/guards. Recomputing an accepted branch baseline is intentional; exact equality against M29a's native baseline integration is checked, not assumed.
5. Every outcome is a **separate frozen teacher hypothesis**. There is no source changing while the charge moves.

Example:

```python
from conductor_sim import (
    BranchSweep, StructuralParameterPlan, SweepAxis,
    run_structural_parameter_family,
)
from examples.m29a_structural_family import model

family = model("uniform-edits")
plan = StructuralParameterPlan(
    "lesson:new-source-study",
    family,
    (
        BranchSweep("add-E", SweepAxis(
            "field:Enew", "field_v_m", ((50.,0.,0.),(150.,0.,0.)))),
        BranchSweep("add-gravity", SweepAxis(
            "gravity", "acceleration_m_s2", ((0.,-1.,0.),(0.,-4.,0.)))),
    ),
)
run = run_structural_parameter_family(plan)
print([e.status for e in run.entries])
auditable = run.as_dict()
```

The `field:Enew` source identity in this example **does not exist in the source-given/original model**; it is an actual new member of the independently qualified `add-E` world. The `gravity` component only exists in the `add-gravity` world. Ordinary M28a `SweepAxis` physically allowed property names and dimensional checks apply without broadening that allowlist.

## Native result interpretation

`StructuralParameterRun.as_dict()` is detached versioned `conductor_sim.structural_parameter_family.v1`. Its full original M29a structural native run, real source identities/names/types, M22a parent→structural child SHA ledger and each branch's original M28a parameter suite preserve the two-stage source and physical revision chain. Each parameter grandchild's `parent_revision_id` equals the **actual structural scenario** SHA, not the original baseline SHA. No source index is substituted for an identity, and a replaced/retired identity is never revived by a property sweep.

- **`evaluated`**: this admitted branch has an original M28a `TrajectorySweepRun`, with per-value statuses `complete`, `censored`, `rejected-physical-model` or `integration-failed`. A `censored` source guard remains a real finite native history with no invented later states.
- **`skipped-structural-model`**: M22a/M29a refused physical assembly before any sweep. No accepted source inventory is fabricated.
- **`rejected-sweep-axis`**: the physical structural branch was accepted, but this requested target/property/value is not an admissible M28a sweep on *that branch* (e.g. target ID absent or retired; same-value revision; wrong vector shape; potential-reference gauge rather than physical parameter). Preserve the actual accepted structural inventory.
- **`unavailable-branch-trajectory`**: a structurally admitted branch did not furnish its base native M29a trajectory, or a new M28a baseline integration encountered a recognized numerical/domain error. Never misreport this as physical non-admission.

Within each M28a sweep, original 3D position/velocity differences use **literally identical saved physical times**, not array indices or presentation interpolation. M29a's original structural comparisons likewise remain intact. M30a does **not** compute work from cross-inventory energies, cross-grid sensitivity derivatives, cross-family potential-energy differences or event-time shifts. The versioned JSON is not trusted input and source names/provenance are authored claims, not scanned-PDF authentication.

## Verification boundaries and extensions

The M30a native tests cover analytic uniform-electric acceleration of a newly added source, a newly replaced source's retired original identity, newly added gravity property sweeps, distinct rejected structural and rejected sweep-axis stages, explicitly refused physically invalid grandchild, guarded native histories, and an independent Coulomb midpoint quadrature reference for a new tilted rod + signed fixed points + gravity + added charge family. No new field, force, 3D plane, RK, FEMM, event or conductor response implementation is introduced.

This is deliberately **native engine + JSON**, not a browser visualization or universal Cartesian parameter grid. M29b already supports identical typed event questions across changed source inventories; nested parameter-plus-structure event exploration or source geometry drawing remains future qualified work. The full historical Python, browser and 97 real FEMM5 suites must remain green. An independent R2 review is required to check a genuinely unfamiliar source-addition property sweep, two-stage source identities, SI dynamics, refusal scopes and guard censoring before release.
