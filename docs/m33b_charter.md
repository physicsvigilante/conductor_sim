# M33b — Frozen charter: reusable native event inquiries on qualified physical-world graphs

**Preimplementation frozen contract.** Base is independently reviewed/released M33a main `a88a5eefc308331555efe6a07c67fd72a712d6a1`, PR #75, exact-tree identical source and 15/15 postmerge successful workflows. Commit this charter alone before implementation. This is a prospective charter, NOT built or independently reviewed functionality.

## Educational requirement

A teacher should be able to keep one immutable, versioned graph of *genuinely qualified stationary-source worlds*, then ask further **native typed detector/reversal questions** of selected actual worlds, including siblings and nonadjacent descendants, **without reauthoring/requalifying the physical source graph**. Different questions are new measurement requests on the same model; they do not imply a change to source charges, physical initial conditions, field physics or a physical transition between hypothetical worlds.

## Additive native interface (new schema only)

- Introduce standalone `GraphEventInquiryPlan`, `GraphEventInquiryEntry`, `GraphEventInquiryRun`, `run_graph_event_inquiry`. Accept **only an authentic, runner-issued** `UnifiedObservationRun` produced by M32b or M33a with `retain_source_ancestry=True`. This is an in-process native object reference, **not imported JSON**, saved trajectory samples or third-party serialized model. Revalidate the input source graph on construction, execution and export.
- One bounded new immutable inquiry: stable `inquiry_id` (1–36 ASCII chars matching source plan ID convention), `world_ids` (1–8 distinct baseline/node stable IDs), native `questions` (1–16 existing M24a PlaneEvent/VelocityReversal objects with distinct IDs), exact native `EventPolicy`, optional ordered `comparisons` (0–8 exact existing M33a `WorldComparison` requests whose side world IDs must be selected). Reject malformed types, unknown IDs, duplicates, reversed duplicate pairs, contradictory same-world requests, unbounded list, missing opt-in ancestry.
- Each world selection references its **actual** admitted physical `PrescribedScenario` with exact revision and branch-local M32b `SourceWorldAncestry`; no new structural M22a or physical M20b source edit. A structurally/physically refused world yields explicit `skipped-parent-model` inquiry row without native EventRun. A physically admitted world whose previously requested observation refused can still be independently asked a different M24a question and legitimately succeed.
- **One genuine fresh M24a `EventStudy` + `investigate_motion` run per selected admitted world**, with the same new question tuple and numerical policy. Never derive events from saved trajectories, reuse a prior incompatible EventRun, interpolate saved frames, re-solve a field model unnecessarily or invent a missing event. Per-world M24a validation/refusal and integration failure are recorded truthfully. Integration statuses are exactly native `complete`, `censored-source-guard`, `terminal-event`, `event-unresolved` or genuine `rejected-event-study`/`integration-failed`; no fabricated later motion.
- New standalone detached `conductor_sim.graph_event_inquiry_plan.v1` and `conductor_sim.graph_event_inquiry.v1` output, explicitly binding originating graph plan ID, original model revision ID, a canonical digest of the complete source graph evidence and exact inquiries, native per-world model revision/source inventory/ancestry/native event/run outcomes, status/reason and sorted/ordered requested comparisons. Do not change the old graph v1/v2/v3 plan/record shapes, type constructors, exported data, original runner receipt or old parent comparisons.

## Correct comparison semantics

- For each selected ordered pair, use only actual fresh M24a results for **this SAME new typed question set and policy**, with right-minus-left orientation and each true model revision/source inventory/ancestry recorded on its own side. Reuse existing M28a `_shared_rows` for literally equal saved SI timestamps; no rounding, index matching, resampling or postguard extrapolation. Reuse unchanged M28b `_root_pair` for single located, same-direction roots in two *duration-complete* runs; multiple, opposite, terminal, source-guard and unresolved roots are unpaired with precise reason.
- Trajectory comparison and event-time pairing are **different observables**: an absence of common saved time stamps does not itself invalidate independently located, compatible whole-duration event roots. A top-level pair is `compared` if it has at least one admissible shared-time numerical row **or** at least one native unique event pairing, otherwise `unpaired` with explicit reason. Individual events remain unpaired where rules prohibit comparison. Do not label cross-inventory potential/energy differences as physical work or claim a source moved.

## Typed evidence integrity and bounded science

- Constructor and every pre-export `as_dict()` must rebind inquiry ID, original graph and certified source revisions, exact native source inventory and ancestry, all selected world statuses/questions/policy, genuine EventRun numerical samples/root/termination to an in-process runner-issued SHA256 receipt; independently derive pair rows from genuine native events. Use exact built-in type checks and type-faithful clock validation, so `False==0.0` cannot be exploited as timestamp evidence. No cryptographic trust against privileged Python module internals or authentication of teacher/PDF input is claimed.
- The inquiry result and output are finite and detached JSON, never trusted import into physics. No native source modification and no silent replacement of the baseline or prior records. Probe actual zero SI times, refutation of forged stop statuses, altered root brackets/locations, altered labels/parent hashes, alternate questions, changed mode/status, and dataclass replacement/public postconstruction mutations. Retained source graph is unchanged.
- Scientific acceptance: independently express qE+mg x/y/z SI Newtonian state/force and signed roots in at least one novel planar-oriented field/initial-condition arrangement; run actual new detector questions against at least three related models with sibling and nonadjacent branches. Exercise genuine study refusals, source guards, multiple/opposite roots, terminal, different sampling intervals where possible and distinct sibling ID histories.
- Preserve original M32a/M32b/M33a tests and byte-shape old exported schemas; dedicated Python 3.10/3.12, real FEMM5 historic 97 tests, historic Chromium and independently expressed source-head numerical reference. Record source HEAD and tree in CI artifacts.

## Not included

No novel Coulomb/rod/ring or conductor field law, no moving held source, response/induction, contact, collision, new ODE/RK/event locator, scene graph, browser-side dynamics, arbitrary event callback code, JSON deserializer, unrestricted 3D, automatic textbook parsing, or cryptographic attestation.
