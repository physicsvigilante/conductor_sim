**Draft development candidate.** The [frozen charter](m35a_charter.md) predates implementation. See the [project audit](m35a_audit.md) for reproduced defects, corrections, open issue #80 and the validation plan. Independent R2 review and owner-authorized release are not implied by this document.

## Continue a previously solved branch, without replaying it

The existing `GraphWorldForkPlan.source_graph` now accepts either an authentic `UnifiedObservationRun` or an authentic completed `GraphWorldForkRun`. The latter is an explicitly multi-stage source. The same M22a structural and M20b physical revisions requalify newly requested worlds, then only those newly admitted worlds receive native integration. Original model, assembly, trajectory/event and source-ancestry objects are retained exactly. A physical-model refusal produces skipped descendants; an admitted model whose earlier observation was refused may still be a valid physical parent.

```python
from conductor_sim import (
    GraphWorldForkPlan, PhysicalWorldNode, CoupledPropertyEdit,
    WorldComparison, run_graph_world_fork,
)
# first is an authentic completed native GraphWorldForkRun.
# 'earlier-world' exists in its retained source graph or one of its prior stages.
second_plan = GraphWorldForkPlan(
    first, 'teacher:stage-two',
    (PhysicalWorldNode('new-mass', 'earlier-world', 'New probe mass',
        (CoupledPropertyEdit('test-particle', 'mass_kg', 3e-6),), 'events'),),
    first.plan.questions, first.plan.policy,
    (WorldComparison('old-new', 'earlier-world', 'new-mass'),),
)
second = run_graph_world_fork(second_plan)
# A later GraphWorldForkPlan can now use second as its source.
```

`GraphEventInquiryPlan` can also accept an authentic fork history and ask fresh native M24a questions of the original baseline, any earlier admitted world or a newly added world. This is a new measurement and genuinely reintegrates each selected model for those questions, unlike a physical fork which observes only its new children. These two operations must not be conflated.

## Evidence, identities and comparison

The chain is traversed iteratively, bounded and checked for cycles before numerical work. The original graph and every preceding stage's native result/receipt are revalidated chronologically. No persistent validation cache is retained between calls. True immediate model/assembly objects, model revision hashes and branch-local seen/active/retired IDs survive every stage; retired IDs cannot be resurrected by moving to a later stage. Separate alternative branches may independently use the same ID.

World and stage IDs may not overwrite inherited identities. Shared-time comparison uses literally equal saved SI timestamps and right-minus-left vectors, not interpolated animation frames. Event shifts require the same full typed detector questions/policy and two duration-complete uniquely located same-direction roots. Guards, terminal/unresolved histories and multiple/opposite signed roots remain unpaired; a matching event ID string alone is insufficient.

The first direct graph fork preserves `graph_world_fork_plan.v1` / `graph_world_fork.v1`. Continuing from a completed fork opts into **v2**, adding original graph digest, immediate source-history digest, ordered prior stage identities/digests, stage number and cumulative world count. Parent provenance distinguishes `source_graph`, `prior_fork` and `this_fork`. Fresh inquiries on fork histories similarly use inquiry **v2**; original graph inquiries remain v1. The original five graph/direct-fork/inquiry output formats are compared byte-for-byte against released M34b on an unchanged real fixture.

These are in-process issued receipts, not cryptographic signatures from a trusted third party. Detached finite JSON is evidence for inspection, never automatically trusted input for reconstructing physical models.

## Bounds and exclusions

| Request | Bound |
| --- | --- |
| First direct graph fork | Original M34b limits unchanged: 1–5 new nodes, at most 12 cumulative nonbaseline worlds, depth 6, 12 physical edits. |
| Multi-stage continuation | At most 8 fork stages including the new one, 32 cumulative nonbaseline worlds, physical depth 12, 1–5 new nodes and 12 physical edits per stage. |
| Refused worlds | Count toward cumulative budgets; failure does not reset a budget. |
| Inquiry | Existing 1–8 selected worlds, 1–16 typed questions and at most 8 explicit comparisons. |

This means successive exploration calls in **one Python process**. There is no durable session database, process-restart restoration, JSON physics importer, merge of divergent stage histories, concurrent editing or automatic problem-text interpreter. No new force law, FEMM solver, responding/moving conductor, collision, unrestricted 3D motion or scene graph is introduced.

The new example uses a certified non-dyadic oblique plane `(3,4,-2)`, electric fields plus uniform gravity, two original sibling alternatives, then three successive stages with mass edits, source addition/replacement/removal, a rejected retired-ID resurrection and an independent valid reuse. A fresh M24a inquiry follows on four selected history worlds. Earlier saved observations remain unchanged.

The independent-form checker imports **no production package**. It derives Cartesian Newtonian states/forces and quadratic signed detector times, checks actual saved SI clocks and exact source-history digests, reconstructs branch-local retirement membership and refuses deliberately falsified evidence. The companion audit adds nonuniform Coulomb orbit, independent rod/ring quadrature and field–potential consistency tests. These are bounded developer scientific references; a separate-context reviewer must still devise new tests on the exact final source SHA/tree.
