# M28a — One physical apparatus, independently requalified trajectory sweeps

[Frozen preimplementation charter](m28a_charter.md) was committed at `764b56489f55919a2a434605fd4eafd65116ea08` **before any production M28a code**.

## Scope and architecture

The public entry points `SweepAxis`, `TrajectorySweepPlan`, `run_trajectory_sweep`, `render_trajectory_sweep`, and `write_trajectory_sweep_html` form a bounded sweep adapter around the already-accepted M20b `revise_scenario` and M19/M27b `integrate_test_charge`. There is **no new electrostatic field law, geometry qualification, time integrator, event finder, drag model, current, conductor response, browser ODE, or persistent scenario database**.

For each explicit value, M28a creates a new immutable `PrescribedScenario` **directly from the baseline**, addressed by the same source ID. It does not create a chain of sibling revisions. A generated source/particle revision is admitted under exactly the same entire-model plane, source singularity, mathematical and numerical constraints as any other M20b scenario. No numerical tolerances, guard distances, durations or sample grids may be changed with this physical sweep interface.

A sweep has one physical target and 1..6 *distinct* values, none equal to the baseline. It may address a named built-in fixed source's supported physical property (e.g. ring charge or entire 3-vector centre), `test-particle` charge/position/mass/initial velocity, `medium.permittivity_f_m`, or a property of an **existing** gravity component. A zero-size/overbound sweep, unsupported property, source index rather than stable identity, wrong-dimensional vector, nonfinite/Boolean value or repeated baseline is rejected up front.

## Reusable authoring example

```python
from conductor_sim import (SweepAxis, TrajectorySweepPlan,
                           run_trajectory_sweep, write_trajectory_sweep_html)
from examples.m27b_offaxis_motion import author

baseline, _ = author("workbook-xy")
plan = TrajectorySweepPlan(
    "lesson:ring-separation", baseline,
    SweepAxis("ring:B", "center_m",
              ((0.35, 0.0, 0.0), (0.45, 0.0, 0.0))))
result = run_trajectory_sweep(plan)
assert baseline.spec.field.sources[1].center_m == (0.4, 0.0, 0.0)

print([e.status for e in result.entries])
write_trajectory_sweep_html(result, "output/compare.html")
# result.as_dict() is a detached, versioned JSON-native audit record.
```

The elementary example uses the workbook's ring A/B charges +10/-20 μC, 0.30 m radius, 0.40 m source separation, external +world-y field 100,000 V/m **and source-given probe q=+10 μC**. Mass 0.01 kg, x=0.20 m, initial v_x=0.1 m/s, duration 0.015 s and each new sweep value are **teacher hypotheses**, not the original symbolic-mass, rest/axial Q41 solution.

## Numerical and comparison semantics

- **baseline**: ordinary M27b typed `TestChargeMotionResult` from the original immutable `TestChargeMotionSpec`. A model can be admissible yet end at a source guard.
- **complete**: qualified revised model was integrated by the existing RK and reached the requested duration. This does not prove an exact analytic solution.
- **censored**: a qualified revised model integrated but stopped before duration, normally at the source singularity guard. Keep its actual end sample and no later invented states.
- **rejected-physical-model**: the existing entire-model revision constructor refused an inadmissible source shape, plane, launch, parameter or guard.
- **integration-failed**: a qualified revision encountered a recognized numerical/domain error while integrating. Unexpected code exceptions are deliberately not swallowed.

No variation is silently discarded because a sibling failed. Only genuine, **exactly equal saved SI timestamps** are compared. This is stricter than matching array indices: a guarded run can have a non-grid terminal sample, which receives no fabricated baseline alignment. Position/velocity component deltas and Euclidean differences are computed at each shared timestamp; absolute potential energies across scenarios are not interpreted as mechanical work because potential gauges/components may differ. This is *not* a sensitivity derivative, uncertainty bound or proof of ODE accuracy.

`TrajectorySweepRun.as_dict()` returns an independently detached versioned `conductor_sim.trajectory_sweep.v1` report including complete source/particle revision records, requested values, accepted trajectory series, refusals, terminations and aligned differences. SHA-256 revision identifiers attest authored-record identity, **not workbook authenticity or numerical correctness**. External JSON is not accepted by the HTML renderer as trusted native physics.

## Visualization and source-fidelity limits

The standalone offline `render_trajectory_sweep` shows all accepted particle paths projected into a *single certified world plane* with an explicitly labeled orthogonal basis and origin. The colored geometry is **trajectory space only**; it does not draw ring rims, an invented particle guide or a conductor response. For full charged-ring **apparatus** geometry and fields, use the already-qualified M27b saved-time viewer. A shared slider and playback button select only native saved states. If a comparison case is censored, its full solved path ends at its actual last state, and its marker/readout disappear at later baseline times; it is never extrapolated.

A hostile/malformed arbitrary JSON object is not a `TrajectorySweepRun` and is refused. The page embeds data as safely escaped JSON and only uses DOM text APIs for source/variation labels. The real offline Chromium test verifies no network/JS errors, active and unavailable states, saved-time controls and wide/390px layout.

Run native tests with `python -m pytest tests/test_m28a_trajectory_sweep.py -q` and actual Chromium with `python -m tools.check_m28a_browser --output output/m28a-browser`. GitHub also runs the retained full Python 3.10/3.12, FEMM 5 real solver nonregressions and all historical browser checks. Source-given geometric truth was checked in M27b and remains unchanged; M28a tests verify analytic constant acceleration, ring-source stable-ID application, the old M27b field/integrator path, runtime censoring and invalid variations. A separate independent scoped review should challenge new orchestration semantics and viewer temporal truth before a merge.

Out of scope: genuinely changing topology during a **single** run, multiple simultaneous moving particles, 2D Cartesian parameter surfaces, automatic sensitivity/derivatives, solver rewrites, arbitrary 3D charged-particle motion, new physics at ideal ring contact, or continuous parameter variation while the HTML is playing. A later M28b can add **full-apparatus comparison** through the existing source-geometry renderer rather than incorrectly claiming the trajectory plot is an apparatus diagram.
