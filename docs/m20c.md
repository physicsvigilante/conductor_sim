# M20c — Cross-source authoring and negative-case trial

## Purpose and method

This milestone evaluates whether the unchanged M20b immutable revision
interface can support **new** teacher-authored systems beyond Ring A/B,
including multi-source planar motion, volume/surface charge distributions,
and genuine model-contract refusals. The question cards and expected outcomes
were committed separately in docs/m20c_trial_charter.md **before**
implementation. This is a curated reproducible developer trial, not a blind
random sample of JEE textbook questions.

Only examples, tests, trial documentation and the existing browser-test
workflow are changed. No production field formula, integration controller,
viewer or scenario/comparison validation logic is modified.

The educational evaluation contract is retained: interpretation fidelity,
physical correctness, supported simulation coverage, educational usefulness,
and optional textbook-answer completeness must not be collapsed into one score.

## Six complete teacher comparisons

| Card | Physical model | Revision | Independent cross-check |
|---|---|---|---|
| U1 | Charged particle launched transversely through a uniform E | Double mass | Exact constant-acceleration parabola |
| V1 | Oppositely charged particle oscillates inside a **fixed volume-charge sphere** | Increase sphere charge | Interior harmonic oscillator |
| R1 | Off-axis flyby of a fixed finite charged rod | Increase source charge | Independent Coulomb midpoint quadrature |
| P1 | Fixed point charge plus independent uniform field, 2D motion | Increase point source charge | Coulomb + uniform superposition |
| S1 | Particle moving entirely within a **nonconducting charged thin shell** | Double shell charge | Zero interior E, unchanged trajectory, analytic q delta V |
| D1 | Positive particle outside charged thin disc, moving on symmetry axis | Increase disc radius | Exact positive-side disc axial E and V |

No charged source reacts to the probe; all fixed charge inventories are held.
S1 is an ideal uniformly charged *nonconducting* shell, not conductor
shielding or induced surface-charge physics. D1 remains axis-only and has an
undefined field on the ideal surface.

Each comparison independently integrates the baseline and revision using
M19a, validates through M19e and M20a, retains stable IDs, exposes a computed
change ledger, and requires identical exact saved physical time grids and
world projection. The original authored baseline is not changed.

## Six deliberately difficult requests

- N1: transverse disc launch -> qualified axis violation, refused.
- N2: launch on thin shell surface -> field-jump/guard, refused.
- N3: patch source membership by an unknown ID -> structural edit not supported by M20b, refused. A distinct new baseline can still be authored using existing components.
- N4: revise a prescribed volume charge into a grounded conductor -> source type/boundary-condition change beyond the M20b interface, refused. Existing conductor solvers are separate.
- N5: change the true initial particle position -> new model and complete trajectories accepted; M20a refuses side-by-side comparison because the original world slice origins are different. No visual recentering is invented.
- N6: attractive point source with genuine guard termination -> model accepted and both real physical histories explicitly censored; M20a refuses to compare truncated durations.

Blocked pairs are not silently omitted, reinterpreted or converted into static
snapshots. The report differentiates physical model admissibility, trajectory
completion, and comparison eligibility.

## Reproduce on main

From a repository checkout, install with python -m pip install -e ".[test]".

- List the preregistered cases: python examples/m20c_authoring_trial.py list
- Produce the full JSON grading: python examples/m20c_authoring_trial.py grade --output output/m20c-grade.json
- Produce an offline viewer: python examples/m20c_authoring_trial.py render P1 --output output/m20c-point-superposition.html
- Run focused Python checks: python -m pytest tests/test_m20c_authoring_trial.py -q

Positive render IDs are U1, V1, R1, P1, S1 and D1. Every render has a
sibling JSON with baseline, revision, verified comparison manifest and
case-specific independent reference observations. The grade command exits
nonzero if any of its twelve expected outcomes differ. All data and HTML
are reusable offline; no browser-side field or motion solve occurs.

The existing M20a browser workflow also runs all six new cases in actual
Chromium, checking rendered sources, source identities, saved frames,
synchronized playback and mobile width, and records screenshots and
machine-readable assertions as GitHub artifacts. Its FEMM workflow is a
nonregression check, not the physics backend used by these source systems.

## Interpretation

Successful transfer beyond one Ring A/B example would provide evidence of
model composability in the **current qualified fixed-source regime**, rather
than universal LLM authorability. Python code is still authored by the
teacher/agent; there is no automatic natural-language problem interpreter.

What remains unsupported: conductor boundary-condition editing via M20b,
arbitrary source structural modifications, off-axis disc/ring physics,
coupled responding source charges, interpolation between incompatible runs,
and exhaustive arbitrary JEE problem coverage. No textbook-answer
completeness is claimed.

The evidence table, pass counts and acceptance status belong in the PR
review based on actual test and browser logs, not this static methods note.
