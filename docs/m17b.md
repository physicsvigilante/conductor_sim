# M17b — Interactive curved electrostatic trajectories

## Purpose

M17a computes genuine elapsed-time classical vector motion from the existing
analytical `force_energy(solution)` interface in a **physically invariant
plane**. M17b **does not add an ODE solver or force formula**. It presents that
numerical trajectory in the existing standalone M5–M16b offline HTML viewer,
reusing static electrostatic field-map sampling, profiles, colours, contours,
field lines, charge markers, time-controls and energy graphs.

```python
from conductor_sim import (
    ConductingPlane, ElectrostaticProblem, Grounded,
    GroundedPlaneBackend, Motion2DSpec, PointCharge, sample_motion_2d,
)
from conductor_sim.visualization import write_visualization

problem = ElectrostaticProblem((PointCharge(1e-9,(0.,0.,.1)),),
                                (ConductingPlane(),))
spec = Motion2DSpec(problem,0,1e-6,(.2,0.,-.03),.04,.005)
bundle = sample_motion_2d(spec,GroundedPlaneBackend(),resolution=25)
write_visualization(bundle,'output/m17b-plane.html')
```

Or export reproducible standalone HTML and matching JSON from PowerShell:

```powershell
python examples/particle_motion_2d_viewer.py --case plane --output output/m17b-plane.html
python examples/particle_motion_2d_viewer.py --case plates --output output/m17b-plates.html
python examples/particle_motion_2d_viewer.py --case sphere --output output/m17b-sphere.html
python examples/particle_motion_2d_viewer.py --case cavity --output output/m17b-cavity.html
Start-Process .\output\m17b-plates.html
```

`center` demonstrates a stationary exact cavity equilibrium. `guard` is
a controlled vacuum-side approach termination, *not* a collision. The examples
remain explicitly analytical; FEMM force/dynamics are unsupported.

## Reusable architecture and traceable data

`sample_motion_2d(spec, backend, *, result=None)` accepts a previously
integrated matching `Motion2DResult` or invokes M17a's
`integrate_motion_2d` exactly once. Its full original trajectory (up to
2,001 real physical-time samples) is stored as `motion_2d.samples`. All
displacement/velocity and kinetic/interaction/total-energy curves are drawn
from every numerical sample, not from viewport pixels or fake position sweeps.

The same M16b `_choose_indices` limits separately solved electrostatic
potential/E/sigma/field-line snapshots to **2–24 actual trajectory indices**.
The stored `frame_sample_indices` list links each frame to its unique exact
physical-time row. Each frame is independently solved at that row's actual
particle position; the analytical force vector and mechanical interaction
energy are checked against the M17a row. Mismatches, unsupported force
providers, input/result mismatch, unrelated display planes and numerical
FEMM substitutions explicitly fail. Solver resources are closed on errors.

A fixed `SliceSpec` is computed from the previously proved M17a invariant
plane. Infinite-plane anchors do not influence tangential zoom. Exterior
spheres and nested cavity shells retain their complete radial extents.
The particle's entire saved numerical path must belong to that slice; no
out-of-plane projection is disguised as a physical 2D simulation.

Serialized playback schema: `conductor_sim.motion_viewer_2d.v1`, within
the existing `conductor_sim.visualization.v1` bundle. Older v1 static
views, M13–M15 quasistatic position sweeps and M16b
`conductor_sim.motion_viewer.v1` retain their own controls and semantics.

## Browser display

The existing elapsed-time Play/Pause/Restart, time slider and 0.5×–4×
**display speed** controls select only saved physical-time field frames.
They never integrate equations of motion, interpolate from fictitious
electrostatic states, or imply that 1× means one actual second per wall-clock
second. The viewer draws the complete curved numerical path as a dashed
preview, with its traversed portion highlighted. Both path layers use the
full saved output series; clicking the slider synchronizes the highlighted
path, velocity vector, force vector and all graph markers.

Velocity and force vectors are the true stored **3D SI vectors**, projected
onto the proven physical display slice. Arrows are length-normalized for
legibility; the exact values, units and mechanical-energy drift appear in
the readout. Two-component (slice u and v) position and velocity plots
show *elapsed time* on the horizontal axis, plus the original K/U/K+U
energy graph. The browser displays no invented velocity or transverse
constraint force. A surface guard remains an **approach event**, never an
exact point-conductor impact.

## Acceptance and exclusions

Python 3.10/3.12, the full retained M16a/b and M15c regressions,
Chromium offline/390px/playback/field mapping, original source/visual tests
and **97 real FEMM tests with zero skips** are merge gates. The FEMM run
demonstrates **non-regression**, not numerical FEMM vector-force accuracy.

Still unsupported: unconstrained general 3D motion, multi-moving-charge
dynamics, magnetic fields, finite particle collisions, actual conductor
currents, changing electrode voltages, and relativistic motion. M17c
should test fresh JEE-style curved-trajectory authoring problems against
independent references without adding geometry-specific simulation scripts.
