# M34b — Incremental certified physical-world forks

**Development candidate, NOT released or independently reviewed.** Read the frozen
[scientific charter](m34b_charter.md) and verify exact source-head workflows
before treating this as an accepted physical capability.

## Teacher workflow

M32a/M32b and M33a allow one finite qualified world graph with alternative
source structures, real physical-property revisions, trajectories, genuine
typed events and cross-branch comparisons. M33b allows *new event questions*
on existing certified worlds. Until M34b, adding a *new physical hypothesis*
required authoring another whole graph and re-integrating earlier worlds.

M34b introduces a separate, additive **GraphWorldForkPlan** accepting one
authentic issued immutable **UnifiedObservationRun** with retained source
ancestry. It creates **1..5 NEW native worlds** from an already qualified
baseline, previous graph node or a preceding new fork node, using existing
StructuralWorldNode/PhysicalWorldNode, genuine M22a/M20b source/model
operations, and unchanged native M19/M27 or M24a observations.
The original source models, physical trajectories and event runs are
**reused verbatim** and NEVER reintegrated by the fork adapter.
This is incremental counterfactual *authored worlds*, not an evolving source
configuration, source motion, or saved-frame interpolation.

### Python example

    from conductor_sim import (
        GraphWorldForkPlan, PhysicalWorldNode, WorldComparison,
        CoupledPropertyEdit, run_graph_world_fork,
    )

    # source_graph is an authentic, already solved UnifiedObservationRun
    # with retain_source_ancestry=True and a prior world "old-a".
    plan = GraphWorldForkPlan(
        source_graph, "teacher:more-hypotheses",
        (PhysicalWorldNode("changed-mass", "old-a",
                           "New hypothetical particle mass",
                           (CoupledPropertyEdit("test-particle", "mass_kg", 2e-5),),
                           "events"),),
        source_graph.plan.questions, source_graph.plan.policy,
        (WorldComparison("compare", "old-a", "changed-mass"),),
    )
    run = run_graph_world_fork(plan)
    assert run.as_dict()["schema"] == "conductor_sim.graph_world_fork.v1"

A physical parent is eligible when its source model was admitted, even if
its previous observation was rejected. A physically refused parent yields
explicit skipped-parent-model descendants with no fake source/evidence.
New source IDs cannot revive retired IDs in the same physical lineage,
including after an intermediate physical edit. Identical IDs on separate
sibling branches are legal and remain independent. Every admitted child
retains actual immediate parent revision SHA, held-source labels/types,
complete branch-local active/seen/retired ID history, M22a assembly where
structural, genuine M20b revisions where physical.

## Scientifically bounded comparisons

Explicit ordered WorldComparison requests may pair an earlier source world
with a NEW fork world, or two NEW worlds. Each requires at least one new world.
Differences mean **right minus left**. Saved 3D position and velocity rows
use *literally identical actually saved SI timestamps*, never interpolation,
index pairing, rounding or extrapolation past source guards. Native observation
modes must agree.

Native M28b signed event time shifts are a **different observable**. They are
permitted only with identical **full typed M24a question set and numerical
policy** and exactly one located same-direction root in both duration-complete
event runs. An earlier source graph may have different event questions or
policy: shared-time physical trajectory observations remain legitimate, but
root shifts are explicitly **unpaired**, even if event ID strings coincide.
Terminal, guarded, unresolved, multiple and opposite-direction roots cannot
manufacture an admissible whole-duration event shift. Root brackets localize
numerical roots, not error bounds on the exact ODE.

## Evidence integrity and limitations

Only authentic runner-issued native graph objects are accepted, not imported
JSON. Standalone finite detached schemas are
conductor_sim.graph_world_fork_plan.v1 and
conductor_sim.graph_world_fork.v1. Records include a canonical SHA256 of the
complete preserved original graph, source-root ID/schema, full new typed
physical requests, source inventories, true revision/ancestry paths,
new actual native M24a/M27 trajectories, refusal classifications and
side-specific comparisons. The original graph and new fork have independent
runner-issued **in-process** SHA256 receipts rechecked before each export.
Altered native model properties, source history, root brackets, SI timestamps
or statuses are rejected. Detached JSON is not a native-model importer,
externally signed authenticity certificate or verified textbook parser.

Finite bounds: 1..5 new nodes, at most 12 combined old/new graph nodes,
at most six source-root revisions, and 12 physical-property edits.
A later fork can reference original graph nodes but not a NEW world created
by a separate completed fork result; multi-session persistent branching is
left for a future milestone.

No new electrostatic/gravitation law, numerical integrator, FEMM solver,
conductor response, moving held source, contact/collision, unrestricted 3D,
scene graph or browser-time ODE was added.

### Reproduce true native worlds

    python -m examples.m34b_incremental_forks --original-output output/m34b-source.json --output output/m34b-fork.json
    python -m pytest tests/test_m34b_incremental_world_forks.py -q
    python tools/m34b_independent_forks.py --original output/m34b-source.json --fork output/m34b-fork.json --output output/m34b-independent.json

The standard-library-only scientific checker imports NO conductor_sim code.
It verifies every actual saved three-component SI Newtonian sample for all
original and new worlds, signed detector times and numerical root brackets,
three true right-minus-left cross-world event shifts/vector comparisons,
source ancestry and real parent revision hashes, retired-ID refusal, and
seven deliberately corrupted detached evidence cases.

Source-head [scientific workflow](../.github/workflows/m34b-independent-forks.yml)
seals original/new native JSON plus independent SI evidence and exact HEAD/Git
tree. Historical Python 3.10/3.12, real FEMM5, Chromium and existing v1/v2/v3
graph/M33b inquiry/M34a normalization contracts must remain unchanged.

Because new physical model/evidence semantics are involved, one full
separate-context R2 independent reviewer must test the exact source SHA/tree,
then owner must separately approve an expected-head merge after all current CI
is green. Verify every triggered postmerge main-push workflow before release.
