**Charter-only preimplementation freeze.** Released base M34a: ecb6740fff851e0dbce2c2784a173638155a9acb (PR #78, source tree R2-reviewed and 17/17 postmerge main-push checks green). This charter is a contract, not evidence of a working implementation or external review. Implementation will be a separate draft branch and must not modify earlier native graph interfaces.

## Educational gap

After the teacher authors and executes one qualified physical graph, M33b allows asking new *measurement questions* but a new *physical hypothesis* still requires constructing/re-executing another graph plan. M34b must allow a bounded set of **new real physical source-world hypotheses** to fork from any earlier admitted graph world, including from physical descendants, **without reintegrating the original world graph**. This is NOT a time evolution or interaction between counterfactual worlds. The original graph stays immutable, its output unchanged and every new world is genuinely qualified and independently integrated.

## Minimal standalone typed API

- Add native GraphWorldForkPlan, GraphWorldForkEntry, GraphWorldForkRun, run_graph_world_fork under a new standalone module and export them. The request binds **one authentic issued UnifiedObservationRun with retain_source_ancestry=True**. Reject reconstructed JSON, legacy unprovenanced graphs, fake receipts, malformed exact types, and mutated source graph before any physical action.
- Request fields: stable bounded fork_id, 1..5 topologically ordered *new* existing StructuralWorldNode or PhysicalWorldNode objects, optional 1..16 existing typed M24a questions/one exact EventPolicy if any new node observes events, optional up to 8 native WorldComparison pairs. Parent IDs may refer to existing baseline/source-graph nodes or earlier new fork nodes; no duplicate/forward/cyclic IDs, reused original IDs or unlimited recursion. The combined source-graph-plus-fork node count is <=12 and graph-root lineage depth <=6; total physical edits in fork <=12.
- Every admitted new structure is a genuine unchanged M22a reassemble_scenario operation on the **real native immediate parent** (ScenarioReassembly when present, otherwise PrescribedScenario) with existing branch-local M32b SourceWorldAncestry retirement checks. Every physical edit is a genuine M20b revise_scenario with exact true parent revision and unchanged structural source membership. Every child runs a genuinely new native M19/M27 trajectory or M24a event integration; only the child is newly integrated.
- A prior native graph world whose observation refused but whose physical source model was admitted remains eligible as a physical parent. Physically refused parents yield explicit skipped-parent-model descendants with no source model, no fake certificate and no fabricated trajectory/event. Refused siblings do not poison valid siblings.
- New detached v1 plan/run schemas identify source graph canonical SHA256, original/root source revision, fully qualified new authoring, source inventories/labels/kinds, real parent revision IDs, branch-local seen/retired IDs, real new native trajectories/events/terminations, and prior-vs-new observational mode/status. The result is bound by the runner-issued **in-process** SHA256 receipt and independently reconstructed/validated on construction and each export. It is not externally cryptographically signed and never imports detached JSON as trusted physics.

## Physically correct comparisons

- Explicit WorldComparison pairs can compare an old existing world with a new fork world or any two new fork worlds, with at least one new world on each request. Orientation is strictly right minus left.
- Genuine shared-time 3D position/velocity rows use M28a **literally equal actually saved SI timestamps**, never interpolation/index matching/afterguard extrapolation. This is valid when both native observations have the same mode; no fabricated missing worlds.
- For event mode, M28b unique same-direction root-time shifts may pair only for the **same typed question set and numerical policy**, uniquely located in **two duration-complete actual M24a runs**. A source graph may carry different original event questions/policy: then saved-time physical trajectories may still be compared, but roots must explicitly be **unpaired** for question/policy mismatch. Terminal/guard/unresolved/multiple/opposite roots remain unpaired even when some saved trajectory rows exist. Comparison status is compared if either a valid shared-time row exists or a valid independent pair of roots exists.
- Never infer physical source motion, work/energy across different fixed source inventories, contact, postguard continuation or a numerical error theorem from an event bracket.
